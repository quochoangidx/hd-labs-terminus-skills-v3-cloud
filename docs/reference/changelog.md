# Changelog

All project announcements and documentation updates, newest first. The most recent entries are also shown on the [Welcome page](/portal/docs/getting-started/welcome). For the live list of open categories and policies, see [Task Category Status](/portal/category-status).

| Date         | Type   | Change |
| ------------ | ------ | ------ |
| Sep 10, 2026 | 🔄 Update | **Reviewer verifier/reference bar tightened.** One failed Medium criterion now sends a task to revision (same as High). Six verifier/reference rows are now High: no end-to-end solver in `tests/`, dynamic config use, rebuilding source plus validating the required delivered artifact, oracle correctness, tolerance alignment, and objective/tie-break coverage. The existing wrong-solution criterion now explicitly requires meaningful variation across the stated input domain and coverage of any stated lifecycle/resilience behavior. A new High contract row checks that required output paths/names match what the verifier reads. Missing `.dockerignore` is Low; reviewers no longer check canary strings because static checks catch them. [Review Guidelines](/portal/docs/reviewing-tasks/review-guidelines) now walk oracle-correctness under Check Solution. See [Reviewer Checklist](/portal/docs/reviewing-tasks/reviewer-checklist) and [Submission Checklist](/portal/docs/submitting-tasks/submission-checklist). |
| Sep 9, 2026 | 🔄 Update | **Difficulty is now measured once — 8 runs, before review.** The two-stage model is gone: no 4-run iteration check, and nothing re-runs after acceptance. After your task passes the **quality panel**, the platform runs **4 trials per model across both models (8 total)** and that sets the tier your reviewer sees. **At least one of the 8 must fail** for the task to proceed — the 100%-accuracy rule, stated as a gate. Your local `-k 4` runs remain an estimate, not the measurement. The quality panel is now a live blocking check and gates the difficulty run. See [Difficulty Guidelines](/portal/docs/understanding-tasks/difficulty-guidelines) and [After Submission](/portal/docs/submitting-tasks/after-submission). |
| Sep 7, 2026 | 🆕 New | **Platform preflight `verifier_interpreter_permissions`.** If a verifier saves and restores modes for both `/bin/bash` and `/usr/bin/bash` without resolving and deduplicating the targets, cleanup can leave Bash non-executable on merged-`/usr` images and Harbor cannot collect verifier logs. The check scans every Python file under `tests/` before Oracle, reports a blocking ERROR with file and line, and warns when a file cannot be parsed (scan incomplete for that file). Not in `stb harbor check`. See [Writing Tests → Preserve Interpreter Permissions](/portal/docs/creating-tasks/writing-tests#preserve-interpreter-permissions) and [CI Checks Reference](/portal/docs/testing-and-validation/ci-checks-reference#verifier-interpreter-permissions-platform-preflight). |
| Sep 4, 2026 | 🆕 New | **Quality Panel Judge Guide.** The quality panel is an automated four-axis review (`coherent_contract`, `correct_reference_solution`, `protected_ground_truth`, `sound_verifier`) being wired in as a blocking check before a human reviewer. Two frontier models judge each axis; disagreement goes to a third adjudicator. **`Minor` and `Major` both block**, as does `Unsure`; only `None` on every axis auto-accepts. The main page is the how-it-works and checklists only. Numbered synthetic worked cases are a separate [appendix](/portal/docs/testing-and-validation/quality-panel-examples). See [Quality Panel Judge Guide](/portal/docs/testing-and-validation/quality-panel-judge-guide). |
| Sep 3, 2026 | 🔄 Update | **Isolating cases and grade-time keys.** A named domain rule is not tested if the only discriminating fixture is mixed held-out data, or if one coarse mutant (the shipped buggy code) is the only wrong solution you ran. Held-out must not be the sole enforcement of any stated rule. Hidden test inputs are fine; hidden requirements are not. Separate mode protects the verifier from the agent environment, not from code the verifier itself executes. Harbor defaults to **shared** if neither `environment_mode = "separate"` nor a `[verifier.environment]` table is set; Terminus CI requires the explicit key. See [Writing Tests](/portal/docs/creating-tasks/writing-tests) and [Dockerfile §8](/portal/docs/creating-tasks/dockerfile-best-practices#8-separate-agent-visible-runtime-from-verifier-only-assets). |
| Sep 2, 2026 | 🆕 New | **Cloud image builder rejects two Dockerfile patterns that work locally.** `COPY --chown=` must use numeric IDs (`0:0`, `1000:1000`), not names such as `root`. `COPY --from=` image refs must be digest-only — drop the `:tag`, keep `@sha256:…`. `FROM image:tag@sha256:…`, `COPY --from=builder`, and `RUN chown` are unchanged. A blocking preflight (`check_modal_dockerfile_compat`) flags the exact line at submit time. See [Dockerfile Requirements](/portal/docs/creating-tasks/dockerfile-best-practices#cloud-image-builder-syntax). |
| Aug 31, 2026 | 🆕 New | **CAD Task Guidelines for the Hardware category.** A new page covering what general verifier guidance cannot reach: how to establish geometry. Compares the five approaches — direct measurement, invariant checking, symmetric difference, sampling, functional verification — with what each can and cannot see, and which CAD engines support them. Most tasks need more than one. Leads on the trap that point-containment probes *bound* a dimension without ever *determining* it, so a verifier can pass its own oracle and still accept a part wrong in every stated dimension. **A task that asks for a parametric model must test the recompute** — drive a parameter, rebuild, and measure the part, since reading a stored value back proves only that a number exists. Also covers dimension coverage, measuring the oracle's built geometry rather than reading its source, invariance to pose and construction order, tolerance calibration in both directions, why an instruction must never prescribe a feature tree, and how to get a CAD toolchain into your image. Applies on top of [Writing Tests](/portal/docs/creating-tasks/writing-tests), not instead of it. See [CAD Task Guidelines](/portal/docs/creating-tasks/cad-task-guidelines). |
| Aug 24, 2026 | 🔄 Update | **`network_mode` is now set per phase, and `[environment]` must be `"public"`.** The agent harnesses install during the environment build, so a closed environment fails before the agent runs — this was stalling evaluations. Add `network_mode` to `[agent]` and `[verifier]` (`"public"` or `"no-network"`); an offline task keeps `[environment]` public and sets `[agent]` to `"no-network"`. **Applies to new tasks and tasks in progress**, and is enforced by a blocking static check. See [Task Requirements](/portal/docs/understanding-tasks/task-requirements). |
| Aug 19, 2026 | 🆕 New | **Named verifier exploit patterns from delivery review.** Extends the Aug 17 too-loose-verifier guidance with four anti-patterns in [Writing Tests](/portal/docs/creating-tasks/writing-tests): ground truth from agent-writable paths, symlink/copy staging leaks, instruction–verifier tolerance drift, and untested optimization objectives or tie-breaks, plus a short note on not loading agent code before fixed assertions. Ground-truth and symlink patterns fold into the existing **High** reject-wrong-solution criterion; tolerance drift and untested objectives get new **Medium** rows. [Submission Checklist](/portal/docs/submitting-tasks/submission-checklist) self-checks added. |
| Aug 19, 2026 | 🆕 New | **`stb init` now creates a Terminus 3 task folder for you.** Run `stb init my-task-name -p "Terminus-3-Prod"` to download the task skeleton directly, instead of downloading and renaming the zip by hand. See the [CLI User Guide](/portal/docs/cli-user-guide). |
| Aug 17, 2026 | 🔄 Update | **Stronger guidance on verifiers that are too loose.** A task must **reject a wrong solution**, not just accept a right one — run a deliberately wrong solution against your own verifier before submitting. Adds concrete shortcut vectors to [What Makes a Good Task](/portal/docs/understanding-tasks/what-makes-a-good-task), three anti-patterns to [Writing Tests](/portal/docs/creating-tasks/writing-tests) (proxy checks, grading an unrebuilt binary, artifacts the agent controls both sides of), and a **Correct, Not Just Passing** principle to [Writing Oracle Solution](/portal/docs/creating-tasks/writing-oracle-solution) — a passing oracle does not prove the reference is right. [Difficulty Guidelines](/portal/docs/understanding-tasks/difficulty-guidelines) now reads `near_miss` from the failure pattern across runs. |
| Aug 13, 2026 | 🆕 New | **The Terminus 3 task skeleton is available.** [Download it here](/Terminus-3-Prod/default-template.zip) — a single skeleton for this edition, shipped as a complete working task with every field you must fill in marked `REPLACE`. It demonstrates the separate-container verifier, held-out re-run and determinism checks, and digest-pinned canonical base images. ***[See Platform Submission](/portal/docs/submitting-tasks/platform-submission)*** |
| Jul 31, 2026 | 🆕 New | **Terminus 3 is now live; Terminus 2nd Edition has concluded.** The documentation has been migrated: a new seven-category task taxonomy with subcategories, four empirical difficulty tiers (Frontier / Advanced / Core / Base) replacing Easy/Medium/Hard, a verifier that runs in a **separate container** with declared `artifacts`, and `rubrics.txt` / `README.md` assembled by Snorkel at packaging rather than authored by you. Milestone tasks are no longer part of the program, tasks above an 80% pass rate are no longer rejected, and the agent timeout minimum is now 1800s (previously the maximum). Slack has moved to `#terminus-3-submissions` and `#terminus-3-announcements`. ***[See What's New](/portal/docs/getting-started/whats-new)*** |
