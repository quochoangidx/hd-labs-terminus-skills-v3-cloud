- **⭐ Bound an open numeric promise instead of chasing its next boundary; bind held-out seeds to the whole artifact; run the documented invocation (2026-09-25, four panel returns):** *Seeding superseded 2026-09-26:* seeding a held-out draw from any hash of candidate files is itself a finding, because an inert file in the submission can choose the graded cases (daily-overtime v4); seed from a sealed constant in the verifier and seal the drawn inputs from `solution/` (section 2, accepted-corpus entry). The build-metadata rule below still applies to any task that keeps a candidate digest, and `--check seed` is now advisory because three accepted tasks seed that way. `tbrain-delayed-loop-closure-reconciliation` round 1 answered five sound-verifier survivors by adding boundary witnesses (packets before the first anchor, camera integers at `2^63`, `4e-15` covariance, `1e-35` base-time gaps, a generated bundle seeded from `posebridge/**/*.py`) and by removing an undisclosed 60-second subprocess cutoff under the published 1800-second budget. Round 2 then confirmed the next boundary out on the same open promises: a `uint64` camera store passed because the widest fixture was only `2^63 + 1e9`, and a `1e-20` covariance floor passed because only one small scale was tested. The fix was to stop promising more, not to add another witness: FORMAT.md now bounds camera integers to `0..2^63-1` and covariance eigenvalues to `1e-15..1e2`, with fixtures exactly at those limits. The same round showed that (a) a seed hashing only `*.py` let a Python dispatcher read a precomputed `answers.json` shipped alongside it (reward 1 with no general pipeline), so hash every regular file the candidate runs with, making the answer table a fixed point of its own digest; (b) a `runpy` launcher plus `sys.path.insert` rejects a contract-valid `subprocess.run([sys.executable, '-m', 'pkg.worker'])` split, so run the documented `python -m` invocation from the candidate's copy of `/app`; and (c) fixed scenarios capped at two boots let a first-two-boots clock table pass, so the generated bundle now always has 3–4 boots. Also: at `1e-15` scale a lever-arm transport leaves near-zero information entries dominated by ~0.1 of cancellation noise, far above a per-entry `1e-5` tolerance, so an extreme-scale fixture needs a dense anisotropic covariance whose every entry is well resolved. General rules: when a contract promises exact or unbounded values, state the native range (for example signed 64-bit nanoseconds) and test its edge instead of crossing ever-wider type boundaries; test a numerical scale at the stated limit after transport, where a stabilizer would trigger first; use the published phase timeout unless a narrower bound is a justified visible contract. Round 3 (rev2 return) found the same pattern one level down: fixtures placed "just inside" the new limits let an exclusive-bound check pass, and the leftover "finite binary64 without overflow" sentence let a `|x| > 1e6` cutoff pass. Closure: say "includes its endpoints", put a fixture exactly on every endpoint (diagonal covariances with a zero lever arm so the eigenvalues are exact, plus two mirrored corner bundles for positions ±1e4, closure translation ±100, lever arm ±10, angles ±π, base time 0..1e9), and replace every open numeric-domain sentence at once rather than field by field. Extreme closure translations are not merely untested but unsafe: the g2o residual information `Ad(z)^T Σ^-1 Ad(z)` becomes ill-conditioned, so bound them. The same round flagged a held-out seed that picked the structural branch (3 vs 4 boots) from candidate-writable bytes: a `.nonce` file steered it. Fix structure in the test (parametrize every structural case) and let the seed vary only continuous values. Known exposure that no script catches: whether every numeric field in the contract has a closed, inclusive range with an endpoint fixture. Round 4 (rev3 return, 2026-09-25) found two more classes. First, a range the reference cannot meet: covariance eigenvalues down to `1e-15`, combined with a 10 m lever arm or a 45° mount, rounded `Ad Σ Adᵀ` to exactly singular before inversion, and at that floor every binary64 inversion order misses a per-entry `1e-5` information tolerance by up to ~2e7×. Before stating a numeric range, compute the worst-case per-entry error at its corners, after every transform the pipeline applies, against the promised tolerance. Then choose a range where both the natural method and the stable one pass by a wide margin. Here that meant a `1e-3` floor with transport as `Ad⁻ᵀ Σ⁻¹ Ad⁻¹`, which stays within 1% of the allowance. Do not ship a floor that only the careful method survives, because that is a hidden numerical trap. Second, a held-out seed hashed every file under `/app`, including the Dockerfile's `git commit` (commit dates, index stat data) and `__pycache__` bytecode (source mtimes), so two clean builds of the same code produced different seeds. Skip both in the digest and in the candidate copy, and make them root-only before candidate runs; `verifier_static_checks.py --check seed` (wired into preflight) now fails a `/app` seed digest that does not name both. Still no script for: whether a stated numeric range is satisfiable in binary64 under the reference's own transforms. The local clearance of the v4 repair (2026-09-26) then found two more defects. First, the reference's absolute `‖grad‖∞ < 1e-4` convergence guard on a 3-point finite-difference Jacobian rejects a reached optimum once closure information hits ~1e3, which the 1e-3 floor permits. The CLI then aborts on ordinary in-range bundles (a 6-pose loop at the origin with 5 m of loop drift, or poses near 1e4 m with 0.5 m of drift). Both static reference reviewers only raised this as a hunch, so run a stress bundle through the reference CLI before any panel: floor covariance × lever arm × position magnitude × realistic loop drift. Judge convergence relative to the cost scale, not with an absolute gradient bound. Second, verifier staging that resolves every entry under `/app` and hard-fails on an escaping or dangling symlink or a FIFO rejects a correct repair that left `/app/.venv` behind. Skip unrelated entries without ever dereferencing them, rather than failing the whole run. Both classes are now gates wired into preflight. `verifier_static_checks.py --check staging` flags a per-entry assert or raise inside a copy, stage or hash walk over `/app`. `--check gradient` flags a raw `.grad` compared against a constant in `solution/` or `tests/`. Neither flagged any other task in the 41-task corpus once root preconditions and output-tree validators were excluded. The two Go lineage fixtures that reject any `/app` symlink are the same exposure but out of the gate's scope. In v5 the reference and the verifier model use analytic SE(2) Jacobians and a Gauss-Newton predicted-decrease test below 1e-8, in objective units. Deliberately contradictory corner graphs (for example a zero-motion closure between poses 28 km apart with yaw at ±π) stall every SciPy method from the odometry start, so they fall outside EVIDENCE.md's attraction-basin precondition. They are not reference defects.

- **⭐ Partition state transitions by invocation boundary, and do not confuse text value with storage encoding (2026-09-24 panel return):** `tbrain-preisach-forc-memory-reconstruction` had two duplicate findings for one gap: every replay history began above all downward thresholds, so an implementation that emitted the first sample from positive saturation without applying its transition passed. One existing boundary witness now invokes the one-sample history `[-1.0]`; duplicate report rows share that root-cause receipt rather than buying duplicate tests. The same return found that all reconstruction variants had positive reversible susceptibility, so `max(0, chi)` passed; changing existing variant A to `chi=-0.1` closes the missing sign partition without adding a variant family. A fourth finding demanded native HDF5 string attributes because the authority promised them, even though the inspector intentionally normalized bytes to text. Native attribute encoding was non-core representation breadth, so the repair removed that promise and retained the five semantic keys and text values. General rules: exercise the first event when initialization-to-event transition is observable; partition derived scalars across every contract-legal sign; consolidate duplicate findings at one invariant; and drop storage-type promises when only decoded semantic content matters.

- **⭐ Related-nonce recovery collapses when the recurrence remains globally linear (2026-09-24, 2 valid solvers):** `tbrain-low-s-affine-nonce-recovery` passed every campaign gate yet its first counted probe was 2/2 solved. Both fresh Sol-medium solvers independently rewrote each low-s signature as `k_i = sign_i * (u_i + v_i*d)`, composed the fixed affine multiplier over counter gaps, solved two modular linear equations for the private scalar and boot increment, and used the public point only as a final filter. Both also self-generated extra multi-boot, reordered, gapped cases, so changing profile names/values, adding a third boot, or increasing gap/record counts does not disturb the collapse. The reusable lesson is structural: an inverse cryptographic task whose entire hidden state stays affine in two unknown scalars exposes a cheap complete forward model once the visible authority is read. A fair strengthening must change the causal interaction—for example, make skipped-state advancement depend on independently verifiable elliptic-curve state—rather than enlarge the same linear system. Evidence: `workspace/reports/tbrain-low-s-affine-nonce-recovery/probe-cycle-1-summary.json` and `workspace/local-solve-probes/archive/tbrain-low-s-affine-nonce-recovery-cycle-1-2of2/`.

- **⭐ Boundary values must cross every producer/consumer surface, and capacity breadth must earn its place (2026-09-24 panel return):** `tbrain-preisach-forc-memory-reconstruction` allowed a positive density floor plus saturation renormalization because every geometrically populated reconstruction cell and every held-out replay model had strictly positive mass. Reusing one existing value variant with an exactly zero populated-cell moment exposed both the reconstruction-side and loader/replay-side shortcut without adding a new test family. General rule: for a nonnegative physical domain, `0` is a semantic boundary, not coverage supplied by zeros in geometrically invalid cells; carry it through both artifact production and downstream consumption. Approximate equality to expected zero still does not establish the directional invariant: whenever negative values are forbidden, assert nonnegativity separately and strictly on every generated or reconstructed artifact before applying numeric tolerances. The same return found that histories never exceeded nine samples while the prose was unbounded, so a sixteen-result buffer passed. When arbitrary capacity is not part of the causal core, bound the visible/evaluated envelope instead of adding ever-longer inputs; when it is core, cross at least one plausible fixed-capacity boundary. Finally, if an artifact is promised semantically and all link dependencies are declared artifacts, do not impose an undisclosed regular-inode/non-symlink rule: open and validate the resolved content under the intended privilege boundary. Likewise, never multiplex unconstrained candidate stdout with a trusted machine-readable result channel; redirect candidate diagnostics or use a separate descriptor before parsing trusted JSON. Canonical evidence: `workspace/reports/tbrain-preisach-forc-memory-reconstruction/panel4-root-invariant-map.json` and its panel-4 revision ledger.

- **⭐ One receipt binds to one snapshot hash (2026-09-23):** the first `builder_certified` build stalled at `panel_precheck.py --full` with all nine wrong-path receipts reported as `wrong_path_survived`, even though every receipt carried `reward: 0` and had been rejected on its own witness. The cause was two spellings of the same idea: `wrong_path_runner.tree_hash` hashed `path + bytes` while `panel_precheck.tree_hash` hashed `path + NUL + bytes + NUL`, so no receipt could ever match the snapshot the precheck computed and the gate was unpassable for any task that used the runner. `wrong_path_runner.py` now uses the precheck's function and says in its docstring that it must. The general rule: when one script writes a hash another script checks, the two must share one implementation, and a gate row that says "not snapshot-bound" while the evidence was produced seconds earlier against an unedited tree is a hasher mismatch until proven otherwise. The failure mode is expensive — every receipt has to be regenerated after the fix — so check the two hashes agree before spending a Docker matrix on receipts.

- **⭐ Platform-visible unit IDs come from CTRF, which drops parametrize IDs (2026-09-23):** `pytest-json-ctrf` 0.5.2 names each test `report.nodeid.split('[')[0]`, so a parametrised suite reports every case under one name. A 22-case `@pytest.mark.parametrize` sweep arrived as 22 identical `test_outputs.py::test_note_07_case` rows, which collapses `verifier-matrix.json` (`unit_ids` must be unique and equal the CTRF names), destroys the obligation manifest's witness mapping, and leaves the platform reading one red row instead of the rule that broke. Write one named test function per rule instead, with the rule in the name; the skeleton's per-case parametrize advice is about not writing one monolithic all-N test, and named functions satisfy it better than parametrize does. Applies to any suite whose witnesses are cited by ID.

- **Fully specified transcription often collapses.** Apply this prior to conformance/spec-engine work, not to evidence reconstruction, live systems, native artifacts, or multi-step domain operations.
