## 1. TL;DR

**⭐ Current platform contract (synced from direct portal Markdown 2026-09-23): Terminus 3 is live; Terminus 2nd Edition has concluded.** Current metadata uses four language-independent tiers (`frontier` <20%, `advanced` 20–<50%, `core` 50–<80%, `base` 80–<100%, averaged across both reference models); Python has no special tier rule. The bands are unchanged, but since Sep 15 2026 a separate eligibility gate requires at least 3 of the 8 platform runs to fail, so no more than 5 may pass and the maximum measured accuracy that can proceed is 62.5%; `base` and a 75% `core` outcome are reachable only by tasks grandfathered on the platform by the morning of Sep 11 2026, including their later revisions. Difficulty also has a second, independent part: a blocking `difficult` expertise-floor check judges whether the task requires genuine domain expertise (graduate-level knowledge or several years of professional experience) at every tier including `base`, and `difficulty_explanation` must say why the task is inherently a challenge for a human expert rather than cite a model pass rate. All seven Title Case categories are open (`Science`, `Software`, `ML`, `Operations`, `Security`, `Hardware`, `Media`), each task has exactly one matching subcategory, and milestones are removed. Every task declares top-level `artifacts`; the verifier is isolated with `[verifier].environment_mode = "separate"` and a digest-pinned `tests/Dockerfile`. Network policy is mandatory per phase: `[environment].network_mode` must be `"public"`, while `[agent].network_mode` and `[verifier].network_mode` must each explicitly be `"public"` or `"no-network"` — unless the task ships a Compose file, in which case all three must be `"public"` (§10). Agent timeout is 1800–18000 seconds. `codebase_size`, `number_of_milestones`, the old `subcategories`, `allow_internet`, Easy/Medium/Hard metadata, and `junior_time_estimate_min` are obsolete. Historical HARD/MEDIUM/EASY labels below remain lane-scoped evidence about solver behavior only.

**⭐ Direct-doc audit (2026-09-11):** the portal nav has 45 live Markdown pages; five Terminus 2 pages were removed and must not remain in the local mirror. The new Hardware/CAD guide requires geometry-capable verification: measure every stated dimension, make sampling finer than its tolerance, test the built Oracle geometry, and drive a fresh parameter value through recompute when parametric behavior is promised. Cloud preflight `check_modal_dockerfile_compat` blocks external-image `COPY --from=` refs that are not digest-only; stage aliases and digest-only image refs are required. Its named-`COPY --chown=` rule was reversed on 2026-09-17 — the builder now resolves names through `/etc/passwd`, so named and numeric forms both pass; see the section 10 entry. When portal pages disagree on trial count, `docs/understanding-tasks/difficulty-guidelines.md` is authoritative: difficulty is measured once after quality-panel clearance and before human review, 4 runs/model (8 total), with at least 3 failures for a new submission and no post-acceptance rerun. Canonical `FROM` references still use the exact published registry, tag, and digest; never leave Node or Java digest placeholders in generated tasks.

Under a **warm loop** (persistent container + `docker exec`, real build+verify cycle), historical Opus 4.8-medium probes solved nearly every fully-specified minimal-codebase task by deriving their own reference and self-differential-testing thousands of cases. Reliable top-tier difficulty is not achievable by minimal spec-task building alone. Only three historical levers still bite:

1. **Non-self-verifiable ground truth** — conformance over a hidden/divergent reference the solver cannot re-derive (§3). Was the genuine HARD lever (~60% yield historically); by 2026-07-19 the FRESH survivor set is nearly empty — needs an UNDER-documented reference AND a broad multi-rule tail AND a category-safe shape (§6 batch-10 verdicts).
2. **Under-fuzzed input shape** — a boundary corner the solver's own fuzzing misses; interval-ledger/duty-cycle ports (§4). A ~0–25% lottery, not a guarantee — and ports are closed by the fresh-only doctrine (§2).
3. **Decoupled decoy where the plausible fix is itself wrong** (§5). Necessary but not sufficient; fresh stub-fill variants collapse via the disclosure trap (§6).

**⭐ Current Terminus 3 status:** all seven domain categories and their published subcategories are open. Milestones are removed, not merely blocked. Category selection is domain-first; legacy classifier evidence is retained only as generalized calibration. Interaction and conformance archetypes may still be poor Frontier sources, but valid Base/Core/Advanced tasks are now useful outcomes.

**⭐ Terminus 3 epistemic contract (authoritative, 2026-08-13):** fairness means a clear goal plus enough agent-visible evidence to infer the graded domain model; it does **not** mean spelling every semantic rule out as prose. Keep artifact paths, public interfaces/schemas, hard safety constraints, and arbitrary exact conventions explicit. Allow the agent to reconstruct causal relations, protocol semantics, geometry, scientific interpretation, state transitions, and interacting constraints from one or more visible sources. Hidden instances, combinations, and metamorphic variations are desirable when they exercise the same inferable model. Hidden oracle-only policies, unreachable authorities, undocumented exact strings, arbitrary constants, and facts the agent could not possibly obtain remain invalid. When older empirical notes conflict with this paragraph or the live Terminus 3 docs, this paragraph and the live docs win.

**⭐ Active CORE+ campaign override (updated 2026-09-15):** `campaign_ready` counts candidates whose hash-bound two-run blind probe produces a provisional Core, Advanced, or Frontier signal. Before probing, finish the retained-scope verifier and Oracle, pass V3 evidence inferability, map every public surface and the natural causal core, kill a dedicated plausible partial-fix mutant for every retained mechanism/interaction, and pass strict Oracle=1, NOP=0, noexec, isolation, review, and audit gates. There is no fixed component/mechanism/interaction/trap count beyond the structural need for a genuine interaction; counts never authorize scope padding. Run exactly two valid fresh blind-solver results: `0/2` or `1/2` solved qualifies for handover; union coverage, common misses, and failure geometry are diagnostics. Infrastructure/setup/timeout failures are preserved but replaced. `2/2` permits one fair strengthening/remediation cycle and one fresh two-run re-probe; a second `2/2` rejects the candidate. Each task uses one persistent builder, one fairness reviewer reused for contract/final review and rechecks, two valid blind-solver results, and one persistent consolidated auditor. Every subagent uses `gpt-5.6-sol` medium on Codex or Opus 5 medium on Claude Code. Historical `advanced_frontier_only` receipts remain evidence only. An explicit `panel_ready` batch instead uses one builder plus the quality-panel reviewers, Oracle/NOP/noexec and deterministic checks; it omits fairness/auditor/probe and the campaign mutation suite while retaining minimal precheck wrong-path/harness evidence. It may report only `local_panel_cleared`, never a tier or `candidate_ready`.

**⭐ User decision — adaptive frontier design portfolio (updated 2026-09-03):** design candidates from a domain-native failure mode, work surface, and deliverable before assigning a catalog pattern. Patterns classify a completed causal design; they do not prescribe one. The schema-v3 candidate ledger records every mining-plan-qualified attempt and its disposition but enforces no candidate budget or maximum attempt count; replacements may use either track, and the first task that clears every quality and difficulty gate may be accepted regardless of track. Treat roughly 20–30% derived attempts as a non-blocking exploration advisory. Across the rolling five accepted tasks, aim for one or two derived tasks, no dominant topology above three of five, and no exact role stack three times consecutively; portfolio drift changes later mining priority but never invalidates a qualifying task. Derived candidates still require a genuine `X-*` transformation across at least two structural axes. Pattern membership never substitutes for freshness, V3 inferability, mutation-backed semantic rank, structural diversity, or frozen probes. Validate the candidate ledger with `task-batch/scripts/design_pattern_mix_check.py` before scaffolding and before handover.

Within **conformance/transcription tasks**, rule complexity, counter-intuitive stated rules, named algorithms, cascade depth, and fully specified optimization often collapse (§6). This is a lane-specific prior, not a universal Terminus 3 rejection rule. Evidence-reconstruction, native-artifact, live-state, and multi-system tasks must be screened on their own domain inference and interaction shape. Probe honestly (§7): warm loop, exactly two fresh solvers per task, N≥5 only for pooled same-engine calibration, terse prompt, score by differential, and never trust self-report or a setup-driven failure.

**⭐ Collapse-law scope correction (2026-08-13):** the July transcription result remains valid for spec engines and library-conformance clones, but it must not screen every candidate. A fair Terminus 3 task may derive difficulty from reconstructing a model from specialized evidence, coordinating state across steps, producing a semantically valid native artifact, or satisfying interacting safety/performance/provenance constraints. Reject a hidden fact only when it is arbitrary or unobtainable; do not reject a discoverable hidden requirement merely because no sentence states its final rule. The V3 compatibility report remains named `instruction-sufficiency.json`, but schema version 3 audits goal clarity, evidence inferability, hidden-generalization continuity, and semantic equivalence rather than contract transcription.

## 2. Core principles (why tasks collapse or hold)

- **⭐ Bounded design and obligation-driven verifier (user decision, updated 2026-09-14):** design one coherent primary outcome and record a pre-scaffold scope ledger separating causal-core obligations, supplied support plumbing and explicit non-goals. Domain adjacency does not make parsing, schema, serialization, malformed-input handling or compatibility behavior core. Retain difficulty through inferable causal interaction and a natural-but-wrong path, not unrelated breadth. Historical unit/cluster/shape/component/mechanism/interaction/trap counts are not difficulty gates. Exact inventory/CTRF integrity and public-surface alignment remain quality requirements; campaign-only inferability, mutants and fresh difficulty evidence apply only in `campaign_ready`. Repairs default to no new promises, not no new lines. Keep discovery → one batch → one clearance; a blocking clearance becomes `rescope_required`, and another witness batch under the unchanged obligation set is not a rescope. Canonical guidance: `terminus-regular-task-authoring/references/bounded-task-design.md` and `task-batch/references/execution-profiles.md`.

- **⭐ A sync must retire the claim it reverses (2026-09-23):** the 2026-09-17 portal change re-allowed named `COPY --chown=` values. `sync-doc-and-skill` recorded it as a new section 10 entry and updated `task-policy.py` plus eight skills, but left section 1 still saying `check_modal_dockerfile_compat` blocks named values and requires numeric IDs, so this file asserted both for days. Appending is not updating: an agent that reads the earlier section and stops follows the withdrawn rule. After any sync, grep `AGENTS.md` and `.agent/skills/` for the **subject** of each changed rule — not for the new wording, since the stale sentence is phrased the old way — read every hit, and repair the superseded claim in place with its reversal date and a pointer to the newer entry. A reversal is the dangerous direction, but a tightened rule hides the same way, so sweep both. `sync-doc-and-skill` Step 5b now owns this, and its report must carry a `Superseded claims repaired` count.

- **⭐ Seeded departures from a complete note collapse against frontier solvers (2026-09-23):** the first `builder_certified` candidate, `tbrain-int8-activation-requantization` (ML / Inference, eight seeded departures from a numbered in-repo note across a 120-line int8 quantisation package), was built exactly to the `contract-closure.md` pattern and cleared every deterministic gate — strict Oracle=1/NOP=0/noexec, determinism, independence, eight per-site wrong paths plus a harness bypass, full obligation precheck — and a two-turn reviewer that found and closed a real blocking contract defect. It then failed the CORE+ bar **2/2 twice**: four independent Opus-5 solvers each found all eight departures and passed 32/32. The strengthening cycle in between was real (the coverage envelope had been naming the two subtlest departures rather than the input families, which the reviewer agreed was trap disclosure) and changed nothing about the outcome. The lesson is archetype-level, not execution-level: a **complete, ordered, short authority over a small package is a transcription task**, and section 6's collapse law applies to it. The solvers all described the same method — read the note section by section and diff it against the code — and the note's own structure hands them the checklist. `contract-closure.md` is a strong recipe for *fairness and panel-clearance*, and this run is evidence it does not by itself produce difficulty. To get both, the authority must stop being a checklist the package can be diffed against: make some graded behaviour reconstructable from distributed evidence rather than stated section by section, or make the package large enough that a section-by-section diff is not the cheap path. Do not spend a second candidate on the same shape without changing that, and do not read the 2/2 as a verifier or fairness defect — the evidence says the contract was sound and the task was simply easy.

- **⭐ One receipt binds to one snapshot hash (2026-09-23):** the first `builder_certified` build stalled at `panel_precheck.py --full` with all nine wrong-path receipts reported as `wrong_path_survived`, even though every receipt carried `reward: 0` and had been rejected on its own witness. The cause was two spellings of the same idea: `wrong_path_runner.tree_hash` hashed `path + bytes` while `panel_precheck.tree_hash` hashed `path + NUL + bytes + NUL`, so no receipt could ever match the snapshot the precheck computed and the gate was unpassable for any task that used the runner. `wrong_path_runner.py` now uses the precheck's function and says in its docstring that it must. The general rule: when one script writes a hash another script checks, the two must share one implementation, and a gate row that says "not snapshot-bound" while the evidence was produced seconds earlier against an unedited tree is a hasher mismatch until proven otherwise. The failure mode is expensive — every receipt has to be regenerated after the fix — so check the two hashes agree before spending a Docker matrix on receipts.

- **⭐ Platform-visible unit IDs come from CTRF, which drops parametrize IDs (2026-09-23):** `pytest-json-ctrf` 0.5.2 names each test `report.nodeid.split('[')[0]`, so a parametrised suite reports every case under one name. A 22-case `@pytest.mark.parametrize` sweep arrived as 22 identical `test_outputs.py::test_note_07_case` rows, which collapses `verifier-matrix.json` (`unit_ids` must be unique and equal the CTRF names), destroys the obligation manifest's witness mapping, and leaves the platform reading one red row instead of the rule that broke. Write one named test function per rule instead, with the rule in the name; the skeleton's per-case parametrize advice is about not writing one monolithic all-N test, and named functions satisfy it better than parametrize does. Applies to any suite whose witnesses are cited by ID.

- **⭐ `builder_certified` is the default task-creation profile (user decision, 2026-09-23):** a bare `task-batch N` selects it; `campaign_ready` and `panel_ready` are explicit opt-ins. One builder, **one** reviewer (`contract_review` blind to `tests/` and `solution/`, then `final_review`), and the blind solve probe. No quality panel, fairness reviewer or auditor; this overrides the mandatory-panel clause of the 2026-09-11 topology and the 2026-09-15 precheck decision for this profile only. The five axes are carried by receipts: `preflight.sh --strict` and `--determinism`, `independence_check.py`, `wrong_path_runner.py` per core obligation, `panel_precheck.py --full`. Difficulty bar is **CORE+** — two blind solvers, at most one succeeding; do not harden past it for `advanced`/`frontier`, and do not reject at CORE. Read solver failures for cause anyway: an uninferable convention or a rejected contract-valid solution is a defect, not difficulty. Two invariants keep it honest: the builder reports only what a snapshot-bound receipt shows, and a disputed gate becomes a `documented_exception` with its contract citation rather than a quiet task edit. Label is `builder_certified`, never `local_panel_cleared`, `candidate_ready` or a measured tier. `task-local-solve-probe/scripts/probe.py` has no `builder_certified` profile and its counted profiles demand campaign receipts this route does not produce, so prepare the pair with `--exploratory`: that mode asks for no campaign receipt and already labels its output non-tier, which is exactly what the CORE+ bar here is. Report the number as a local signal and never as a measured tier. **Known exposure:** no independent reader covers semantic coherence over the whole domain, acceptance of every alternate valid implementation, or a case the builder never conceived. `task-quality-panel-judgement` is retained for use *after* a platform return, two reviewers on the returned axis only — that targeted mode is now its default. The obligation gate moved to `terminus-regular-task-authoring/scripts/panel_precheck.py` (2026-09-23), since every profile runs it while the panel runs rarely; its file name is historical. Route: `task-batch/references/execution-profiles.md`.

- **⭐ Retired upstream-mining lanes (2026-09-23):** `find-task-prs` and `issue-to-regression-test` are removed. Both self-documented as dead: the PR lane's reproduce-a-fix shape "often collapses", and the upstream-issue lane "serves a mostly-dead shape: mechanical fixes of real upstream bugs collapse 3/3". Neither was referenced by any workflow, and both point away from the seeded-departures pattern `builder_certified` builds. Their reusable content — assertion policy, instruction/test symmetry, anti-shortcut shapes — was folded into `terminus-regular-task-authoring/references/contract-closure.md` sections 12–14 rather than discarded. Do not reintroduce an upstream-PR/issue lane without fresh evidence that its output shape survives the collapse law in section 6.

- **⭐ Gates judge properties, not spellings (2026-09-23):** the repo's mechanical gates produced 11 FAIL rows on `cairnlift-fold-and-mend`, a task that cleared the platform panel; nine were wrong. Causes worth remembering: whole-line `grep -qxF` missing `**/`-prefixed `.dockerignore` patterns; `set -e` matched inside the comment explaining its deliberate absence; a pinned `/venv/bin/python` read as bare `python`; literal `install -d -m 700` and one blessed reward footer demanded where equivalents existed; `COPY <files> /tests/` unmatched; `javap` counted as candidate execution. Two more were stricter than the platform's own documents: the published `test.sh` template in `docs/submitting-tasks/platform-submission.md` does **not** pre-write a default reward, and `docs/testing-and-validation/quality-panel-examples.md` states a missing `--no-new-privs` alone is not a finding without a reachable escalation. Now 0 FAIL. Three standing rules: **a FAIL on a task that already passed the platform is a bug in the gate until proven otherwise**, so re-run the corpus after every new rule; **a rule stricter than the documented platform contract is a `warn`, never a `fail`** (`task-policy.py` has `advisory()` for this, and the row must name the document it goes beyond); and a false FAIL outranks a miss in danger under `builder_certified`, where nothing overrules it — the `set -e` row would have had an author break a working reward channel. A restriction is enforced only at the level that can see it: **source text does not decide what a program may reach at run time**, since the capability stays reachable through a constant, a generated name or a dependency. `restrictions[].enforcement_level` must therefore be `compiled`/`both` for reflection, native code, subprocess, network or namespace rules, and `source` only for what source genuinely decides such as file location; the gate also requires `enforced_by` and `allowed_exceptions_disclosed` per restriction. Per the client guidance above, a restriction that is not core is cheapest to answer by not stating it — the general rule is that every promise needs a witness that can see it, not that every task makes the same promises. `instruction_preflight.py` now splits blocking findings from advisory notes: word, backtick and bullet counts never fail, grading-apparatus names and paths (`/tests/`, `test_outputs`, `ctrf`, `rubric`, `reward`, `pytest`, `test.sh`, "hidden test") stay blocking, and the bare nouns `verifier`/`oracle` are advisory because blocking them costs real restriction prose.

- **⭐ Contract closure from a panel-cleared sample (2026-09-23):** `cairnlift-fold-and-mend` clears its axes because the artifacts answer them directly, and every technique is mechanically checkable: one numbered in-env authority plus a universal-rule clause and a silence clause closing the rest of the input domain; a coverage-envelope paragraph naming hidden input families and no values; an authority sentence behind every exact convention; restrictions listed with their legal exceptions; expected values re-derived from the authority without importing the package, so Oracle=1 is agreement between two independent derivations rather than a tautology; a shipped-versus-repaired differential guarding the silence clause; and a `solve.sh` header mapping each contract topic to its change, because the reference is judged against the instruction alone. Its instruction runs long because it carries contract, not because length is good. Counter-lesson: its mutation claim is prose with no receipt, which our receipt discipline must keep rejecting. Canonical guidance: `terminus-regular-task-authoring/references/contract-closure.md`.

- **⭐ Deterministic panel precheck (user decision, 2026-09-15):** before scaffolding, `panel_ready` must pass the quality-panel `panel_precheck.py --design-only` connected-core gate; before reviewer packets, it must pass `--full` against the exact task snapshot. The full manifest maps every retained obligation to visible authority, implementation sites, verifier witnesses and minimal natural wrong-path evidence, requires one harness-bypass receipt, and validates strict Oracle=1/NOP=0/noexec plus candidate demotion through existing receipts. Support plumbing is complete, smoke-tested and outside the intended repair surface; exact output conventions need a domain/interoperability rationale. `mechanically_ready` never means an axis is `None`: scripts cannot establish semantic coherence, omitted-branch completeness, reference correctness over the whole domain or acceptance of every alternate valid implementation, so the fresh eight-reviewer panel remains mandatory. Do not expose precheck conclusions to reviewers.

- **⭐ Panel returns are answered with receipts, not prose (2026-09-23):** the build path refused unbacked claims while the revision path accepted them, which is how a return gets answered with "repaired" and comes back with the same finding a round later. A revision now keeps `workspace/reports/<slug>/revision-ledger.json`, validated by `terminus-regular-task-authoring/scripts/revision_ledger_check.py`: one row per numbered finding with a `decision` of `backed` / `dropped` / `disputed` / `acknowledged` and a rationale. `backed` needs **two** receipts — the defect reproduced on the snapshot the platform judged and its closure on the snapshot being resubmitted, since a closure alone only shows a test passing that may never have failed. `dropped` names the `removed_obligation_id`, cross-checked against the manifest so the precheck can confirm the prose left with it. `disputed` needs the cited contract passage **and** a reproducible counterexample. `acknowledged` is refused on a blocking finding. Every row carries the `gate` rule the finding bought or a `not_mechanizable` reason, and every carried-forward `P`-finding needs an explicit response — the report omitting one does not resolve it. Restore from the **exact returned artifact** first: a drifted tree is a different task, so evidence gathered on it is about something the panel never saw; keep the diverged tree only as a rollback artifact.

- **⭐ Client guidance on answering panel findings (2026-09-23):** the client reports that most teams answer a finding only by building to satisfy it — more tests, more contract detail, more edge-case promises — which expands the surface the panel judges and produces the revision loop. A finding means a promise is not backed or a test does not check what it claims, and it has **two equally valid answers: make it true, or stop promising it**. The first question is *does this promise earn its place in the task?* — core to the hard thing means back it properly; not core means remove it and the finding goes with it, deleting obligation, assertions, contract prose and manifest entry in one move so nothing stays half-promised. This is intended use, not a loophole: exhaustive nit-picky edge coverage is explicitly not wanted, and "a tight task that does one hard thing properly" is. The hard limit is difficulty — **cut breadth, keep the hard thing**; trimming until the task is easy swaps one failure for another, and the eligibility gate already requires at least 3 of 8 platform runs to fail. Loop signals: hundreds of accumulated assertions, findings moving axis each round, 10+ revision rounds, the same axis failing with a new finding each round; the counter-move is to take the flagged promise out rather than build on it. This reframes, not replaces, the 2026-09-12 adaptive-remediation option map. Removal is now mechanically supported, not just advised: the manifest carries `removed_obligations` with each drop's reason and the `former_anchor` sentence that used to promise it, and `panel_precheck.py --full` fails when that sentence still reads in the task — a promise outliving its witness is enforced by the panel with nothing defending it, strictly worse than before the cut. Trimming also invalidates every difficulty signal collected before it, so rerun the probe rather than carrying a tier across a scope change. Canonical: `task-revise-flag-remediation/SKILL.md` and `terminus-regular-task-authoring/references/contract-closure.md` §11.

- **⭐ Adaptive panel remediation (user decision, 2026-09-12):** for each confirmed root cause compare shared repair, narrowing, coherent non-core removal, justified expansion, and retirement/redesign; this supersedes a fixed shrink-first preference. Choose by retained task value, interaction coupling, regression risk and verification cost, not patch size or sunk effort. Use snapshot-bound failed attempts and deterministic closure evidence to stop strategies that keep reproducing the same invariant failure or adding exceptions; stochastic panel changes and infrastructure failures alone do not justify dropping a feature. Remove separable low-value surface when authorized, aligning all contract/implementation/verifier/rubric/inventory dependencies without deleting tests for promises that remain. If no bounded repair preserves the core, mark the design not-for-submission and preserve it; core redesign or replacement needs existing task/batch authority or user direction. Retirement is not filesystem deletion or success. Keep the single-clearance stop and user budgets; no automatic extra panels, probes or replacement task. Canonical option map: `task-revise-flag-remediation/references/root-cause-remediation.md` (moved there 2026-09-23 so it stays reachable when no panel runs).

- **⭐ Submission panel-input hygiene (user decision, 2026-09-11):** 800 lines per submitted task text file is a soft readability warning, not a platform limit or correctness gate. Track per-file lines/bytes and per-axis aggregate input; label token estimates with their method and do not invent a safe platform budget. Reduce duplicate prose, unused scaffolding and proven-redundant fixtures, keep one discoverable authority per rule, and split code by responsibility rather than line count. Never minify to game the warning, hide necessary evidence, or sacrifice named-rule, boundary, interaction, lifecycle or mutant discrimination. Small files and split corpora do not guarantee complete platform reads: actual unread/truncated mandatory evidence still blocks local clearance. Keep this assessment inside existing review reports, without extra agents/cycles; preserve snapshot-validation rules after edits. This heuristic does not require splitting mirrored portal docs, skill files, or the single AGENTS.md memory. Canonical guidance: `terminus-regular-task-authoring/references/panel-input-hygiene.md`.

- **⭐ Corpus inventory must be executable (2026-09-12):** the platform panel for `tbrain-margin-collateral-dispute-reconstruction` inferred that two alphabetically late corpus families were absent because its displayed file listing was truncated, even though the exact ZIP contained all 37 batches and 135 unique units. Do not rely on filenames, generator notes, or reviewer packet completeness to establish the graded roster. A corpus-driven verifier must fail collection unless loaded unit IDs are unique and exactly match a compact committed plan/manifest, including cluster metadata when present. Remove authoring-only witness generators from the upload once the frozen fixtures and executable inventory check are self-contained; this reduces panel input without weakening semantic coverage.

- **⭐ Sep 10 reviewer bar (direct-doc sync 2026-09-11):** one failed human-review Medium now requires revision, as does High; Low alone does not. Six verifier/reference rows are High: no end-to-end solver in tests, dynamic config dependence, rebuilt-source plus required-deliverable validation, independent Oracle correctness, tolerance alignment, and objective/tie-break coverage. Required output paths/names must match the actual graded artifact; verify full required content, meaningful domain variation, and any promised lifecycle/resilience behavior without inventing new promises. Missing `.dockerignore` is Low in the human checklist; canary checks remain static even though their human-review row was removed. These High/Medium/Low labels are distinct from quality-panel Major/Minor/Advisory/Unsure. Docs-only sync found stale two-stage platform-measurement language in task-miner, task-clone, task-batch, task-harbor-runner, task-local-solve-probe, task-client-feedback-review, and terminus-hard-python-verifier; their workflow edits remain pending, while user-selected local two-run probes are unchanged.

- **⭐ Two-reviewer quality-panel topology (user decision, 2026-09-11):** each discovery or clearance panel uses ten fresh-context reviewers, two per quality axis, with the same axis-specific packet and full checklist for each pair. Keep five packets, not ten different evidence universes; neither panelist sees the other's output. Collect all ten responses before adjudicating the union of findings per axis, preserving raw verdicts and claim provenance. A `None` vote cannot cancel a confirmed finding; agreement cannot substitute for evidence, and unresolved material conflicts or incomplete reviews block clearance. The orchestrator consolidates five axis verdicts and one cross-axis root-cause batch without an automatic eleventh reviewer. Clearance uses ten new sessions; historical four- and eight-reviewer receipts remain historical and do not satisfy the new topology. Other fairness/probe reviewer counts are unchanged.

- **⭐ Quality-panel evidence completeness (2026-09-11):** the local panel must include instruction-referenced candidate-visible authorities and their dependencies without exposing tests to the reference reviewer or solution to other axes. Explicit `--contract-file` selections under `environment/` supplement the narrow packet table; this is a local completeness extension, not a claim about platform internals. Record unread/truncated evidence and unfinished mandatory checks as clearance blockers, not confirmed task bugs. Separate reproduced/static-proven findings from unverified hypotheses, trace relevant rule interactions and same-invariant sibling paths in the original bounded review, and never treat a named fixture as a discriminating witness without checking its assertions and inputs. ## 3. Historical Terminus 2 calibration — conformance/reference lane

These are lane-scoped priors, not universal Terminus 3 rejection rules.

- **Under-documented authority plus a broad tail was the only durable conformance wall.** A candidate needs behavior that materially exceeds clean public documentation and spans several independent semantic mechanisms. A famous or fully documented standard, man page, RFC, public pseudocode, or named library is usually reconstructable.
- **Run a Step-0 divergence gate before building.** Compare the real authority with an independent faithful implementation over a large corner-biased sample. Near-total agreement means the public contract already determines the behavior; a tiny residual usually indicates a single implementation quirk, not a broad task.
- **Single-lever residuals are not Frontier evidence.** If many failures collapse to one boolean, convention, or corner, disclose it and the task becomes transcription; hide it and the task becomes unfair. Do not confuse many affected fixtures with multiple mechanisms.
- **Independent authority and Oracle checks matter.** A ported corpus, shared helper, or shared implementation lineage can reproduce the same bug. Cross-check with a genuinely independent source and audit every verifier assertion against task-visible evidence.
- **Offline reachability is part of fairness.** If the authoritative tool or documentation is unavailable in the agent image, every non-inferable graded convention must be supplied locally. Claims about ungraded behavior must be removed or backed by discriminating tests.
- **Public input symmetry is mandatory.** Tests may use only documented public keys, values, encodings, and schemas. Compatibility aliases and internal constructor names pin an implementation shape and can manufacture correlated misses.
- **Documented-tool familiarity is broader than expected.** Inner details of build systems, pattern languages, policy engines, version resolvers, and protocol canonicalizers may be recalled or reconstructed even when the tool is old or obscure. Screen the documentation surface, not the tool's popularity.
- **Category is domain-first.** Historical classifier reactions to exact-reference wording are calibration only; do not distort a current Terminus 3 task to evade an obsolete classifier.

## 4. Historical Terminus 2 calibration — interval/state ledgers

- **Under-fuzzed shape was a lottery, not a reliable design strategy.** Interval ledgers, duty cycles, and state-transition boundaries sometimes survived because solvers missed one representation or ordering corner, but ports and reskins are not novel submissions.
- **State representation must preserve the domain's natural invariants.** Use half-open intervals when possible, define simultaneous-event ordering explicitly when arbitrary, and test zero-length, touching, nested, repeated, and boundary-aligned cases.
- **Exact constants and tie-breaks need visible authority.** If a score, threshold, rotation direction, or priority rule is arbitrary, hiding it is unfair and stating it often trivializes the task. Prefer inferable causal structure over secret constants.
- **Real-valued estimation can remain difficult where clean rule engines collapse.** The load-bearing component should involve evidence-supported estimation, calibration, aging, or noisy cohort inference; clean logic may support it but should not be the only wall.
- **Interaction count is not semantic rank.** Several rules routed through one central helper or one recovered mapping still form one mechanism. Count independent causal decisions and their interactions, then verify them with disjoint partial-fix mutants.

## 5. Historical Terminus 2 calibration — decoys and verifier simulation

- **A decoy works only when the plausible natural fix is itself wrong.** Merely hiding the real helper, leaving a stub, or adding an unused field does not create difficulty if a careful default implementation satisfies the contract.
- **Avoid disclosure traps.** Enum names, adjacent comments, TODO lists, fixture labels, worked examples, and field groupings can reveal the intended mechanism. Keep the public goal and evidence complete while making scaffolding neutral.
- **Verifier-side simulation needs a canonical, stable target.** Hidden simulation parameters are unfair; fully disclosed simulators are often reproducible. Useful cases require evidence-supported dynamics whose observable outcome is stable across valid implementations.
- **Test perturbation robustness for dynamical systems.** Agreement between two implementations is insufficient when both track the same fragile trajectory. The graded outcome must survive physically negligible input perturbations; scattered basin flips indicate chaos and an unfair oracle.
- **Event-driven dynamics are not automatically fair or hard.** Closed-form inter-event motion improves canonicality, but dispersing or long-tumble systems can remain chaotic. Prefer convergent, dissipative outcomes with well-separated final states.
- **Named textbook algorithms often collapse novel-looking tasks.** Canonical multi-regime geometry or scientific computation is still easy when recalling the named object determines the complete solution. Domain interpretation and interacting evidence must remain after algorithm recall.
- **Run Docker-first determinism checks.** Concurrency, RNG, scheduling, futures, and background work must pass the full Oracle matrix in the exact isolated/noexec environment before semantic manifests or probes.

## 6. Historical saturation evidence — reusable screening rules

> Apply these only to matching shapes. Current Terminus 3 accepts honest Base, Core, Advanced, and Frontier tasks.

- **Fully stated decision engines usually collapse.** More rules, recursion depth, optimization states, or cascades do not reliably create difficulty when the entire contract can be transcribed and self-tested.
- **Well-known standards and published adjudicators are usually reconstructable.** The residual tail often becomes either a contested convention or one narrow quirk. Reject only the matching conformance shape, not the broader domain.
- **Contested authorities are unsuitable hidden ground truth.** If serious implementations disagree on hard cases, either specify the chosen convention or redesign around an uncontested observable.
- **Canonical operational repair is discoverable by iteration.** Multi-service restoration and standard database migration can remain easy despite causal unmasking because logs and established recipes lead solvers through the fix.
- **Pure interaction breadth does not guarantee difficulty.** Long context, several services, or multiple disclosed rule families can still reduce to mechanical joins or a canonical procedure.
- **Continuous chaotic simulation has no fair-and-hard window when discrete outcomes depend on integrator choices.** Tame cases are easy; chaotic cases are oracle-sensitive. Require method-independent outcomes and perturbation robustness.
- **Optimization is not a reliable wall by itself.** Strong solvers derive dynamic programs or brute-force small domains and self-check the optimum. Difficulty must come from domain reconstruction or interacting constraints, not merely objective complexity.
- **Measure before declaring a family dead.** Platform returns or pooled probes support strong priors; a local sample of one instance supports only a suspect prior. A materially stronger, structurally different control may retest a suspect seam, but never a reskin.
- **Preserve lower-tier and rejected evidence honestly.** Do not prune easy cases, hide facts, or add hints to manufacture a target tier. Generalize the lesson here; keep task-specific logs, hashes, scores, and artifacts outside this shared file.

- **⭐ Diagnostic failure analysis (updated 2026-09-03).** Preserve per-case and mechanism-level failure geometry to find verifier defects and improve later designs, but do not use common misses, union completeness, or de-correlation as a CORE+ acceptance gate.
- **Local probes are preliminary:** map the two-run pass fraction to a provisional Core/Advanced/Frontier signal without language exceptions. A quality-complete zero-solve or one-solve result may enter the local shortlist; all-pass local samples provide no signal. Platform iteration and final measurement remain authoritative.
- **Current CORE+ shortlist mapping (updated 2026-09-03):** obtain exactly two valid blind-solver results. Archive and replace stale, setup, timeout, dependency, refusal, provider, and verifier-execution failures; they do not count toward the pair or difficulty. Accept a quality-complete `0/2` or `1/2`; do not require a third valid result, union completeness, zero common misses, or de-correlated geometry. Every failing solver in the port batches "built clean and reported byte-for-byte correct."

- **Validate any base before porting:** gate on harbor oracle=1.0 AND nop=0.0 AND a blind probe that actually fails (found bases with stub==solution, non-compiling images, and 3/3 "hard" labels).

Record the run as unverified, preserve the logs, and retry only when the infrastructure is healthy. Local fresh probes and current `stb` model runs must use real provenance; neither may be replaced by a handwritten surrogate.
- Keep local compute light: validate in Docker (harbor), not on the host; no 2^n brute force for n>18 locally.

## 8. Verifier & test design

- **State the OUTCOME, not the mechanism.** Detailed rules live in `/app/SPEC.md` (or an RFC-style file under `environment/app/`), instruction.md keeps goal + high-level names of every tested violation kind.
- **Binary reward 0/1, never proportional.** Clients flag the CTRF proportional-reward pattern as a verifier defect. Fix coverage honestly (per-case parametrize / prune / disclose) and use the standard pytest-exit-code block; oracle must then pass 100%.
- **Corpus curation (V3 correction, 2026-08-13):** soft size cap ~≤100 curated cases for a normal conformance corpus (300+ only for a genuinely broad wall with per-case evidence). A predicted low-pass case is a 0/N risk, not an automatic disclose/drop instruction: audit oracle/verifier, explicit interface, evidence inferability, and CTRF resolution first. Keep hidden instances/combinations that exercise the same inferable model; remove only invalid, redundant, flaky, over-strict, or oracle-only assertions. Never trim easy cases to manufacture a higher tier.
- **Build the candidate from `/app` source at verifier import time** — never `shutil.which()` or a pre-installed binary path (makes nop ungradeable, fragile to nonstandard build paths).
- **Use the project's own build system, never hardcode compiler invocations in the verifier.** A `build_binary` fixture that calls `g++ src/main.cpp src/engine.cpp` instead of `make` (or `cargo build`, `go build ./...`, etc.) ignores agent-added source files and Makefile updates, failing the agent unfairly. Always invoke the project's build tool so agents can modularize freely.
- **A build helper must check the build's EXIT STATUS, not just that the artifact exists.** `make clean` → assert the binary is gone → build → assert `returncode == 0` (stdout+stderr in the message) → assert the binary exists. Otherwise a warm Docker build can leave a stale binary and grade non-compiling source as green. Drop warm artifact builds and inject a compile error to confirm reward 0 with the build failure surfaced.
- **Checker-owned compile and hidden answer corpora:** if `tests/` ships expected-value corpora, never run submitted build logic while the corpus remains readable. Load the corpus into memory, unlink it before compiling or running candidate code, and use a verifier-owned build command when the public interface permits it so submitted build logic cannot generate a fixture lookup.
  - **Hide `/solution`, reject escaping source, and isolate pytest.** Remove `/solution` before grading; reject source symlinks or includes that escape `/app` or name the solution. Run pytest from a verifier-owned directory with `PYTHONSAFEPATH=1 python3 -P -m pytest` or `python3 -I -m pytest` so agent-planted startup files or `pytest.py` cannot bypass collection. Put executable build outputs on an exec-capable filesystem, not a noexec `/tmp`.
  - **Rubrics score final behavior, not work steps.** Do not award points for reading files, running a build, or following a particular process. Score the implemented model and required observable command surface. Keep the platform rubric synchronized with the canonical submission packet.
- **Hermetic fixtures:** build/compile into a fresh `tempfile.mkdtemp()` (own GOCACHE/GOPATH/classpath), never write into read-only `/app`.
- **Randomized differentials must not re-test pinned corners:** if >40% of generated cases hit a corner the curated suite already enforces, strip it from the generator (zero-param 66%→0%, count 8000→4000; injected bug still caught 53%).
- **Free-form explanation strings:** match structured fields exactly + assert key FACTS as order-independent substrings — exact string match creates a no-middle-band unfairness; count-only asserts (`len(findings)>0`) create false EASY.
- **Neutralize test/fixture labels and docstrings** ("latent defect", "second bug") — behavior_in_task_description FAILs on them; fix the labels, never describe the wall in the instruction.
- **⭐ Entry points can mask oracle/reference bugs.** A formatter may drop, truncate, or reindex a malformed internal result while keeping black-box CLI output correct. Test public intermediate methods and structural invariants directly, including empty inputs and output length, while preserving NOP failure on the actual missing behavior. Neutralize scaffold comments that reveal the algorithm, but keep the authoritative task-visible evidence required for fairness.
- **Editing `environment/repo` source (even comments) breaks `fix.patch`:** regenerate the patch against the edited base, confirm it carries none of the removed text, re-run oracle+nop.
- **Starter comments are agent-visible difficulty surface:** do not leave `NOTE`/TODO blocks that enumerate the exact incomplete components or missing mechanism families. Keep behavioral requirements in the public contract; let the agent locate work from neutral code and failing behavior. After scrubbing comments, regenerate `solution/fix.patch` from the clean base and confirm the patch does not reintroduce them.
- **Editing `environment/repo` source (even comments) breaks `fix.patch`:** regenerate the patch against the edited base, confirm it carries none of the removed text, re-run oracle+nop. **Editing environment files consumed at Docker-build time (SQL seed data, config files, static fixtures) does NOT break `fix.patch`** — only changes to files under the git-tracked source directory that the patch targets require patch regeneration. Always re-run oracle+nop after any environment change regardless.
- Two legit hardness-reduction patterns when the SPEC itself causes a 0%: location-string normalization in the comparison fn; honest coverage fixes. Never apply to dodge an intentional hidden convention.
- Guard every promised preservation clause with a test; give concrete observable acceptance bars, not algorithm names. Naming exact OUTPUT constants (reason codes, enum values) is fair and satisfies behavior_in_task — output constants aren't mechanism; never lump a should-be-ALLOW outcome in with suppression outcomes (spec coin-flip = unfair).
