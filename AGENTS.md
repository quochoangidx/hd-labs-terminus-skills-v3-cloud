## 1. TL;DR

Under a **warm loop** (persistent container + `docker exec`, real build+verify cycle), **Opus 4.8 medium solves nearly every fully-specified minimal-codebase task** — it derives its own reference and self-differential-tests thousands of cases. **Reliable HARD is not achievable by minimal spec-task building alone.** Ship honest MEDIUM (platform-OK for non-Python; Python tasks must be Hard). Only three levers still bite:

1. **Non-self-verifiable ground truth** — conformance over a hidden/divergent reference the solver cannot re-derive (§3). The genuine HARD lever, ~60% yield.
2. **Under-fuzzed input shape** — a boundary corner the solver's own fuzzing misses; interval-ledger/duty-cycle ports (§4). A ~0–25% lottery, not a guarantee.
3. **Decoupled decoy where the plausible fix is itself wrong** (§5). Necessary but not sufficient.

Everything else — rule complexity, counter-intuitive *stated* rules, named algorithms, cascade depth, optimization even when non-decomposable — collapses (§6). Probe honestly (§7): warm loop, N≥5, terse prompt, score by differential, never trust self-report or a lone 0/3.

**⭐ Master collapse law (Opus 4.8, confirmed over a 15-task blind-probe batch 2026-07-12):** a task holds under a fair blind probe **if and only if** it hides one of exactly two things — (a) an **undisclosed in-image library-quirk differential** (behaviour the solver can only match by differential-testing a real lib present in the image), or (b) an **undisclosed counter-intuitive rule** (a rule a naive-but-careful impl gets wrong). Everything disclosed-and-derivable is EASY. Corollary: a **DISCLOSED** counter-intuitive rule is *not* hard — Opus reads it straight from the spec and does not fall for "written-in-spec but contradicts the memorized standard" traps (hanabi downward-rotation, maven memorized-reference both collapsed 820/820 once stated). This forces the central tension below.

## 2. Core principles (why tasks collapse or hold)

- **Complete spec ⇒ Opus 3/3.** A fully-specified contract — stateless or stateful, simple or deeply cascaded, intuitive or counter-intuitive — gets transcribed and self-differential-tested. Adding rules, cascade depth, or counter-intuitive-but-stated rules never hardens a task.
- **Difficulty must be decoupled from the symptom.** Any symptom specific enough to anchor a fair instruction also tells a domain-expert solver the fix. If there is exactly one symptom and fixing it solves the task, it is 3/3 regardless of domain.
- **Named algorithm/idiom = collapse.** If the symptom makes a strong solver recall a named algorithm (Kahan/Neumaier, Chaitin-Briggs, HLL++, scalable-Bloom, A*-reopen, decode-to-fixpoint, tail-carry UTF-8, presume-abort, Hamilton apportionment, Efraimidis-Spirakis…), reject. Survivors are counter-instinct AND a non-default, non-obviously-named variant.
- **Hide the mechanism, state the contract.** Difficulty survives only when the spec describes the outcome, never the algorithm. Source comments and test labels are as much a difficulty surface as instruction prose — de-telegraph all three.
- **No middle band on arbitrary conventions.** Tiebreak direction, undocumented constants, bandwidth-model choice, rotation direction: hide it → unfair (0/N + spec-gate FAIL), state it → trivial. Retire on sight; a decoupled wall must also be enum-unconstrained or it's telegraphed.
- **Natural-impl-correct never bites.** The decoy structure only works when the plausible/natural fix is itself WRONG on a fixture; if a careful engineer's default implementation is correct, the task is 3/3.
- **Closed-form cost walls need a non-obvious exact constant** that is not searchable (never "smallest x meeting bound B" — emit a raw computed number) and never leaked via a worked example that evaluates the hidden formula.
- **Fully-stated optimization collapses** — non-decomposable, coupled tree-DP, carried-state, small-N brute-forcible: Opus derives the exact DP or brute-forces the ground truth and self-checks to the optimum (checkpoint-segment ultimately shipped MEDIUM; affine-carry, terrace DP, signal-repeater, min-makespan all 3/3).
- **User preference:** non-victim archetypes (estimation/aging/cost via a secondary observable) over victim/eviction-direction tasks; name slugs by domain (no "-ledger" suffix); `tbrain-<problem-slug>` without tool/repo filler.

## 3. Lever 1 — Conformance over a divergent / hidden reference (genuine HARD)

**Recipe:** ship a stub; bake an official machine-checkable suite HIDDEN under `tests/` (never in `environment/repo`); correct oracle; verifier calls a specific solver entry point; forbid vendoring third-party libs; **always probe offline** (a suite solved online can still hold offline — uri-template went 250/250 online but missed 15/249 offline). ~60% yield (10 HARD / 17 built).

**What holds:** WHATWG-URL, UTS-46 IDNA, RFC 9535 JSONPath, UAX-14 / UAX-29-sentence, JSON-Schema-2020-12, HTML5 tokenizer, iCal RRULE (hidden `python-dateutil` ground truth; tail = BYDAY ordinal, negative BYMONTHDAY, BYSETPOS, WKST divergence, Feb-29), CSS-Syntax-3 tokenizer, PHP composer version constraints (real-impl-as-spec, held 0/14), RFC 7208 SPF (with remediation), dockerignore matcher, protobuf schema-less wire decode, FASTA/FASTQ, DNS name compression, R splinefun/approx interpolation (fmm/natural/periodic/monoH.FC/hyman + linear/constant; port of R's splines.c/monoSpl.c/approx.c; the 5 spline methods are distinct targets differing by ~unity on the same data, so a generic cubic spline fails; Go matches R to ~6e-15 rel, tol 1e-9; oracle 1.0/nop 0.0 harbor).

**What collapses:** well-known formats/rules even with "edge cases" added — nginx-location, tar, bencode, msgpack, multipart, chunked HTTP, shell word-split, ical unfolding, css-specificity, iso8601-duration, poker/bowling/BLEU, RFC 6265 cookie (single contiguous algorithm = one-shot transcribable), Mustache (small rule set, no big table), **robots.txt RFC 9309** (Sonnet one-shots a correct independent port, 372/372 — hardening a memorized public library is futile), bibtex name-splitting (memorized; sole wall = one correlated hyphen quirk = 0/N flag with no fair fix), **Punycode RFC 3492** (complete-spec Bootstring algorithm; Python `'punycode'` stdlib available in Docker image → solver differential-tests trivially; 52 curated edge-case tests added — hyphens in basic portion, uppercase decode, supplementary intersections, boundary codepoints, bias thresholds — still 100% pass, honest ceiling MEDIUM), **R classical exact tests** (`fisher.test`/`ks.test`/`wilcox.test`/`binom.test`/`poisson.test`; 2026-07-12 fair offline probe EASY — blind Opus solver 466/466 pure-Go from knowledge: the exact algorithms are named/published (Fisher central-hypergeometric relErr rule, KS Marsaglia-Tsang-Wang + Birnbaum-Tingey psmirnov, cwilcox/csignrank DP), combinatorial parts come out bit-exact, and a loose 1e-9 p-value tol removes any special-function precision wall → knowledge-reachability collapse, not fixable by test-hardening). **R central distribution functions** (`pgamma`/`pbeta`/`pt`/`pf`/`pchisq`/`ppois`/`pbinom` + quantiles; 2026-07-14 fair offline probe EASY — blind Opus solver 308/308 pure-Go: log-space incomplete-gamma series + Lentz `betacf` CF + region-switch + safeguarded-Newton quantiles + AS-241 `qnorm` + Cody `pnorm`, matching R within 1e-9 across central/deep-tail/log_p/near-boundary. **The earlier claim that "nmath TOMS-708 is machine-precision non-re-derivable" was WRONG** — a LOOSE 1e-9 tolerance is achievable by textbook log-space series/CF, so R's more sophisticated bratio is unnecessary to pass. Same collapse class as the exact tests). **⭐ CORRECTED DISTINGUISHING RULE for numeric/library ports (2026-07-14, supersedes the machine-precision claim):** "reproduce standard function/library X to a LOOSE tol (1e-9)" is RE-DERIVABLE → EASY, even for gnarly-looking special functions, because textbook algorithms clear 1e-9. A numeric task holds ONLY when it has a **natural-implementation-is-WRONG decoy** (§5) — the plausible/textbook algorithm gives a materially wrong answer on a fixture, forcing the ONE correct variant: geodesic Vincenty-diverges-at-antipodes (Vincenty 1013/2740), date DST-offset-inheritance, numerical-stability decoys (Miller backward recurrence vs unstable forward, TR-BDF2 vs ringing trapezoidal) — OR a large UNION of R-specific arbitrary CONVENTIONS a solver must know exactly, not derive (quantile type 1-9 interpolation rules). Tightening tol to 1e-15 is UNFAIR (Go-vs-glibc libm differ ~1-2 ULP). For non-numeric, the reliable lever is IMPLEMENTATION-SPECIFIC accreted tool behavior where a natural impl is wrong (pkg-config private-static-non-dedup + diamond-multi-visitation, GNU date getdate + DST decoy, m4/make/ssh/perl). Never build "reconstruct a published algorithm / reproduce a standard function to loose tol" as HARD. **⭐⭐ ONE-vs-MANY DECOY RULE (the decisive 2026-07-14 finding — a decoy is necessary but ONE is not sufficient):** a single hidden natural-impl-wrong corner grades only **MEDIUM**, because independent blind solvers SPLIT on it (some read the spec/guess right) → it is derivable, not a universal 0/N wall. Reliable **HARD needs ≥2 INDEPENDENT, DE-CORRELATED hidden decoys** so no single insight clears the task and different solvers miss different slices. Measured on this batch: **gnu-date-parse = HARD** (2 independent decoys: DST-offset-inheritance on pure-relative-to-now AND unpadded getdate time fields `5:3:1` → 2 solvers each miss ≥1) vs **pkg-config-resolve = MEDIUM** (its only wall was ONE corner, private-static-non-dedup; run-1 solver got it right, run-2 missed it → split = derivable). And a decoy that is DISCLOSED in the spec collapses to fragile/EASY (r-spline `natural` linear-extrapolation, all 74 fails in that one disclosed family → a careful agent passes). **So: mine tasks with a MULTI-quirk tool whose accreted behavior has SEVERAL independent traps a natural impl gets wrong, keep them hidden (purge the authority), and confirm with a ≥2-run probe that solvers miss DIFFERENT quirks. Also: always run a 2-run probe, never 1 — a single run cannot distinguish a universal wall from a corner solvers split on, and it can hide an unfair spec bug (pkg-config's rpmvercmp `1.00`==`1.0` false hint caused run-1's only failures until fixed).**

**Selection rules:**
- Load-bearing rules must be **scattered/combinatorial across spec sections**, not one localized algorithm.
- Prefer an **unmemorizable, irregular table** (megabytes: UTS-46/UAX-14/UCA class data). Small clean rule sets collapse.
- **Stdlib-reachability trap is fatal:** if a Python stdlib one-liner reproduces the behavior (unicodedata normalize/casefold, json, csv, ipaddress, datetime, base64, urllib.parse, `'punycode'` codec), the solver differential-tests against it in-image. Use non-stdlib refs (hpack, CBOR, OpenPGP, collation, binary32 formatting). **When Python stdlib IS the reference used for test-vector generation, the Python version in the Docker image must match the generation environment — `'punycode'` codec output changed across Python versions (3.12 → different encodings for same strings vs earlier versions).** **⭐ The trap applies to the ENV image's `python3`, not just the corpus-gen host — the verifier is pytest so `python3` is ALWAYS installed in the built image and reachable by the agent. Any authority a python3-stdlib one-liner reproduces is therefore DEAD regardless of purging binaries: confirmed-dead candidates = tz/local-time (`zoneinfo`), `crypt(3)` password hashes (`crypt` module, present in 3.11), `openssl` cipher-string selection (`ssl.SSLContext.set_ciphers`/`get_ciphers`), plain `pnorm`/`qnorm` (`statistics.NormalDist.cdf/inv_cdf`). Pick authorities with NO python-stdlib equivalent (R incomplete-beta/gamma distribution & exact-test p-values, GNU date getdate grammar, pkg-config resolution, Rust/C++ symbol demangling, spline interpolation). Verified 2026-07-12: `golang:1.24-bookworm` ships `c++filt`, `pkg-config`(=pkgconf), `date`, `zdump`, `openssl`, `gcc`, `g++`, `python3`, AND `/usr/include/crypt.h`; `R`/`rustc` absent. Purge whichever binary is your authority — but `c++filt` is reachable via BOTH binutils (`c++filt`/`nm`/`objdump`/`addr2line`) AND `g++` (`abi::__cxa_demangle` in libstdc++), so cloning C++ demangling needs an invasive purge of binutils+gcc+g++; prefer Rust v0 demangling (rust:1.85-slim ships neither rustc-demangle nor a demangler, and offline cargo cannot fetch the crate).**
- **Vendored-copy leak when removing a `packaging` authority (2026-07-12, wheel-tag-compat):** the pep440-style prune of `*/{pip,setuptools,pkg_resources}/_vendor/packaging` is INSUFFICIENT — the `wheel` package (present on `rust:1.85-slim`) ships `wheel/vendored/packaging/tags.py`, so `from wheel.vendored.packaging.tags import parse_tag` still works and leaks the compressed-tag expansion. Prune broadly: `find / -type d -name packaging \( -path '*/_vendor/*' -o -path '*/vendored/*' \) -prune -exec rm -rf {} +` AFTER `pip uninstall packaging`, then verify in-image that `import packaging` AND every `*.vendored.packaging.*` variant fail and `find / -type d -name packaging` is empty. pytest 8.4.1 still runs with packaging fully absent.
- **Ill-conditioned-reference trap (numerical conformance):** when the authority's DOUBLE-precision result is itself ill-conditioned vs the exact/high-precision reference, generate expected values by running the authority's OWN double-precision implementation, NOT its ultra-high-precision validation dataset. WGS84 geodesics: the official `GeodTest.dat` gives 50-digit values, but double-precision Karney legitimately diverges from them by up to ~2e-4° in azimuth at exact antipodes/poles (inherent conditioning, not a bug) — so expected = geographiclib **Python** (double Karney), with `GeodTest.dat` used only to SELECT inputs across regimes (near-antipodal/polar/equatorial/meridional). Same shape as "expected computed by running R" (quantile). **Cross-language libm divergence sets the tolerances:** Go `math` vs glibc differ ~1-2 ULP, fine on well-conditioned fields (s12 rtol 1e-12, lat 1e-9) but amplified where the quantity is ill-conditioned (antipodal azimuth) — so use a per-field **conditioning filter**: at corpus-build time run the Go oracle alongside the authority and grade a field only where the oracle reproduces it within tol/10 (drops just the pathological antipodal/polar azimuths, keeps every well-conditioned field). Verifier stays trivial (per-row `check` field-set). golang:1.24-bookworm ships NO geodesic authority (no GeodSolve/geographiclib/proj) → no purge needed, unlike ssh/perl/make.
- **Real-impl-as-spec** works, but every disclosed "subtlety"/example MUST be oracle-verified per-case — one false hint (composer `1.0.0-beta` claim; jsonpatch "`/` = whole document", when RFC 6901 says `/` = empty-string key) creates an unfair correlated 0/N and a reviewer reject. **When the instruction pins a specific library version as the reference ("match library X version Y exactly"), every test expected value MUST be generated by actually running that library — never hand-computed from its documentation or spec.** The library's actual behavior can diverge from what its own spec says (editorconfig==0.17.1: `get_properties()` keeps `"unset"` values in the result dict, while the EditorConfig spec describes `unset` as "removing" the property). A reviewer caught this by running the named library against the verifier's test cases; hand-computed expected values that removed `unset` were returned.
  - **Composer constraint satisfaction hardening (2026-07-13):** a narrow matrix (≈50 constraints × 39 versions) plus prose that spells out dev-branch/stability/pre-release comparator behavior grades too easy. Re-harden with Composer 3.4.3 authority-generated vectors over numeric branch versions (`1.x-dev`, `1.2.x-dev`, `v1.x-dev`), `x/X` wildcards, optional `v` prefixes, comparators with spaces (`>= 1.0`, `!= 1.2.3`), hyphen lower pre-release bounds, bare version stability flags (`1.0.0@RC/@beta/@dev`), build-metadata constraints, and mixed comma/space/`||` groups. Keep examples oracle-verified and hidden-corpus-disjoint; put conventions in examples, not in telegraphing prose. Update the official solution/parser against the same authority before shipping.
- **Offline library conformance must be self-contained.** If tests pin exact behavior from an unavailable implementation, "match library X" is not enough: either document the algorithm, tie-breaks, and edge cases in an agent-visible offline reference, or ship allowed offline source/reference (uri-template: bundle RFC 6570 Appendix A + encoding sets as `/app/RFC6570.md`). BUT self-containment and difficulty can conflict: if fair disclosure forces you to hand over the whole reasoning wall (TER/sacrebleu block-shift algorithm — a reviewer demanded it be disclosed for offline fairness, yet the best agent already reconstructed it to 162/163 from memory), disclosing flips the task EASY → DROP (see the Disclose-vs-DROP test below).
  - **Reference-unreachable ⇒ an agent-facing `examples.json` of input→output rows is REQUIRED, not answer-leakage** (cartoq/node-semver, no Node in image, 2026-07-12). When the ONLY discoverable signal for a canonical output convention is the examples file, an "instruction sufficiency" return means the hidden corpus grades families the examples never show. Fix = add a *handful* of rows per flagged family. The verifier reads only the hidden corpus (never examples.json), so example VALUES must be exactly right — generate each by running BOTH the oracle in-image AND the real authority (`node:22` + `npm i semver@7.6.3`) and confirm they agree, and confirm every added query-object is corpus-DISJOINT (the reviewer's own named literals — bare `||`, `x - 1.0.0`, `1.0.0 - x`, `0.x || 1.x` — were all verbatim corpus rows, so teach the same rule with disjoint siblings + a contrast row that keeps the real bound, e.g. `x - 2.5.0`→`<=2.5.0`, `0.x || 2.x`→`<1.0.0-0||>=2.0.0 <3.0.0-0`). This is the mirror image of the css-tokenization verdict (strip outputs when a reference IS reachable or the rows leak the graded corpus): reachability decides the direction.

**0/N-coverage-flag remediation** ("some tests not passed by any agent"):
- **⭐ Suspect the ORACLE before you prune.** N independent strong agents each reconstruct the authority; when they all disagree with the oracle on the same cluster, the base rate says the oracle is wrong. Re-derive every expectation in the cluster by running the REAL authority (a live `node_modules/semver`, the actual jar, the upstream binary) and differential-fuzz the oracle against it over tens of thousands of generated inputs — the corpus is self-consistent with the oracle's bugs by construction, so `oracle == corpus` proves nothing; gate on `oracle == authority`. Pruning first just deletes the evidence: the semver-range family's two 0/N valid_range clusters (numeric-after-wildcard, build-metadata-on-partial) were BOTH oracle bugs, the prune cleared the flag, and a client reviewer returned the sibling task months later. Only once the oracle is proven conformant is a 0/N cluster evidence of a real blind spot, and only then do the moves below apply.
- Diagnose from the per-test pass table, not the summary. Classify each 0/N case: redundant group test → delete; monolithic/aggregate test → **parametrize per-case** (always prefer per-case over per-area aggregates — clears behavior_in_tests without seeding the flag); irreducible correlated blind-spot tail → **prune** the ≤5/10 cases keeping softer representatives of every feature cluster (ceiling = min kept pass-count; keep it ≤60% for HARD); spec ambiguity/convention → **disclose** in the instruction; over-concentration (46% of corpus = one trap) → delete the adversarial bulk of that one feature, keep it minimally covered.
- **Anti-hardcoding flag** ("visible fixtures → hard-coding possible"): add a runtime differential vs a HIDDEN oracle copy in `tests/reference/`, generating well-specified rules deterministically at verify-time (fixed seed, per-case) restricted to the envelope MINUS every previously-pruned feature; prove flag-safety with a correct-except-pruned-feature emulation and teeth with a plausible-bug emulation.
- Keep test-format checks decoupled from result correctness (SPF `test_output_format` re-tested hard results = double jeopardy → 4/10 artificial cap).

**⭐ Disclose-vs-DROP decisive test (the 2026-07-07 batch).** A 0/N return on an all-or-nothing "match named lib" port is either fixable-by-disclosure or a DROP, decided by ONE question: *does a BROAD residual wall survive after you disclose the correlated blind spot?*
- **Disclose & KEEP** when a genuinely broad, self-contained wall remains and the BEST agent still falls well short of 100%. Cluster 0/N cases by feature, extract EXACT values from the oracle (build the oracle binary; generate DISJOINT worked examples, not corpus rows), ship an in-env `<LIB>_NOTES.md` (`COPY` before the image's `git add`; reachable at `/app/...`) + a narrative instruction pointer. Disclose LOOKUP knowledge (formatting rules, regex, function surface, aggregation formula), NOT the reasoning wall. Proven on **jsonnet-eval** (full interpreter = fair broad wall, best agent 93%). ⚠️ Disclose COMPLETELY — a partial rule is a new correlated blind spot (ter-score round-2: `no_punct` note gave only the ASCII class, missing CJK/full-width removal under `asian_support` → new near-0/N).
- **DROP** when difficulty is NARROW (best agent within 1–3 of 100%, all runs ~95%+, sub-100% tests all the SAME few features) OR the "wall" is an offline-unreachable library internal that fairness FORCES you to disclose AND the best agent already nears 100% without it. Disclosing then flips it EASY with nothing left to hold the pass rate down. Dropped **cookie-string-parse** (one `Domain=.` gotcha), **icu-messageformat** (3 ICU quirks: half-even, stray-`}`, `'#'`-outside-plural), **ter-score** (block-shift algo is a `lib_ter.py` internal; a reviewer demanded it be disclosed for offline fairness, but best agent already hit 162/163). Same profile as css-syntax / vcard. Move files to `workspace/dropped/`, add `DROPPED.md`, do not resubmit.
- Non-ASCII **literal** text (RFC 6570 `ucschar`/`iprivate`, and similar) is copied VERBATIM, never pct-encoded — only expanded VALUES are encoded. A byte-wise scanner that pct-encodes every byte ≥0x80 is a common oracle bug the official vectors miss; add a focused case.

**⭐ Pure-contract-ambiguity 0/N (undisclosed OUTPUT contract, NOT a coverage cluster; 2026-07-13 approval-quorum-arbiter, inventory-lot-allocator).** When a hand-authored all-or-nothing verifier returns 0/N with oracle 100% and best agents nail the SEMANTICS but fail on the serialization, the root cause is an uninferable output contract — output wrapper (`{"decisions":[…]}`), exact field names/types (integer timestamps, `acceptedApprovers:[]`-on-reject), cold-vs-ambient ordering, per-order vs global capacity. Disclosing the contract is **MANDATORY** (hiding it is just unfair), but by the master law it usually collapses to EASY because the algorithm is derivable once the contract is known. Two exits: (i) if the HARD levers are untouched by the disclosure (they live in the semantics, not the contract), disclose the schema in TEXT ONLY and difficulty is preserved (inventory-lot-allocator — disclose shipment schema + `coldCapacity` per-order + ambient-before-cold, HARD kept); (ii) if disclosure collapses it, **REDESIGN**: keep the contract disclosed and bury ONE undisclosed counter-intuitive rule (approval-quorum: same-manager `separation` for a *delegated* approval is charged to the delegation's ISSUER `d.from`, not the approver's own manager — naive impls key on the approver → fail only that test). **Never ship disclosed-only.**

**⭐ fair⊥hard on a single-lever task ⇒ DROP (2026-07-13 hanabi-play-adjudicator, provenance-release-gate, arena-generation-tag).** When a task's ENTIRE difficulty is one boundary/off-by-one/precedence rule, disclosing it → EASY (master law) and hiding it → unfair 0/N — there is no fair-and-hard path, and neither a worked-example nor an added *stated* counter-intuitive lever rescues it (hanabi's downward-rotation lever still solved 820/820). Fingerprint: a self-contained game-replay or single-invariant adjudicator whose 0/N flag correlates to exactly one code path. **DROP it the moment the 0/N flag appears** (hanabi, provenance both dropped). Escape only if you can ADD a genuinely orthogonal *undisclosed* second lever with a broad footprint (dkim `b=`-not-last; hex-requirement orthogonal intersection=0) — a de-correlated single-blind-spot inside a LARGE multi-rule spec is the target HARD shape, a lone lever is not. ⚠️ An output-contract field that names the fix mechanism (arena STATS `retired`) forces the lever into the open → hide-the-mechanism is impossible → SHIP MEDIUM (state the invariant + open question, not the recipe) or DROP. Always probe the ORIGINAL instruction too: "was accepted as hard once" ≠ hard-clean.

**⭐ Reviewer "document family X" where X is the prior probe-surviving lever ⇒ OVER-DISCLOSE collapse (2026-07-13 yaml-document-load r9).** Documenting the exact mechanism that a previous round's probe survived on hands the wall over → eval Opus jumps to 100%. Fix: REVERT the doc + REMOVE the now-telegraphed test, and restore hardness with a DIFFERENT undisclosed lever (yaml: dropped the NaN-key doc/test, added undisclosed YAML-1.1-vs-1.2 scalar quirks — `0o17`→string, `on`/`off`→bool but `y`/`n`→string, `1:20`→sexagesimal 80). Distinguish from the legitimate "disclose the contract" move: disclose ambiguous CONTRACT/vocabulary, never the load-bearing lever a probe already proved holds.

**⭐ 0/N with `verifier_did_not_run` / 0 tokens AND oracle 100% = Step-0 INFRA, not coverage (2026-07-13 pchip-interpolate-rust).** Before touching the corpus, check the Dockerfile: a `rust:1.85-slim` (or similar minimal) base often omits `tmux`+`asciinema`, which the harness needs to record the agent session → every run dies before solving. Fix = apt-install `tmux asciinema` in the Dockerfile. Rule out this infra cause FIRST whenever 0/N coincides with a passing oracle and non-semantic ("other"/no-token) failures.

**Out-of-band-TOO-HARD remediation** ("Solvable" but 0/N agents reach 100% under all-or-nothing; best agent ~85%): **TRIM the hardest never-solved cases, keep binary 0/1 scoring — NEVER switch to pass-rate/threshold** (proportional reward is a flagged verifier defect). Data-driven from the per-case pass table: compute each agent's failure count; trim N cases → every agent failing >N is guaranteed to stay <100% (provable ceiling), so pick N between the top agent's failure count (floor) and the (k+1)-th agent's (ceiling) to land the 10–40% band. Also relax any PIN test that re-walls a trimmed behavior. yaml-load 86→67 cases, ceiling 30%. Coverage-expansion and band-fit pull opposite ways — tune corpus SIZE, not the reward.

**Test-only re-hardening of a complete-spec task that graded TRIVIAL** (instruction/difficulty untouched):
- **Expected values must be oracle-verified, never hand-computed.** For both Punycode and OpenPGP packet framing, multiple hand-computed expected values were wrong despite appearing correct on inspection — only the Go oracle binary (built from `fix.patch`) is authoritative. Generate ALL vectors by running the oracle, capture stdout, and assert roundtrip correctness. Hand-computed Punycode vectors for `a+U+0100` gave `xn--a-xda` (wrong) vs oracle `xn--a-mha` (correct); the bias threshold test category lost all discriminating power without oracle verification.
- **Mutation-guided fixtures** (broker-consumer-rate): build ~9 plausible-but-wrong mutant engines, measure which fixtures catch each, add curated fixtures until every mutant is caught by ≥2. The client-reported near-misses are exactly the thinnest-coverage mutants.
- **Library-semantics differentials** (graphviz agget): add cases hitting the delegated library's subtle effective-value semantics (inherited defaults, byte-lex strcmp ordering, non-back-propagation) — generate ALL expected values by running the oracle in the task's own image, never hand-computed, and drop any candidate where spec and oracle disagree. Validate with plausible-wrong variants.
- Honest ceiling: tests-only hardening raises the bar for subtle-boundary bugs but cannot force 1/10 when the spec is complete.

**Instruction/test symmetry audit (both directions), applied on every conformance/matcher task:**
- Grep the verifier for every field/sentinel/constant it pins and confirm each is stated in the PRIMARY spec body — never only in an appendix example (cups-queue: `failover` always-present-`null` in JSON vs omitted in conf; `generatedAt == requestedAt`).
- Every stated failure diagnostic needs a discriminating test (jsonpatch: "print `error` on stderr" had no assert — added, verified discriminating via a silent-on-stderr variant).
- **Symmetry covers the implementation LANGUAGE.** A verifier that shells out to a language-specific check (`php -l`, `tsc`, `javac`, `go vet`) pins the language; an instruction saying only "an executable script" lets a rewrite in another language fail the build. State it ("keep it a single self-contained PHP file at `/app/<bin>`") or drop the check and validate by running the program (cartogram-dataset-resolver).
- **Symmetry covers the INPUT MODE (criterion 38 / E2).** If instruction.md says the program reads from its file-argument OR from stdin when no arg is given, the verifier MUST exercise BOTH paths — a suite that only runs `[BIN, path]` is a reviewer-blocking gap even when everything else is green (broadcast-airtime-ledger Go, 2026-07-12; the reviewer accepted the rebuttal on the TODO scaffold but held the line on the untested stdin mode). Fix = add a `_run_binary_stdin(text)` helper (`subprocess.run([BIN], input=text, text=True, …)`) and a test that feeds a spread of logs on stdin and asserts the stdin report equals BOTH the file-argument report and the reference. This gap is per-port: sibling language zips that only test the file path carry the identical gap and will be returned too.
- When a reviewer asks you to disclose an edge-case family and quotes literals that are **verbatim hidden-corpus rows**, do NOT paste them: teach the same rule with oracle-verified, corpus-disjoint siblings from the same family plus a contrast row that blocks over-correction (`>=01.0.0`→null beside `0.0.7`→`0.0.7`; `>4.x`→`>=5.0.0` beside `<=4.7.x`→`<4.8.0-0`). Corpus coverage and difficulty both survive.
- **Disclose the token CLASS, not the char list (2026-07-13 cookie-prefix-session-gate r4).** When a reviewer says "define what counts as malformed/invalid X", name the KIND and the FAILURE CLASS ("a cookie name must be a non-empty HTTP token; names with whitespace or HTTP separator punctuation are malformed") — never enumerate the literal allow/deny set (`( ) < > @ , ; : \ " / [ ] ? = { }`). Same fair⊥trivial tension the master law predicts on any disclosed lever. ⚠️ A shipped instruction can be rewritten by earlier review rounds — re-extract and diff the CURRENT zip before editing, don't assume your last wording survived.

- **Precedence/tie rules must ALSO govern the side outputs they emit.** When the spec picks a winner ("most-recent-start notice takes precedence"), the instruction must say that precedence also decides warnings/logs/counters, not just the primary result — a blanket "each active X produces a warning" contradicts an oracle that emits only the *winning* X's warning, and the contradiction is a correlated 0/N: agents follow the prose, emit both, and cap one test short (cups-queue-config overlapping-failover — agents stuck at 13/14, GPT-5 0/5; fixed by rewording para 3 to "only the precedence-winning notice produces its warning; superseded notices produce none," instruction-only, oracle/nop untouched at 1.0/0.0). **Vendored-authority differential oracle** (bake the REAL tool's output as hidden corpus; ship the tool binary+libs only under `solution/`, exec'd by a thin task-language wrapper `solve.sh` drops into `/app/vendor`; agent has no authority → must reimplement it). Proven end-to-end on **tbrain-ssh-config-resolve** (Go, authority = OpenSSH `ssh -G` effective client-config resolution; oracle 1.0/nop 0.0 docker+harbor). Load-bearing lessons:
  - **⭐ The base image may ALREADY ship the authority → difficulty collapses silently.** `golang:1.24-bookworm` ships `openssh-client` (`/usr/bin/ssh`); an agent shells out to `ssh -G` and one-shots it. `gcc:13-bookworm` ships `make` AND `m4` (both dpkg-owned → `apt-get purge -y m4 || true` + `rm -f /usr/bin/m4 /usr/bin/gm4`, verify `command -v m4 gm4`→NONE in the BUILT image); debian bases often ship the very tool you're cloning. This is the binary-authority analogue of the stdlib-reachability trap (§3).
  - **Vendoring is trivial when the corpus-gen base and the env image share the same debian release.** Extract `/usr/bin/<tool>` + every `ldd`-reported `.so` from a throwaway `debian:bookworm-slim` container; DROP `libc.so.6` (use the env image's identical bookworm glibc + loader — avoids libc/loader coupling), keep the rest; the wrapper sets `LD_LIBRARY_PATH=/app/vendor/lib`. Generate the corpus by running the SAME vendored binary INSIDE the env image (as root) so output is byte-identical to verify-time.
  - **Glibc-independent loader-exec variant (tbrain-m4-macro-processor, C authority = GNU m4 1.4.19).** If you'd rather not couple to the env image's glibc at all, vendor `libc.so.6` + `ld-linux-*.so.2` too and exec THROUGH the loader: `setenv("LC_ALL","C",1); execv("/app/vendor/ld-linux-x86-64.so.2", {"ld","--library-path","/app/vendor","/app/vendor/m4",NULL})`. Fully offline, immune to glibc micro-version drift, inherits stdin/stdout unchanged. Corpus/oracle byte-identical because it's literally the same vendored binary + `LC_ALL=C` both places. Corpus footgun for tools with rescanning (m4): bare `$0` in a body and `define(\`x',\`x')` **infinite-loop** (fix `$0` by double-quoting the body); `f()` empty-parens has `$#==1` not 0; generate with a `timeout` guard + per-case exit-code capture and DROP every nonzero-exit case. 338 cases/18 families, oracle 1.0/nop 0.0.
  - **Version-robust subset grading that stays FAIR + keeps families independent:** compare only a chosen key subset (exclude version-specific mega-defaults — ssh ciphers/macs/kex/hostkeyalgorithms), and per case grade only CORE keys (always) plus non-core keys whose authoritative value differs from the plain default. This stops one wrong default from cascading a 0/N across all cases while still pinning every exercised quirk; ensure each graded key has ≥3-4 non-default cases so thin coverage isn't a single-case 0/N.
  - **ssh -G quirk map** (reusable): booleans split — `pubkeyauthentication`/`controlmaster`(yes)/`requesttty`(yes)/`stricthostkeychecking`(yes)/`addkeystoagent`(yes) print `true`/`false`, but `forwardagent`/`forwardx11`/`compression`/`gatewayports`/`tcpkeepalive`/`identitiesonly`/`exitonforwardfailure` print `yes`/`no`; `SetEnv` is FIRST-directive-only while `SendEnv`/`IdentityFile` ACCUMULATE across directives; `HostName` expands only `%h`/`%%` (an invalid `%n`/`%p`/`%r`/`%u` there errors out), and `IdentityFile` `%`-tokens print literal in `-G`; `Port 022`→`22` (int-canon); `connecttimeout` default is `none` not `0`; first-value-wins per keyword, `-o` highest precedence (applied first).

## 7. Probing & grading methodology

- **Warm loop or the number is garbage:** the probe must give the agent a working build/run loop matching the platform toolchain (persistent container + `docker exec`). Blind-write, broken-mount, dropped-PATH (`bash -lc` loses go), or wrong-toolchain (host go1.22 vs pinned go1.24) probes produce FALSE 0/N. Verify the loop compiles before trusting any 0/3.
- **N≥5; pool same-engine runs.** n=3 is variance (a true ~20% family read 0/3 and 3/5 on identical engines). Never harden one port to chase a per-port number; extend n instead.
- **Local probes are over-generous vs platform:** local 1/3–2/3 routinely maps to platform TRIVIAL. Only a local 0/3 with semantic failures is a shippable HARD signal; local probes can confirm HARD, never MEDIUM. Exception: tie-direction-by-differential tasks read falsely trivial locally — trust the platform.
- **Run probes from the orchestrator** with fresh subagents (build agents are contaminated — they've seen the oracle and systematically leak the wall via comments/prose/Chekhov-gun fields; always leak-audit grep before probing). Solve dirs must be ISOLATED OUTSIDE the repo (agents escape into sibling `verify/` dirs) with a TERSE canonical prompt — hint-rich prompts inflate solve rate ~2–3× ("focus on edge cases" is the main inflator).
- **Score by differential, never self-report:** copy the solver's changed source into the real task + verifier and run pytest/harbor nop in Docker (absolute host paths; auto-detect the build root — solvers restructure layouts). Every failing solver in the port batches "built clean and reported byte-for-byte correct."
- **A 0/N is not proof of fairness:** verify a canonical-correct independent solver actually passes the verifier; when N agents converge on the same wrong answer, reproduce and check whether the reference (and the oracle, which may share its bug) is canonically correct.
- **Validate any base before porting:** gate on harbor oracle=1.0 AND nop=0.0 AND a blind probe that actually fails (found bases with stub==solution, non-compiling images, and 3/3 "hard" labels).
- **Infra death ≠ difficulty:** 0/N with `verifier_did_not_run`/0 tokens/"other" failures (Bedrock 503, OpenAI 429, geoblocking) is platform death — check oracle 3/3 and request a re-run; `n_errors=0` failures ARE valid semantic fails. Harbor LLM calls and stb agent runs are geoblocked from VN (403 region) — needs VPN. Background pipeline agents die silently mid-run: verify results on disk; never build in auto-cleaned worktrees with relative paths (deleted 2 of 4 builds).
- Keep local compute light: validate in Docker (harbor), not on the host; no 2^n brute force for n>18 locally.

## 8. Verifier & test design

- **State the OUTCOME, not the mechanism.** Detailed rules live in `/app/SPEC.md` (or an RFC-style file under `environment/app/`), instruction.md keeps goal + high-level names of every tested violation kind.
- **Binary reward 0/1, never proportional.** Clients flag the CTRF proportional-reward pattern as a verifier defect. Fix coverage honestly (per-case parametrize / prune / disclose) and use the standard pytest-exit-code block; oracle must then pass 100%.
- **Build the candidate from `/app` source at verifier import time** — never `shutil.which()` or a pre-installed binary path (makes nop ungradeable, fragile to nonstandard build paths).
- **Use the project's own build system, never hardcode compiler invocations in the verifier.** A `build_binary` fixture that calls `g++ src/main.cpp src/engine.cpp` instead of `make` (or `cargo build`, `go build ./...`, etc.) ignores agent-added source files and Makefile updates, failing the agent unfairly. Always invoke the project's build tool so agents can modularize freely.
- **A build helper must check the build's EXIT STATUS, not just that the artifact exists.** `make clean` → assert the binary is gone → build → assert `returncode == 0` (stdout+stderr in the message) → assert the binary exists. Otherwise a warm `RUN make` in the Dockerfile leaves a stale binary and a non-compiling submission is graded green against it (reviewer-returned on quill-plugin-resolver). Drop the warm build step from the Dockerfile too; verify by injecting a compile error and confirming reward 0 with the non-zero build status surfaced.
- **Hermetic fixtures:** build/compile into a fresh `tempfile.mkdtemp()` (own GOCACHE/GOPATH/classpath), never write into read-only `/app`.
- **Randomized differentials must not re-test pinned corners:** if >40% of generated cases hit a corner the curated suite already enforces, strip it from the generator (zero-param 66%→0%, count 8000→4000; injected bug still caught 53%).
- **Free-form explanation strings:** match structured fields exactly + assert key FACTS as order-independent substrings — exact string match creates a no-middle-band unfairness; count-only asserts (`len(findings)>0`) create false EASY.
- **Neutralize test/fixture labels and docstrings** ("latent defect", "second bug") — behavior_in_task_description FAILs on them; fix the labels, never describe the wall in the instruction.
- **Editing `environment/repo` source (even comments) breaks `fix.patch`:** regenerate the patch against the edited base, confirm it carries none of the removed text, re-run oracle+nop. **Editing environment files consumed at Docker-build time (SQL seed data, config files, static fixtures) does NOT break `fix.patch`** — only changes to files under the git-tracked source directory that the patch targets require patch regeneration. Always re-run oracle+nop after any environment change regardless.
- Two legit hardness-reduction patterns when the SPEC itself causes a 0%: location-string normalization in the comparison fn; honest coverage fixes. Never apply to dodge an intentional hidden convention.
- Guard every promised preservation clause with a test; give concrete observable acceptance bars, not algorithm names. Naming exact OUTPUT constants (reason codes, enum values) is fair and satisfies behavior_in_task — output constants aren't mechanism; never lump a should-be-ALLOW outcome in with suppression outcomes (spec coin-flip = unfair).

## 9. Client-review playbook (human reviewers sit above the green scanner)
