## 1. TL;DR

Under a **warm loop** (persistent container + `docker exec`, real build+verify cycle), **Opus 4.8 medium solves nearly every fully-specified minimal-codebase task** — it derives its own reference and self-differential-tests thousands of cases. **Reliable HARD is not achievable by minimal spec-task building alone.** Ship honest MEDIUM (platform-OK for non-Python; Python tasks must be Hard). Only three levers still bite:

1. **Non-self-verifiable ground truth** — conformance over a hidden/divergent reference the solver cannot re-derive (§3). Was the genuine HARD lever (~60% yield historically); by 2026-07-19 the FRESH survivor set is nearly empty — needs an UNDER-documented reference AND a broad multi-rule tail AND a category-safe shape (§6 batch-10 verdicts).
2. **Under-fuzzed input shape** — a boundary corner the solver's own fuzzing misses; interval-ledger/duty-cycle ports (§4). A ~0–25% lottery, not a guarantee — and ports are closed by the fresh-only doctrine (§2).
3. **Decoupled decoy where the plausible fix is itself wrong** (§5). Necessary but not sufficient; fresh stub-fill variants collapse via the disclosure trap (§6).

**⭐ Current status (2026-07-19): the three levers above are mostly HISTORICAL context for remediating returned tasks — every fresh minimal-spec-engine seam is mapped dead/spent (§6). The live lanes for NEW tasks are the bd-mgmt seam (task-miner "bd-mgmt seam"; strongest real-CI category signal, needs INTERACTING resolver rules) and interaction/scale shapes (task-miner/interaction_shape_recipe.md; difficulty from ≥3 coupled causes + discovery breadth, escapes the master collapse law).**

Everything else — rule complexity, counter-intuitive *stated* rules, named algorithms, cascade depth, optimization even when non-decomposable — collapses (§6). Probe honestly (§7): warm loop, N≥5, terse prompt, score by differential, never trust self-report or a lone 0/3.

**⭐ Master collapse law (Opus 4.8, confirmed over a 15-task blind-probe batch 2026-07-12):** a task holds under a fair blind probe **if and only if** it hides one of exactly two things — (a) an **undisclosed in-image library-quirk differential** (behaviour the solver can only match by differential-testing a real lib present in the image), or (b) an **undisclosed counter-intuitive rule** (a rule a naive-but-careful impl gets wrong). Everything disclosed-and-derivable is EASY. Corollary: a **DISCLOSED** counter-intuitive rule is *not* hard — Opus reads it straight from the spec and does not fall for "written-in-spec but contradicts the memorized standard" traps (hanabi downward-rotation, maven memorized-reference both collapsed 820/820 once stated). This forces the central tension below.

## 2. Core principles (why tasks collapse or hold)

- **Complete spec ⇒ Opus 3/3.** A fully-specified contract — stateless or stateful, simple or deeply cascaded, intuitive or counter-intuitive — gets transcribed and self-differential-tested. Adding rules, cascade depth, or counter-intuitive-but-stated rules never hardens a task.
- **Difficulty must be decoupled from the symptom.** Any symptom specific enough to anchor a fair instruction also tells a domain-expert solver the fix. If there is exactly one symptom and fixing it solves the task, it is 3/3 regardless of domain.
- **Named algorithm/idiom = collapse.** If the symptom makes a strong solver recall a named algorithm (Kahan/Neumaier, Chaitin-Briggs, HLL++, scalable-Bloom, A*-reopen, decode-to-fixpoint, tail-carry UTF-8, presume-abort, Hamilton apportionment, Efraimidis-Spirakis…), reject. Survivors are counter-instinct AND a non-default, non-obviously-named variant.
- **Hide the mechanism, state the contract.** Difficulty survives only when the spec describes the outcome, never the algorithm. Source comments and test labels are as much a difficulty surface as instruction prose — de-telegraph all three.
- **No middle band on arbitrary conventions.** Tiebreak direction, undocumented constants, bandwidth-model choice, rotation direction: hide it → unfair (0/N + spec-gate FAIL), state it → trivial. Retire on sight; a decoupled wall must also be enum-unconstrained or it's telegraphed.
- **Natural-impl-correct never bites.** The decoy structure only works when the plausible/natural fix is itself WRONG on a fixture; if a careful engineer's default implementation is correct, the task is 3/3.
- **Closed-form cost walls need a non-obvious exact constant** that is not searchable (never "smallest x meeting bound B" — emit a raw computed number) and never leaked via a worked example that evaluates the hidden formula.
- **Fully-stated optimization collapses** — non-decomposable, coupled tree-DP, carried-state, small-N brute-forcible: Opus derives the exact DP or brute-forces the ground truth and self-checks to the optimum (checkpoint-segment ultimately shipped MEDIUM; affine-carry, terrace DP, signal-repeater, min-makespan all 3/3).
- **User preference:** non-victim archetypes (estimation/aging/cost via a secondary observable) over victim/eviction-direction tasks; name slugs by domain (no "-ledger" suffix); `tbrain-<problem-slug>` without tool/repo filler.
- **⭐ User preference — fresh-only mining doctrine (2026-07-19):** default = 100% NEW tasks; no ports/reskins of shipped/held engines, no same-corpus variants, no twists on existing gallery/portfolio tasks (`gallery_novelty` must be `novel`). History serves only as forbidden-zone map (§6 + collapse verdicts), design laws (collapse-law screen), and dedupe/novelty lookup — never as the idea source. Ports run ONLY on explicit user request via task-language-port, and an engine with ≥5 shipped variants is originality-saturated (DKIM at 8 = closed). Quantified saturation ledger from the 91 platform-passed tasks (user-provided 2026-07-19): UAX-14 wrap 10, UAX-29 sentence 8, WHATWG URL canonicalize 8, version-constraint 8, viterbi decode 7, RFC 6570 URI template 6, LOWESS 5 — all CLOSED; full member lists + sub-threshold counts in `mined-candidates/platform-passed-portfolio.md`. ⚠️ Those passes are largely grandfathered (pre-date the category/template/originality enforcement) — the ledger is for dedupe/saturation only, never evidence a shape clears today's CI, and passed ≠ hard (non-Python MEDIUM is platform-OK). Expect 2–4 delivered tasks/batch under honest gates; a high kill rate is the design working — never backfill quota with ports. Source repos come from active **Repo Prospecting** (task-miner): `gh search` by lever/archetype signal for mature-but-obscure repos (~100–5k stars, ≥2y history) — famous repos are memorization-poison (frontier solvers know their behavior and bug history cold), so the static Source Queue is fallback-only. Full doctrine (6-source idea menu, 20–30-idea fan-out, exploration-map logging): task-miner, "Fresh-only exploration doctrine". Two priority lanes added 2026-07-19: **bd-mgmt seam** (manifests/lockfiles/dep-graphs as the OBJECT — strongest real-CI category signal on record, purl→bd-mgmt 1.0; needs INTERACTING resolver rules, not standalone quirks; task-miner "bd-mgmt seam") and **interaction/scale shapes** (multi-service ops restoration, stateful data-store operations, long-context cross-referencing — difficulty from ≥3 coupled causes + discovery breadth, escapes the master collapse law; recipe: task-miner/interaction_shape_recipe.md).

## 3. Lever 1 — Conformance over a divergent / hidden reference (genuine HARD)

**Recipe:** ship a stub; bake an official machine-checkable suite HIDDEN under `tests/` (never in `environment/repo`); correct oracle; verifier calls a specific solver entry point; forbid vendoring third-party libs; **always probe offline** (a suite solved online can still hold offline — uri-template went 250/250 online but missed 15/249 offline). ~60% yield (10 HARD / 17 built).

**What holds:** WHATWG-URL, UTS-46 IDNA, RFC 9535 JSONPath, UAX-14 / UAX-29-sentence, JSON-Schema-2020-12, HTML5 tokenizer, iCal RRULE (hidden `python-dateutil` ground truth; tail = BYDAY ordinal, negative BYMONTHDAY, BYSETPOS, WKST divergence, Feb-29), CSS-Syntax-3 tokenizer, PHP composer version constraints (real-impl-as-spec, held 0/14), RFC 7208 SPF (with remediation), dockerignore matcher, protobuf schema-less wire decode, FASTA/FASTQ, DNS name compression.

**⭐ DKIM canonicalization (RFC 6376) is DEAD as a §3 base — single-lever, NOT broad (2026-07-19, tbrain-dkim-deliver-probe platform return, [[batch-2026-07-19-verdict-port-pincer-dkim-only-survivor]]).** Earlier notes called dkimpy-conformance the "sole broad-HARD pincer survivor"; the platform overturned that. deliver-probe returned with the coverage flag: **20 strong runs (10 opus-4.8 + 10 gpt5) ALL landed 491/545 and ALL missed the IDENTICAL 54 cases** (0/20). A one-line agent-bug mutant (rstrip trailing WSP at a body end with **no terminating CRLF**) breaks **exactly** those 54 — so the whole residual difficulty is ONE boolean: relaxed *body* canon keeps trailing WSP-with-no-CRLF as a single compressed SP (`strip_trailing_whitespace`=`[\t ]+\r\n` strips WSP only *before* a CRLF), `hello   `→`hello \r\n`. Every other feature is solver-passable 20/20. Oracle = corpus = verbatim dkimpy port (545/545) → no oracle bug. This is the fair⊥hard single-lever fingerprint → **DROP, no remediation** (prune 54→best run 100%→EASY; disclose/cover-example→master law→EASY; SPEC already states the rule so 0/20 still miss it = knife-edge, no middle band; no orthogonal second lever — 20/20 pass all other DKIM features). All 8 series variants share a byte-identical corpus (md5 `feb96d12…`) → every sibling will return the same 54-case 0/N. My earlier local "488–491, varied clusters, broad" read was n≈2 variance mistaken for breadth; the 20-run platform convergence is authoritative. Retires DKIM alongside the version lane: the §3 lever needs an UNDER-documented reference AND a broad multi-rule tail — DKIM had neither.

**What collapses:** well-known formats/rules even with "edge cases" added — nginx-location, tar, bencode, msgpack, multipart, chunked HTTP, shell word-split, ical unfolding, css-specificity, iso8601-duration, poker/bowling/BLEU, RFC 6265 cookie (single contiguous algorithm = one-shot transcribable), Mustache (small rule set, no big table), **robots.txt RFC 9309** (Sonnet one-shots a correct independent port, 372/372 — hardening a memorized public library is futile), bibtex name-splitting (memorized; sole wall = one correlated hyphen quirk = 0/N flag with no fair fix).

**Selection rules:**
- Load-bearing rules must be **scattered/combinatorial across spec sections**, not one localized algorithm.
- Prefer an **unmemorizable, irregular table** (megabytes: UTS-46/UAX-14/UCA class data). Small clean rule sets collapse.
- **Stdlib-reachability trap is fatal:** if a Python stdlib one-liner reproduces the behavior (unicodedata normalize/casefold, json, csv, ipaddress, datetime, base64, urllib.parse), the solver differential-tests against it in-image. Use non-stdlib refs (hpack, CBOR, OpenPGP, collation, binary32 formatting).
- **Vendored-copy leak when removing a `packaging` authority (2026-07-12, wheel-tag-compat):** the pep440-style prune of `*/{pip,setuptools,pkg_resources}/_vendor/packaging` is INSUFFICIENT — the `wheel` package (present on `rust:1.85-slim`) ships `wheel/vendored/packaging/tags.py`, so `from wheel.vendored.packaging.tags import parse_tag` still works and leaks the compressed-tag expansion. Prune broadly: `find / -type d -name packaging \( -path '*/_vendor/*' -o -path '*/vendored/*' \) -prune -exec rm -rf {} +` AFTER `pip uninstall packaging`, then verify in-image that `import packaging` AND every `*.vendored.packaging.*` variant fail and `find / -type d -name packaging` is empty. pytest 8.4.1 still runs with packaging fully absent.
- **Real-impl-as-spec** works, but every disclosed "subtlety"/example MUST be oracle-verified per-case — one false hint (composer `1.0.0-beta` claim; jsonpatch "`/` = whole document", when RFC 6901 says `/` = empty-string key) creates an unfair correlated 0/N and a reviewer reject.
  - **Composer constraint satisfaction hardening (2026-07-13):** a narrow matrix (≈50 constraints × 39 versions) plus prose that spells out dev-branch/stability/pre-release comparator behavior grades too easy. Keep examples oracle-verified and hidden-corpus-disjoint; put conventions in examples, not in telegraphing prose. Update the official solution/parser against the same authority before shipping.
- **Offline library conformance must be self-contained.** If tests pin exact behavior from an unavailable implementation, "match library X" is not enough: either document the algorithm, tie-breaks, and edge cases in an agent-visible offline reference, or ship allowed offline source/reference (uri-template: bundle RFC 6570 Appendix A + encoding sets as `/app/RFC6570.md`). **0/N-coverage-flag remediation** ("some tests not passed by any agent"):
- **⭐ Suspect the ORACLE before you prune.** N independent strong agents each reconstruct the authority; when they all disagree with the oracle on the same cluster, the base rate says the oracle is wrong. Re-derive every expectation in the cluster by running the REAL authority (a live `node_modules/semver`, the actual jar, the upstream binary) and differential-fuzz the oracle against it over tens of thousands of generated inputs — the corpus is self-consistent with the oracle's bugs by construction, so `oracle == corpus` proves nothing; gate on `oracle == authority`. Pruning first just deletes the evidence: the semver-range family's two 0/N valid_range clusters (numeric-after-wildcard, build-metadata-on-partial) were BOTH oracle bugs, the prune cleared the flag, and a client reviewer returned the sibling task months later. Only once the oracle is proven conformant is a 0/N cluster evidence of a real blind spot, and only then do the moves below apply.
- Diagnose from the per-test pass table, not the summary. Classify each 0/N case: redundant group test → delete; monolithic/aggregate test → **parametrize per-case** (always prefer per-case over per-area aggregates — clears behavior_in_tests without seeding the flag); irreducible correlated blind-spot tail → **prune** the ≤5/10 cases keeping softer representatives of every feature cluster (ceiling = min kept pass-count; keep it ≤60% for HARD); spec ambiguity/convention → **disclose** in the instruction; over-concentration (46% of corpus = one trap) → delete the adversarial bulk of that one feature, keep it minimally covered.
- **LOWESS/statsmodels delta remediation (2026-07-15, tbrain-lowess-smooth):** a returned 0/N cluster can sit inside a broad real-implementation wall even when one SPEC sentence is misleading. **⭐ Disclose-vs-DROP decisive test (the 2026-07-07 batch).** A 0/N return on an all-or-nothing "match named lib" port is either fixable-by-disclosure or a DROP, decided by ONE question: *does a BROAD residual wall survive after you disclose the correlated blind spot?*

## 7. Probing & grading methodology

- **⭐ Gate pipeline (2026-07-18) — spend tokens at the cheap end of the funnel:** mine (fresh-only doctrine, §2) → **collapse-law screen** (name the hidden lever in one sentence — in-image library-quirk differential or undisclosed counter-intuitive rule; can't name one, or single-lever fair⊥hard fingerprint → reject at mining, cost 0) → **skeleton probe** (instruction + buildable env + stub + rough check command, N≥3, BEFORE building oracle/verifier/packaging; 3/3 pass → drop/redesign) → full build → **per-case pass-table pre-audit** (re-score stored probe diffs per-case, free: every case ≥1 passer, best union <100%, soft representative per cluster; suspect the ORACLE before pruning any 0-probe cluster) → submit. Mirrored into task-miner / task-clone / task-local-solve-probe / task-revise-flag-remediation skills. Old ordering (full build first, probe last) burned whole builds on 3/3-EASY candidates and produced the "0/N flag → remediate → EASY" loop.
- **Warm loop or the number is garbage:** the probe must give the agent a working build/run loop matching the platform toolchain (persistent container + `docker exec`). Blind-write, broken-mount, dropped-PATH (`bash -lc` loses go), or wrong-toolchain (host go1.22 vs pinned go1.24) probes produce FALSE 0/N. Verify the loop compiles before trusting any 0/3.
- **N≥5; pool same-engine runs.** n=3 is variance (a true ~20% family read 0/3 and 3/5 on identical engines). Never harden one port to chase a per-port number; extend n instead.
- **Local probes are over-generous vs platform:** local 1/3–2/3 routinely maps to platform TRIVIAL. Only a local 0/3 with semantic failures is a shippable HARD signal; local probes can confirm HARD, never MEDIUM. Exception: tie-direction-by-differential tasks read falsely trivial locally — trust the platform.
- **Run probes from the orchestrator** with fresh subagents (build agents are contaminated — they've seen the oracle and systematically leak the wall via comments/prose/Chekhov-gun fields; always leak-audit grep before probing). Solve dirs must be ISOLATED OUTSIDE the repo (agents escape into sibling `verify/` dirs) with a TERSE canonical prompt — hint-rich prompts inflate solve rate ~2–3× ("focus on edge cases" is the main inflator).
- **Score by differential, never self-report:** copy the solver's changed source into the real task + verifier and run pytest/harbor nop in Docker (absolute host paths; auto-detect the build root — solvers restructure layouts). Every failing solver in the port batches "built clean and reported byte-for-byte correct."
- **A 0/N is not proof of fairness:** verify a canonical-correct independent solver actually passes the verifier; when N agents converge on the same wrong answer, reproduce and check whether the reference (and the oracle, which may share its bug) is canonically correct.
- **Validate any base before porting:** gate on harbor oracle=1.0 AND nop=0.0 AND a blind probe that actually fails (found bases with stub==solution, non-compiling images, and 3/3 "hard" labels).
- **Infra death ≠ difficulty:** 0/N with `verifier_did_not_run`/0 tokens/"other" failures (Bedrock 503, OpenAI 429, geoblocking) is platform death — check oracle 3/3 and request a re-run; `n_errors=0` failures ARE valid semantic fails. Harbor LLM calls and stb agent runs are geoblocked from VN (403 region) — no VPN/remote access is available anymore; treat them as PERMANENTLY unreachable from this environment and never plan around regaining them. Difficulty/category preflight runs ONLY via local fresh-subagent probes + the rules-first category check (`task-miner/category_rules.md`). Background pipeline agents die silently mid-run: verify results on disk; never build in auto-cleaned worktrees with relative paths (deleted 2 of 4 builds).
- Keep local compute light: validate in Docker (harbor), not on the host; no 2^n brute force for n>18 locally.

## 8. Verifier & test design

- **State the OUTCOME, not the mechanism.** Detailed rules live in `/app/SPEC.md` (or an RFC-style file under `environment/app/`), instruction.md keeps goal + high-level names of every tested violation kind.
- **Binary reward 0/1, never proportional.** Clients flag the CTRF proportional-reward pattern as a verifier defect. Fix coverage honestly (per-case parametrize / prune / disclose) and use the standard pytest-exit-code block; oracle must then pass 100%.
- **Corpus curation (2026-07-18):** soft size cap ~≤100 curated cases for a normal task (300+ only for a genuinely broad wall that passed the pass-table pre-audit); per-case floor — a case predicted <~35% per-run pass is a 0/N candidate, disclose or drop at design time; **soft-representative rule** — every feature cluster keeps ≥1 case a majority of runs pass, never a hard-cases-only corpus, and trimming is always pass-table-driven (never "drop easy, keep hard" — easy cases are the coverage that keeps the 0/N flag from firing).
- **Build the candidate from `/app` source at verifier import time** — never `shutil.which()` or a pre-installed binary path (makes nop ungradeable, fragile to nonstandard build paths).
- **A build helper must check the build's EXIT STATUS, not just that the artifact exists.** `make clean` → assert the binary is gone → build → assert `returncode == 0` (stdout+stderr in the message) → assert the binary exists. Otherwise a warm `RUN make` in the Dockerfile leaves a stale binary and a non-compiling submission is graded green against it (reviewer-returned on quill-plugin-resolver). Drop the warm build step from the Dockerfile too; verify by injecting a compile error and confirming reward 0 with the non-zero build status surfaced.
- **Checker-owned compile + hide answer corpus (2026-07-16, tbrain-lowess-smooth):** if `tests/` ships expected-value corpora, never run a submitted Makefile/executable while the corpus remains readable. Load the corpus into memory, unlink `/tests/<corpus>` before compiling or running candidate code, and compile the submitted source with a checker-owned command (`cc ... /app/lowess.c -lm`) so a Makefile cannot generate a fixture-lookup binary.
  - **Hide `/solution` + reject escaping source, AND run pytest isolated from a verifier-owned dir (2026-07-16 r2, same task).** Three more compile/grade-time cheats a checker-owned compile alone does NOT stop, all reviewer-returned: ① a submitted `/app/lowess.c` that is just `#include "/solution/lowess.c"` (or a symlink `/app/lowess.c -> /solution/...`) compiles the complete oracle and passes every case without implementing anything → in the build fixture, **remove `/solution`** (the oracle's solve.sh has already copied its source into `/app` before the verifier runs, so deletion is safe) AND **scan the translation unit**, rejecting it if it is a symlink, resolves outside `/app`, or contains a `#include` whose target is absolute (`startswith('/')`), contains `..`, or names `solution`. ② An agent-planted `/app/sitecustomize.py` (or `usercustomize.py`) that calls `os._exit(0)` during interpreter startup makes `python3 -m pytest` exit 0 without running any test → `reward.txt` gets 1. Fix in `test.sh`: `RUN_DIR="$(mktemp -d)"; cd "$RUN_DIR"; python3 -I -m pytest …` — **isolated mode `-I`** (ignores `PYTHON*` env, user site, and — via `-P` on 3.11+ — the cwd on `sys.path`) run from a fresh verifier-owned dir keeps `/app` off `sys.path`, so `/app/sitecustomize.py` never imports. Verified: sitecustomize+stub → reward 0 (blocked), both include and symlink cheats → 0, oracle → 1, nop → 0. Note the build dir must still be created with `dir=/app` (exec-capable) not `/tmp` (platform mounts `/tmp` noexec); `RUN_DIR` under `/tmp` is only a cwd, nothing is exec'd from it, so noexec is fine there.
  - **Rubric must score final BEHAVIOR, not work-steps (same task).** Reviewer rejected criteria that awarded points for "reading files before implementation" and "running make successfully" — these are process steps, not LOWESS behavior. Replace with checks that the **final C source implements the model** and the **rebuilt executable follows the required command surface** (reads one JSON object on stdin, prints exactly one JSON array line). ⚠️ The reviewer's paraphrase of the rubric rows did NOT match `rubric.md` — the platform rubric field was out of sync with the in-repo `rubric.md` (which is NOT shipped, like SUBMISSION.md); hand the user the corrected full block to paste over the platform copy.
- **Hermetic fixtures:** build/compile into a fresh `tempfile.mkdtemp()` (own GOCACHE/GOPATH/classpath), never write into read-only `/app`.
- **Randomized differentials must not re-test pinned corners:** if >40% of generated cases hit a corner the curated suite already enforces, strip it from the generator (zero-param 66%→0%, count 8000→4000; injected bug still caught 53%).
- **Free-form explanation strings:** match structured fields exactly + assert key FACTS as order-independent substrings — exact string match creates a no-middle-band unfairness; count-only asserts (`len(findings)>0`) create false EASY.
- **Neutralize test/fixture labels and docstrings** ("latent defect", "second bug") — behavior_in_task_description FAILs on them; fix the labels, never describe the wall in the instruction.
- **⭐ An oracle/reference bug can be MASKED by the entry point that consumes it, so a black-box CLI-only suite never catches it (2026-07-15 transcript-sentence-split).** The reference `boundaries([])` returned `[true, true]` (SB1 + SB2 appended unconditionally) instead of the contract's `n+1 == 1` flag, but `render` only reads `flags[0]` for empty input, so the printed `÷` stayed correct and every output test passed — the defect was invisible. (Ironically the STUB, sized `Array.new(n+1, true)`, was correct while the SOLUTION was buggy.) Fix = (a) correct the reference (`return [true] if n.zero?` before appending SB2); (b) add a test that inspects the INTERNAL method's return value directly, not just the CLI string — shell into the interpreter to call the public method and assert its shape (`ruby -r./sbreak -e '…JSON.generate(TranscriptSplit.boundaries(cps))'`, assert `boundaries([]) == [true]` and `len == n+1` for several inputs). These contract tests pass on the stub too (preserved invariant), so nop stays failing on the real segmentation and the gate is unweakened. Whenever an algorithm's public output is produced by a formatter/renderer that can drop or reindex the raw result, test the raw result directly. Also: **de-telegraph the in-code stub "hint"** — reviewer "exclude the name of the algorithm from the hint" = strip the algorithm NAME from the scaffold comment the agent reads ("This is the algorithm under test: it must implement the Unicode default sentence-boundary rules" → neutral "This is the method to implement"), while KEEPING instruction.md's authoritative standard reference (a hidden-conformance task must still name its ground-truth spec to stay fair — removing it there would be under-specification, not de-telegraphing).
- **Editing `environment/repo` source (even comments) breaks `fix.patch`:** regenerate the patch against the edited base, confirm it carries none of the removed text, re-run oracle+nop.
- Two legit hardness-reduction patterns when the SPEC itself causes a 0%: location-string normalization in the comparison fn; honest coverage fixes. Never apply to dodge an intentional hidden convention.
- Guard every promised preservation clause with a test; give concrete observable acceptance bars, not algorithm names. Naming exact OUTPUT constants (reason codes, enum values) is fair and satisfies behavior_in_task — output constants aren't mechanism; never lump a should-be-ALLOW outcome in with suppression outcomes (spec coin-flip = unfair).

## 11. Harbor / platform troubleshooting

- **Invocation:** `harbor run -a oracle|nop -p <task-dir> -o <jobs-dir> --job-name <n> -q`; reward at `stats.evals.<key>.metrics[0].mean`; gate = oracle 1.0 AND nop 0.0. Build context IS `environment/` — no `environment/` prefix in COPY paths. Run stb from the jobs parent dir, models sequentially.
- **Docker validation without harbor:** `docker build -t task-test ./environment` then `docker run --rm -v $(pwd)/solution:/solution:ro -v $(pwd)/tests:/tests:ro task-test bash -c 'cd /app && patch -p1 < /solution/fix.patch && go build -o latmon ./cmd/latmon && mkdir -p /logs/verifier && cd /tests && bash test.sh && cat /logs/verifier/reward.txt'`. **⚠️ Must mount `solution/` and `tests/` as volumes — `.dockerignore` excludes them from the image.** For nop, omit the patch step. ⚠️ A verifier that UNLINKS files under `/tests` (corpus-hiding anti-cheat) errors every test under a `:ro` tests mount — false red; platform `/tests` is writable. Mount at `/tests-src:ro`, `cp -r` to a writable path inside the container, and run pytest on the copy (the hide-guard that checks the dir is exactly `/tests` simply skips, which is fine for grading).
- **"Oracle solution failed" root causes by language** (check ALL; multiple can coexist):
  - **Go (4):** ① git buildvcs on root-owned `/app/.git` → `git config --system safe.directory /app` + `-buildvcs=false`; ② no writable HOME breaks GOCACHE → private temp GOCACHE/GOPATH; ③ `go build -o` into read-only `/app` → build into the temp dir; ④ the `# syntax` line (above). Repro trap: use `chmod -R a+rwx`, never `chown` (false PASS), and test the source-only/read-only path (Go's identical-binary skip masks ③).
  - **C (3):** empty requirements.lock; fix.patch logic gaps; `subprocess.run(input=str)` needs bytes on Python 3.11.
  - **Java:** `javac -d classes` writing into `/app` → hermetic temp classpath; plus safe.directory, `-Xint`, `languages=["java"]`.
  - **Node/TS:** ts-node unavailable offline → pin ts-node/typescript, real package-lock.json, flatten the Node project to `environment/` top level.
  - **C graphviz precedent:** wrong include path, fixture violating its own policy, orphaned asserts — build+run the oracle against EVERY fixture.
- **"Oracle failed" on a byte-identical locally-green artifact** = stale platform image → fresh repackage + force-build; repeated staleness means content-hash caching — make a real difficulty-neutral content change (e.g. trim a verifier loop) to bust it.
- **Platform "Oracle failed" while local harbor+docker are 255/255 GREEN AND the verifier execs a staged/temp binary ⇒ suspect noexec `/tmp` FIRST (2026-07-15 tbrain-dns-message-decode r2).** The platform mounts `/tmp` **noexec** (standard hardening); any verifier that stages a binary under `tempfile.mkdtemp()` (defaults to `/tmp`) and then **execs** it — a chroot-jailed grading binary, an ASan/instrumented build, a compiled helper — dies with `PermissionError: [Errno 13]`/EACCES on exec → every test errors → oracle fails, invisibly, because the local runtime's `/tmp` is exec. **Repro exactly** with `docker run --tmpfs /tmp:noexec,nosuid,size=256m …` (fails) vs without the flag (passes). **Fix = stage temp/exec dirs on an exec-capable filesystem, never bare `/tmp`:** a `_find_exec_base()` that probes `[ /app, /var/tmp, /dev/shm, gettempdir() ]` by writing+running a tiny `#!/bin/sh` script and picking the first that returns 0 (workdir `/app` is exec by definition — it's where the tool builds/runs — so it heads the list), then pass `dir=EXEC_TMP_BASE` to every `mkdtemp`. Difficulty-neutral (jail-under-`/app` still contains only binary+libs, no `/tests`). **AUDIT EVERY QUEUED VERIFIER FOR THIS PROACTIVELY — the purl 6-language port series had it in 5 of 6 tasks (2026-07-18):** Rust/C/C++ built the graded binary into `mkdtemp()` and exec'd it; TS and Java staged a `#!/bin/sh` **wrapper script** in `/tmp` (`exec node …`/`exec java -cp …`) — same death, and the wrapper variant has a cleaner fix than the probe: **yield the argv prefix instead of a staged executable** (`["node", main_js]` / `["java", "-Xint", "-XX:+UseSerialGC", "-cp", classes, "Main"]`, `_run` does `subprocess.run(list(binary) + args)`) — interpreters READ code files fine from a noexec mount; only the exec bit is blocked, so compiled JS/classes can stay in `/tmp`. Ruby was safe (runs the script at `/app` in place). Validate every fix with the noexec tmpfs repro (oracle reward 1 AND nop reward 0 under `--tmpfs /tmp:noexec`).
- **A language with NO sanctioned base image ⇒ vendored-toolchain size fragility ⇒ PORT to Go/Rust/gcc (2026-07-13 paseto-v4-verify).** A Kotlin PASETO task that verified 115/115 green everywhere still failed "Oracle failed" on the platform; root cause was the **85 MB zip = ~36× the size of a normal task** — Kotlin has no canonical Terminal-Bench image, forcing a vendored ~60 MB compiler jar.
