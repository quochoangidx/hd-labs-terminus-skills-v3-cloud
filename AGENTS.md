## 1. TL;DR

- **Platform (portal sync 2026-09-23; Terminus 3 live, 2nd Edition concluded).** Four language-independent tiers averaged over both reference models: `frontier` <20%, `advanced` 20–<50%, `core` 50–<80%, `base` 80–<100%. Since 2026-09-15 at least 3 of 8 runs must fail (max 62.5% proceeds); `base` and a 75% `core` only for tasks grandfathered by the morning of 2026-09-11, revisions included. Difficulty is measured once, after quality-panel clearance and before human review, 4 runs/model, no post-acceptance rerun (`docs/understanding-tasks/difficulty-guidelines.md` wins on trial count). A separate blocking `difficult` expertise-floor check applies at every tier; `difficulty_explanation` says why the task is hard for a human expert, never a model pass rate.
- **Metadata.** Seven Title Case categories, all open (`Science`, `Software`, `ML`, `Operations`, `Security`, `Hardware`, `Media`), chosen domain-first, with exactly one matching subcategory; milestones are removed. Top-level `artifacts`; `[verifier].environment_mode = "separate"` with a digest-pinned `tests/Dockerfile`. `[environment].network_mode = "public"`; `[agent]` and `[verifier]` each explicitly `"public"` or `"no-network"`; with a Compose file all three are `"public"` (§10). Agent timeout 1800–18000 s. Obsolete: `codebase_size`, `number_of_milestones`, old `subcategories`, `allow_internet`, Easy/Medium/Hard, `junior_time_estimate_min`; historical HARD/MEDIUM/EASY labels are lane-scoped solver evidence only.
- **Docs audit (2026-09-11).** `check_modal_dockerfile_compat` needs digest-only external `COPY --from=` refs (stage aliases fine); named and numeric `COPY --chown=` both pass since 2026-09-17 (§10). `FROM` uses the exact published registry, tag and digest; never leave Node/Java digest placeholders. Hardware/CAD verifiers measure every stated dimension, sample finer than tolerance, test the built Oracle geometry, and recompute with a fresh parameter when parametric behavior is promised. Removed Terminus 2 portal pages must not stay in the local mirror.
- **Grading flow (2026-09-26).** (1) Quality panel + checks: a fail is revised. (2) Difficulty: CORE/ADVANCED/FRONTIER continues; a test no run passed returns as unsolvable; BASE means proposing a replacement task (user go-ahead needed), not hardening. (3) Human review. This repo's 25 returns up to 2026-09-26 landed 20 at the panel, 3 at the pre-panel `solvable` check and 2 at difficulty (one unsolvable test, one BASE), none at human review, so passing the panel first time is the largest lever. On a return read "Blocking stage" and "Pre-Difficulty Gate Failed" first and run every mandated step without asking (`task-revise-flag-remediation` *Grading flow*).
- **Epistemic contract (2026-08-13; wins over older notes).** Fairness is a clear goal plus enough agent-visible evidence to infer the graded model, not every rule in prose. Keep artifact paths, public interfaces/schemas, hard safety constraints and arbitrary exact conventions explicit; let the agent reconstruct causal relations, protocol semantics, geometry, scientific interpretation, state transitions and interacting constraints from distributed evidence. Hidden instances, combinations and metamorphic variants of the same inferable model are good; hidden oracle-only policies, unreachable authorities, undocumented exact strings, arbitrary constants and unobtainable facts are invalid. The V3 report keeps the name `instruction-sufficiency.json` but audits goal clarity, evidence inferability, hidden-generalization continuity and semantic equivalence.
- **Profiles.** A bare `task-batch N` runs `builder_certified` (§2). `campaign_ready` (explicit): retained-scope verifier and Oracle, V3 inferability, public-surface and causal-core map, a killed plausible partial-fix mutant per retained mechanism/interaction, strict Oracle=1/NOP=0/noexec, review and audit gates; one builder, fairness reviewer and persistent auditor; exactly two valid fresh blind solvers, where `0/2`/`1/2` qualifies, infra failures are replaced, `2/2` allows one fair strengthening and one re-probe, and a second `2/2` rejects. No count quota beyond a genuine interaction. `panel_ready` (explicit): builder, quality panel, Oracle/NOP/noexec, deterministic checks and minimal wrong-path/harness evidence; reports only `local_panel_cleared`, never a tier. Subagents use `gpt-5.6-sol` medium (Codex) or Opus 5 medium (Claude Code).
- **Accepted-task blueprint, reference only (user decision 2026-09-26).** Six accepted seeded-departure tasks define the shape (`terminus-regular-task-authoring/references/accepted-task-blueprint.md`); new tasks take only abstract lessons and reuse no domain setting, authority, departures, trap instances, data shapes or instruction/silence/rubric wording. All six are `accepted_reference` in `mined-candidates/index.jsonl`.
- **Design portfolio (user decision 2026-09-03).** Start from a domain-native failure mode, work surface and deliverable; patterns classify a finished design. The schema-v3 ledger records every qualified attempt, no budget; ~20–30% derived attempts is advisory; across the rolling five accepted tasks aim for 1–2 derived, no topology above 3/5, no exact role stack three times running (drift never invalidates a task). Derived candidates need a real `X-*` transformation on ≥2 structural axes. Validate with `task-batch/scripts/design_pattern_mix_check.py` before scaffolding and handover.
- **Collapse law, scoped.** In a warm loop solvers derive their own reference and differential-test it, so fully specified transcription, named algorithms, cascades and stated optimization collapse in conformance/spec-engine lanes. The prior does not screen evidence-reconstruction, native-artifact, live-state or multi-system tasks, and a discoverable hidden requirement is not rejected merely because no sentence states it. The historical levers (hidden reference §3, under-fuzzed shape §4, wrong plausible fix §5) are nearly exhausted for fresh tasks (§6). Probe honestly (§7): warm loop, two fresh solvers, N≥5 only for pooled calibration, terse prompt, score by differential, never trust self-report or setup failures.

## 2. Core principles (why tasks collapse or hold)

Full historical entries and evidence are in `docs/history/agents-section2-archive-2026-09-26.md`; new findings go into the matching theme here as a short rule, with long evidence in the relevant skill reference or the archive. Paths are under `.agent/skills/`; `task-authoring/` = `terminus-regular-task-authoring/`.

### Profiles & process

- **`builder_certified` is the default** (user decisions 2026-09-23/25/26; lean route, ~7–10 model sessions per task). One builder, one reviewer (`contract_review` blind to `tests/`/`solution/` at step 3, before any verifier, then `final_review`), skeleton probe (step 4a), deterministic closure, builder-run Sound Verifier sweep (step 5b), difficulty check (step 7), then a narrow pre-submission panel. No fairness reviewer, auditor or separate adversarial reviewer. Route: `task-batch/references/execution-profiles.md`.
- **Probe early, at a CORE+ bar.** Two fresh blind solvers run on the skeleton (model + Oracle, no verifier yet); step 7 rescores those diffs against the finished verifier and runs a fresh pair only if the agent-visible contract changed. At most one of two may succeed; never harden past it for a higher tier or reject at CORE. `2/2` allows one redesign/strengthening of the existing causal core and one fresh pair; a second `2/2` replaces the candidate. Read failures for cause: an uninferable convention or a rejected contract-valid solution is a defect, not difficulty. Use `probe.py prepare --exploratory`; report a local signal, never a tier (`task-local-solve-probe`).
- **Probe model.** `terminus-probe` is pinned to `claude-opus-5` (the platform's model); launch it without a `model` argument, record the exact model ID, and stop rather than fall back. Opus 5.5 or GPT-5.6 results never estimate a tier (`task-local-solve-probe` SKILL).
- **Probe contract hash skips Finder files:** `probe.py` now ignores `.DS_Store`/`._*` like the ledger and precheck hashers; before 2026-09-26 one appearing after `prepare` made a finished pair unrecordable. Still delete them before `prepare`.
- **Panel in creation mode (lean, 2026-09-26):** discovery spawns reviewers for `sound_verifier` and `correct_reference_solution` only; `coherent_contract`, `protected_ground_truth` and `deterministic_execution` are carried by receipts (`panel_gate.py` `source: "gate"`). Full five-axis panel only on user request or a contract shape new to the team. One consolidated remediation batch, then clearance only on axes whose judged files changed (`panel_gate.py clearance-axes`); a blocking clearance stops as `rescope_required`; a batch that narrowed a core obligation gets one fresh re-probe. Packaging needs a passing `panel_gate.py check` receipt on the zipped snapshot. After a platform return the panel runs targeted mode (two reviewers on the returned axis) (`task-revise-flag-remediation` *Verification under `builder_certified`*). Label is `builder_certified`, never `local_panel_cleared`, `candidate_ready` or a tier (`task-quality-panel-judgement`).
- **Roles and models.** Reviewers and panelists use `gpt-5.6-sol` medium (Codex) or Opus 5 medium (Claude Code); every role runs as a collaboration subagent; the Luna reviewer/auditor path is retired (2026-09-23). Builder and orchestrator independently adjudicate every reviewer finding (builder `accept`/`challenge`/`partial`, orchestrator `uphold`/`overrule`/`narrow`). Report only what a snapshot-bound receipt shows; a disputed gate becomes a `documented_exception` with its contract citation (`task-batch/references/single-reviewer-workflow.md`).
- **Builder context.** One persistent informed builder records a pattern-blind domain-crux card before reading the pattern catalog. Reviewers and solvers stay fresh; never leak builder reports or intended mechanisms to them.
- **Builder lifecycle and hooks.** Each builder turn is bound to one candidate and one stage; Stage B scaffolding needs a passing digest-pinned canonical source smoke. Repairs are recorded, never capped by count; hooks do not poll, so the orchestrator interrupts expired stages (`task-batch/references/builder-quota-hooks.md`).
- **Grading flow:** see §1; run every mandated revision step without asking (`task-revise-flag-remediation` *Grading flow*).
- **Accounting.** Record every model invocation, failed and retried ones included; obey user budgets. Rerunning checks, rebinding, reverting or repackaging is not a new semantic version. Hand over tasks incrementally, screening later candidates against accepted ones; an unchanged snapshot never reruns reviews or probes.
- **Cost order.** Stabilize Oracle and targeted witnesses before any full matrix; Harbor is post-shortlist unless the user asks.
- **Blind-solve packet isolation.** Solve copies hold only `instruction.md` and the environment (no `task.toml`, `tests/`, `solution/`, rubrics, reports, memory); inspect before launch; copy with `symlinks=True`. An exposed session is invalid but still counts.
- **Campaign-only receipts.** V3 `instruction-sufficiency.json` (`sufficiency_manifest_check.py --require-v3`) and `semantic-coverage.json` (`semantic_coverage_check.py --advanced-plus`, a killed partial-fix mutant per retained mechanism/interaction) gate counted `campaign_ready` probes; `builder_certified` and `panel_ready` neither demand nor waive them. Any task/verifier change stales counted probe evidence (`task-authoring/references/semantic-coverage-gate.md`).
- **Local vs platform.** Local runs are preliminary; the platform's single 8-run measurement decides. Shared local misses are coverage risk and trigger an Oracle/verifier/inferability audit; they never block a quality-complete `0/2`/`1/2`. Base and Core are honest outcomes: never prune cases, hide facts or tune fixtures to change a tier; never promote an exploratory, stale or setup-failed run.
- **Retired lanes (2026-09-23):** upstream PR and issue-to-regression mining are removed (reproduce-a-fix shapes collapse); their reusable content is in `contract-closure.md` §12–14. Language ports, reskins, same-corpus variants and twists on prior tasks are not submittable: every task needs a fresh setup, definition and data.
- **User naming/archetype preferences:** non-victim archetypes (estimation/aging/cost via a secondary observable) over victim/eviction-direction tasks; slugs `tbrain-<problem-slug>` by domain, no `-ledger` suffix or tool/repo filler.
- **Skeleton pair after a clean contract review, never beside it; replace fast (batch-8, 2026-09-27).** Four of five candidates lost a skeleton pair to wording the concurrent review then found ambiguous, and every strengthened candidate went 2/2 again; Opus 5 pairs flip between 0/2 and 2/2 on one sentence of trap wording. Allow exactly one strengthening after a 2/2 (it saved workers-comp and trace-metal); a second 2/2 replaces the candidate, and no further rewording loops (3PL billing: six pairs, still 2/2) (execution-profiles step 4a).

### Design & difficulty

- **Accepted shape (2026-09-26):** 200–450 LOC synthetic package, one numbered in-environment authority with ceilings and floors for every figure, a 300–600-word three-paragraph instruction (symptoms + universal-range clause; three-tier silence clause with the composition sentence; coverage envelope), 6–9 departures, one named test per rule and per trap, expectations sealed from `solution/model.py`, a shipped differential under its own uid. Canonical: `task-authoring/references/accepted-task-blueprint.md`.
- **Seeded departures are self-verifiable; restraint traps carry the tier.** Every platform run repaired every departure (solvers write a reference from the note and fuzz it), so departure count and rule surface are not the lever. Difficulty comes from a repair that has to stop: departures in functions that own an ugly-but-shipped silent sub-domain, already-correct code that looks imprecise under a stated rounding rule, silence stated as a rule with boundary categories, silent-case expectations taken from the shipped code (`contract-closure.md` §15).
- **One live trap lands at BASE** (local-magnitude, dropped 2026-09-27 at `base` on its first difficulty run after two panel rounds): the skeleton pair's only miss was the off-table silence trap, the reading filter and two-sensor pooling were never missed, and the post-repair re-probe went 2/2. Require at least two independent traps that some local runs miss before upload, and treat a 2/2 re-probe as a stop, not sampling noise (`workspace/dropped/_submissions-local-magnitude/README.md`).
- **Traps that held** sat inside an aggregate a departure forces the solver to rebuild, were a bare unlabelled subtype excluded only by a domain-word definition, kept one routing decision, and followed from a chain of definitions. Use several independent, signposted traps of mixed kind that no single instruction sentence disarms; precision and empty-case traps did not bite. GPT-5.6 falls for definition hops, Opus 5 for "apply the formula everywhere" edges (blueprint §4).
- **Traps that failed:** naming each silent case per parameter is a site inventory; abstract categories, decoy complements and compositional silence are neutralised by the default "implement each rule on its stated domain, keep old code elsewhere" policy; over-preservation shortcuts catch nobody; more ranged sites do not help. Keep the calibrated silence wording "add no exception, clamp or guard". A single cross-parameter trap is a fragile common miss.
- **0/8 screen before upload.** A trap every local run misses predicts a platform unsolvable return; screen it for a competing positive enumeration, no definitional chain, contrary expert instinct, an unnamed shared step, or the trap threaded through several tests. Answer a 0/8 by dropping the trap (make the case governed or "left entirely open"), never by disclosing it (blueprint §4.3; `task-revise-flag-remediation` *Restraint trap at 0/N*).
- **Solver-path screen (user decision 2026-09-25):** score `self_verification_resistance` in `task-miner` (1 rejects, 2 deprioritizes) and in the `contract_review` turn (1 stops before any verifier; 2 is advisory and the skeleton pair decides, user decision 2026-09-27). Never score ambiguity as difficulty; recalibrate after 10+ new probe outcomes (`task-miner/solver_path_screen.md`).
- **Skeleton probe before any verifier** (mandatory in `builder_certified`, step 4a): it catches self-verifiable designs cheaply. A precisely stated criterion, a protocol plus simulator, or hidden state that stays affine in a few unknowns is turned into an executable oracle and fuzzed; strengthen by changing the causal interaction, not by enlarging the same system.
- **Collapse law is lane-scoped.** Fully specified transcription, stated optimization and named algorithms often collapse in conformance/spec-engine lanes; reject a named algorithm only when recalling it completes the task. Evidence reconstruction, native artifacts, live state and multi-step operations are screened on their own inference shape.
- **No middle band on arbitrary conventions** (tiebreak direction, undocumented constants, rotation direction): hidden is unfair, stated is trivial; retire on sight. A decoy works only when the natural fix is itself wrong on a fixture. Closed-form cost walls need a non-searchable exact constant never leaked by a worked example.
- **Bounded design (user decision 2026-09-14):** one coherent primary outcome and a pre-scaffold scope ledger separating causal-core obligations, supplied plumbing and non-goals. Parsing, schema, serialization and malformed-input handling are not core by adjacency. No unit/mechanism/trap count quotas; claimed independent traps must touch different semantic nodes with distinguishable witnesses. Repairs default to no new promises. Assign each retained mechanism a plausible partial fix and witness before building (`task-authoring/references/bounded-task-design.md`).
- **Candidate ledger and patterns.** Schema-v3 ledger: domain-native failure mode, work surface, native artifact, why difficulty survives removing incidental schema; one dominant topology, optional orthogonal secondary and one P4/P6 amplifier; two disjoint natural-but-wrong repairs. Pattern count is not rank; reject label stacking one helper resolves. P1/P3/P5/P6 are the strongest foundations; duration, file count and environment friction are exposure multipliers, not patterns. Before the full verifier, pass an assertion-to-source audit and a canonical-image runtime smoke. Consecutive attempts differ on ≥2 structural axes; no third consecutive topology or role stack (`task-miner/frontier_task_design_patterns.md`).
- **Structural diversity (user decision 2026-09-03):** one hash-bound batch index with a six-axis portfolio matrix (work surface, interaction, input surface, oracle, verifier, failure mode) plus domain key; reject duplicate domain keys or architecture families and pairs matching >4/6.
- **Anti-retrieval:** classify overlap as `none`/`substrate_primitives`/`partial_topology`/`task_topology`/`exact_solution`; reject only a reachable task-specific repair topology, exact solution or callable oracle. Historical Hard-only priors rank exploration, never reject a CORE+ candidate.
- **Reference size and contract density are solvability risks** (an 823-line reference failed the time gate); reduce the surface, never just edit the hour estimate.
- **Best-known-target optimisation fails either way** (press-shop v3–v5, 2026-09-26): "cost at most the best plan found by hours of search" fails the pre-panel `solvable` check against a 5,400 s / 2-CPU budget, and loosened targets measure BASE 8/8. Build an optimisation task only when its target is provably reachable in the budget; task-batch 3's four such candidates were stopped unsubmitted and moved to `workspace/dropped/` (`task-miner` rejects the shape). Bakery-fleet v8/v9 (2026-09-27) failed the same check on identical bytes after passing it in v7; the repair sets each target to the dearest of three cold-start 40-min single-core reference runs and states that budget (probe 1/2 on Opus 5, `workspace/reports/tbrain-bakery-fleet-dispatch/rev5/`). Known gate misfit for artifact-only optimisation tasks: `visible-fixture-graded` and `independence_check` `model_in_tests` flag the verifier's sealed copy of the visible orders and checker, which is the problem statement, not a leak; a rule change needs user sign-off.
- **A general silence sentence names the value that loses its rule, not the input** (trace-metal, 2026-09-26): qualifiers written into each rule went 2/2 (one-hop), a term-level "gives no rule for a non-detect" read two ways (0/2 discarded as ambiguity), and value-level "gives no rule for the value it defines" held at 1/2. ### Contract

- **Contract closure** (`task-authoring/references/contract-closure.md`): one numbered in-env authority with a universal-rule clause and a silence clause; a coverage envelope naming hidden input families; an authority sentence behind every exact convention; restrictions listed with their legal exceptions; expectations derived without importing the package; a shipped-vs-repaired differential guarding silence; a `solve.sh` header mapping contract topics to changes. Prose mutation claims need receipts.
- **Answer the five axes at scaffold time** (user decision 2026-09-23): formula domains, a state table, global claim vs silence, model-vs-Oracle fuzz before tests, harness shape (including `chmod -R a+rX /app`), each witness run in a state where its violation shows, one or two alternative correct implementations (`task-authoring/references/scaffold-five-axis-checklist.md`).
- **Silence names categories, not sites:** `panel_precheck.py` requires `closure.silence.named_cases` with a witness per named case; a promised silent case the model cannot witness fails `test_instruction_alignment`.
- **Bound open numeric promises** instead of chasing the next boundary: state each field's native inclusive range ("includes its endpoints"), put a fixture on every endpoint, and replace every open numeric sentence at once. Before stating a range, compute worst-case per-entry error at its corners after every pipeline transform; pick a range both the natural and the stable method pass with margin (no floor only careful numerics survive). Unsafe extremes are bounded, not merely untested.
- **Exact thresholds on decimal inputs need a margin, not exact arithmetic.** A float reference cannot decide a value mathematically on a decimal limit (0.1 + 0.2 vs 0.3 flips ND/J); the panel returns it as a Correct Reference Major. Unless on-limit inclusivity is the task's core, state a margin in the authority ("never within 10^-5 of a limit") plus a magnitude bound that keeps float error far below it, check both at seal time, and put fixtures a power-of-two hair either side (trace-metal v9, `workspace/reports/tbrain-icpms-sop-data-reduction/revision-ledger.json`). The same holds for cancellation between stated ranges: a slope of 10^-12 beside an intercept near 10^6 put the float reference 140,000× outside tolerance (v11); bound the combination ("intercept at most 10^4 times the slope") after fuzzing the reference against `Fraction` at every range corner (`workspace/reports/tbrain-icpms-sop-data-reduction/revision-v11/`).
- **Drop what does not earn its place:** storage-encoding promises when only decoded content matters, black-box-unobservable promises (e.g. atomic replace), preservation over unbounded input families, arbitrary capacity (bound the envelope; if capacity is core, cross a plausible fixed-capacity boundary), incidental structure (state a minimum instead).
- **Instruction symmetry:** "repair X and Y" requires both to change, and every preservation property needs a discriminating check, so describe outcomes and list only enforced preservations. Optional "may reuse" prose cannot support required-hit assertions. Public fixtures use only documented canonical keys. Every verifier-read field traces to a visible requirement; an oracle-only field is a task bug.
- **Restrictions are enforced where they are visible:** `enforcement_level` is `compiled`/`both` for reflection, native code, subprocess, network or namespace rules, `source` only for file location; each needs `enforced_by` and `allowed_exceptions_disclosed`. A non-core restriction is cheapest unstated.
- **Prompt style:** flat outcome lists of ≤20 items are fine; no nested lists, heading trees, tables or long enumerations. `instruction_preflight.py` blocks grading-apparatus names (`/tests/`, `test_outputs`, `ctrf`, `rubric`, `reward`, `pytest`, `test.sh`, "hidden test"); counts and bare `verifier`/`oracle` are advisory.
- **Protect finished plumbing** (CLI wrapper, entry point) with a disclosed do-not-change sentence plus a digest pin rather than grading every field through it; pin a file by digest only when a visible sentence names its component.

### Verifier & harness

- **Model in `solution/`, never `tests/`:** the expectation model lives in `solution/model.py`, does not import the package, and seals its output into `tests/expected/` as readable JSON (the panel reviewer cannot read `.json.gz`); an end-to-end model in `tests/` is a human-review return (`independence_check.py` `model_in_tests`, blocking).

Structural branches get named tests; seeds vary only continuous values. A task that still keeps a candidate digest hashes every regular file it runs with, skipping `.git` and `__pycache__` (`verifier_static_checks.py --check seed`/`--check seeded_draw`, advisory).

Keep a `harness_bypass` wrong path (`scaffold-five-axis-checklist.md` §3).
- **Protected ground truth:** a shipped differential copy is owned by its own uid, mode 0700, run as that uid ("readable, not writable" is superseded); seal `/tests` and `/logs/verifier` 0700 in `tests/Dockerfile`; stage jobs in prefix-less `mkdtemp()` so no case label reaches the candidate; never grade a byte copy of a visible sample; goldens never derive from `/app` or agent trees. A test proves the sandbox uid cannot read `/tests`, expectations, the shipped copy or `/logs/verifier`.
- **Privilege separation is independently blocking:** demote every candidate build/runtime process (`setpriv --no-new-privs`, own session, small env, `python3 -I -S`) with candidate-owned scratch; static review fails when demotion is absent. Test a 0750 helper lock the way candidate code would start it (`unprivileged([ENV, helper, TRUE])` plus an `env true` control), not through setpriv.
- **Trusted channels:** the root verifier builds inputs and interprets outputs; the demoted adapter gets opaque stdin, and never sees ground-truth labels. Never multiplex candidate stdout with a trusted result channel.
- **Run the documented invocation** (`python -m pkg`) from the candidate's `/app` copy, not the function behind it (`--check alignment`). A direct-call adapter calls documented functions by name and positionally, checks the documented return type, and proves snapshot independence.
- **Staging:** stage the complete declared `/app` tree; preserve internal symlinks and exec bits; skip unrelated entries without dereferencing rather than failing the run (`--check staging`); reject escapes, cycles and special files only where they matter. Vary dataset, output and working-directory paths independently.
- **One named test per rule:** CTRF drops parametrize IDs, so parametrized cases collapse to one row; name the rule in the test function. Validate exact CTRF IDs/counts (`results.summary`). Size the suite from obligations, boundaries and interactions; the old unit/cluster quotas are retired.
- **Isolating witnesses:** every named rule needs a fixture whose result changes when that rule alone is inverted; a mechanism whose rows share one outcome is untested. Every documented mode runs on a discriminating hard instance. Score one mutant per branch; a case where both branches agree is not a witness. Pick boundary witnesses no other guard masks.
- **Boundaries and partitions:** hit every `<`/`<=` at equality (on a float path only with binary-exact values the contract restricts to, else a stated margin; see *Exact thresholds on decimal inputs*) and the accepting side of strict bounds; hit lower as well as upper range endpoints; carry `0` through producer and consumer for nonnegative domains and assert nonnegativity strictly; partition derived scalars across legal signs; exercise the first event after initialization; carry per-generation mechanisms one step past their first repeat; drive formulas in both directions and at every width; use non-default configuration values.
- **State machines:** compare complete results and snapshots (including before any input and after each failure, discard and retirement), compare JSON type-strictly (`True == 1`), follow a failing call at an expiry tick with a full-state check, and hit every replay rule on each selection branch.
- **Representative structure:** for a retained grouped/anchored model vary identity, cardinality, ordering, duplicates and gauge when each changes a plausible implementation; generated bundles exceed any fixed-scenario count. Subtract integer timestamp origins before converting to float.
- **Native artifacts:** grade the artifact and its consumer as one objective (reparse the emitted file and prove it is what the optimizer used); accept standard comments, arbitrary record order, interleaved rows and semantic aggregation; never impose the Oracle's layout or row cardinality. Order, multiplicity and key collision are separate obligations: prove equivalence with accepted reorderings and preservation with one rejected lossy mutant per key-collision class.
- **Semantic equivalence:** accept the full safe equivalence class instead of the Oracle's internal representation; require only evidence the contract obliges, and test that extra irrelevant citations are rejected when used-evidence is promised. Match the spec's character class, not the language default. Promised optimizations need a structural witness, not only numeric equivalence. Exact comparison only for pinned exact output; tolerances match the written band.
- **Reference soundness:** trace reference behavior independently of tests; its ordering must match visible order (an emulator never charges a sentinel its halt hook prevents) and applicable checks accumulate without short-circuiting; run a stress input through the reference CLI at the range corners before any panel; judge convergence relative to cost scale, not an absolute gradient bound (`--check gradient`).
- **Determinism:** run the smallest canonical-image witness before reviewer pass 1; reject unexplained container divergence rather than tuning seeds or sleeps. Never test a restarting engine with a one-shot generator; use a re-iterable without `__len__` and a hard timeout. `preflight.sh --determinism` requires reward 1 on every run.
- **Timeouts and bash restore:** use the published phase timeout, never an undisclosed per-case cutoff. Resolve and deduplicate `/bin/bash`/`/usr/bin/bash` before recording modes, restore each once in `try/finally`.
- **A construction rule needs enforcement the text states.** A behavioural comparison cannot see delegation (an `execv` to GNU ed scored 1). An in-process audit-hook launcher must build its hook in a closure and replace `_posixsubprocess.fork_exec`; say "no native code (through `ctypes`, for example)" in the restriction. An audit hook alone misses a direct `_posixsubprocess.fork_exec` call (sed rev7 scored an embedded-binary wrong path at reward 1); where no child process is legitimate, also start the demoted candidate under `prlimit --nproc=1:1` before `setpriv`, which refuses any fork (at 2 one fork succeeds). Where a Python worker process is legitimate, enforce through the image instead (root-only verifier venv, no pip, `o-rwx` on other executables). Give every such check a witness that passes a legal delivery (set `PYTHONDONTWRITEBYTECODE=1`, skip `__pycache__`).
- **The panel reads about 60 KB per file and 150 KB per packet, and cannot open `.gz`;** unread cases return as coverage findings (`panel_precheck.py` `panel_unread_budget`). One case per line, a file per family, a roster checked at collection; sealed expectations in plain text. The budget covers the whole packet (instruction, `environment/` and `tests/`), not `tests/` alone: icpms v12 reached about 154 KB with `tests/` at 135 KB (under the precheck's limit), and the reviewer never read the two alphabetically last case files, then flagged coverage they held. - **Every case inside the stated input domain, every key field across its declared type** (COBOL `PIC X(8)` accounts with letters and spaces, plus near-misses), and parse candidate output the way the contract reads it, with no undisclosed size cap (press-shop v1).
- **Generated ids never share a stem:** ids like `R507-6` and `R507-17` were read by three panel reviewers as duplicates of `R507` against a distinct-id rule (v11 Coherent Contract Majors, no real duplicate). Number runs with one opaque id each (`L2607`).
- **Range edges include derived extremes:** besides each stated endpoint, fixture the extremes the ranges imply together (largest amount = largest reading × largest dilution, the minimum count of distinct levels, the smallest legal slope, each run kind's own copy of a shared range); caps, floors and guards at these points slipped five panel mutants in one return (trace-metal v9, sweep mutants p1–p8). Close every open end first: an "above nought" or an "at least" with no ceiling cannot be reached, so the next round invents a floor or cap below or above every fixture (trace-metal v10: seven more). Declare every range in a `ranges.json` and run `fixture_bounds_check.py` (task-authoring scripts; example under `workspace/reports/tbrain-icpms-sop-data-reduction/bounds/`) at step 5b; fix every `GAP` in one batch. Declare absolute extremes as well as ratios: a quantity bounded relative to another range reaches the product of that range's ends (icpms v13: only true/(10·loq) was declared, the smallest true concentration 0.001 was never graded, and a `max(1, true)` denominator guard passed).
- **Float comparisons at a contract discontinuity are a platform Major even when no fixture sits on them** (local-magnitude v9: the reference dropped a reading at 0.3 vs 3 × 0.1 and counted a station at 600 km + 1e-12; a local reviewer had raised it as Advisory and it was rejected). Close it with a section-1 margin that keeps every legal input clear of each threshold and inclusive end, so binary and exact arithmetic agree, check the margin at load, and never grade the tie itself. A single numeric tolerance cannot be graded exactly against stored expectations: rounding opened a false-reject sliver (v9 finding 4) and the 1e-9 allowance that closed it opened a false-accept one (v10 finding 2). State an accept bound and a reject bound in the instruction (within 1e-6 passes, more than 2e-6 fails), grade at the midpoint, and keep stored values far inside the gap (`workspace/reports/tbrain-local-magnitude-network-reduction/revision-v10/`).
- **Carrier-isolated trap classes need one file that combines them.** Keeping each trap input in its own file hid an off-table branch without the reading filter (local-magnitude v10 finding 1, reward 1); add a combined fixture with its own test and sweep every pairwise branch interaction (filter × off-table, filter × pooling, pooling × off-table).
- **Four Sound Verifier classes from one return** (noise-dose v11, four Major and two Minor, all reproduced at reward 1): at a list's length limit, put the only qualifying element last, because an impulse at index 1 let `peaks[:100]` pass. Give a flag-free aggregate a flagged member whose own figure lands in a lower band. A superset key check must still reject keys the authority forbids, such as a group's ceiling or impulse flag. Tolerances must be tighter than any rounding the authority forbids: with a 1e-6 tolerance, `round(dose, 6)` passed. Evidence: `workspace/reports/tbrain-occupational-noise-dose-survey/revision-v11/`.
- **A field the contract leaves unbounded still needs its extremes graded** (noise-dose v13, Major): every graded survey name was 8 or 14 characters long, so a `len(name) > 32` guard scored reward 1. Grade every free string field (names, titles, labels) at an empty value, a very long value, and values with non-ASCII characters, quotes, backslashes and edge spaces. Drive them through a relabelled pass rather than new sealed families (`revision-v13/sweep`).
- **Seal the directories around a verifier-owned driver, not just its bytes** (noise-dose v12 f2, Minor, reproduced at reward 1). With `/app/tools` delivered at 0777, candidate code swapped the driver between reductions and restored it on the last one, so the before-and-after byte checks both passed. After installing the driver and before any candidate code runs, `lchown` all of `/app` to root and strip group and other write, then assert the modes in the driver test (`revision-v12/f2/driver_swap_probe.sh`).
- **A static sealed corpus admits a name-keyed lookup table** (noise-dose v11 f6, Minor). Without putting a model in `tests/`, reduce one family again under run-time labels that leave every figure unchanged (new name and ids, shuffled rows, runs split at their level), derive the expected report mechanically, and print the seed on failure.

## 3. Historical Terminus 2 calibration — conformance/reference lane

These are lane-scoped priors, not universal Terminus 3 rejection rules.

- **Under-documented authority plus a broad tail was the only durable conformance wall.** A candidate needs behavior that materially exceeds clean public documentation and spans several independent semantic mechanisms. A famous or fully documented standard, man page, RFC, public pseudocode, or named library is usually reconstructable.
- **Run a Step-0 divergence gate before building.** Compare the real authority with an independent faithful implementation over a large corner-biased sample. Near-total agreement means the public contract already determines the behavior; a tiny residual usually indicates a single implementation quirk, not a broad task.
- **Single-lever residuals are not Frontier evidence.** If many failures collapse to one boolean, convention, or corner, disclose it and the task becomes transcription; hide it and the task becomes unfair. Do not confuse many affected fixtures with multiple mechanisms.
- **Independent authority and Oracle checks matter.** A ported corpus, shared helper, or shared implementation lineage can reproduce the same bug. Cross-check with a genuinely independent source and audit every verifier assertion against task-visible evidence.
- **Offline reachability is part of fairness.** If the authoritative tool or documentation is unavailable in the agent image, every non-inferable graded convention must be supplied locally. Claims about ungraded behavior must be removed or backed by discriminating tests.
- **Public input symmetry is mandatory.** Tests may use only documented public keys, values, encodings, and schemas. Compatibility aliases and internal constructor names pin an implementation shape and can manufacture correlated misses.
- **Documented-tool familiarity is broader than expected.** Inner details of build systems, pattern languages, policy engines, version resolvers, and protocol canonicalizers may be recalled or reconstructed even when the tool is old or obscure. Screen the documentation surface, not the tool's popularity.
- **Category is domain-first.** Historical classifier reactions to exact-reference wording are calibration only; do not distort a current Terminus 3 task to evade an obsolete classifier.

## 4. Historical Terminus 2 calibration — interval/state ledgers

- **Under-fuzzed shape was a lottery, not a reliable design strategy.** Interval ledgers, duty cycles, and state-transition boundaries sometimes survived because solvers missed one representation or ordering corner, but ports and reskins are not novel submissions.
- **State representation must preserve the domain's natural invariants.** Use half-open intervals when possible, define simultaneous-event ordering explicitly when arbitrary, and test zero-length, touching, nested, repeated, and boundary-aligned cases.
- **Exact constants and tie-breaks need visible authority.** If a score, threshold, rotation direction, or priority rule is arbitrary, hiding it is unfair and stating it often trivializes the task. Prefer inferable causal structure over secret constants.
- **Real-valued estimation can remain difficult where clean rule engines collapse.** The load-bearing component should involve evidence-supported estimation, calibration, aging, or noisy cohort inference; clean logic may support it but should not be the only wall.
- **Interaction count is not semantic rank.** Several rules routed through one central helper or one recovered mapping still form one mechanism. Count independent causal decisions and their interactions, then verify them with disjoint partial-fix mutants.

## 5. Historical Terminus 2 calibration — decoys and verifier simulation

- **A decoy works only when the plausible natural fix is itself wrong.** Merely hiding the real helper, leaving a stub, or adding an unused field does not create difficulty if a careful default implementation satisfies the contract.
- **Avoid disclosure traps.** Enum names, adjacent comments, TODO lists, fixture labels, worked examples, and field groupings can reveal the intended mechanism. Keep the public goal and evidence complete while making scaffolding neutral.
- **Verifier-side simulation needs a canonical, stable target.** Hidden simulation parameters are unfair; fully disclosed simulators are often reproducible. Useful cases require evidence-supported dynamics whose observable outcome is stable across valid implementations.
- **Test perturbation robustness for dynamical systems.** Agreement between two implementations is insufficient when both track the same fragile trajectory. The graded outcome must survive physically negligible input perturbations; scattered basin flips indicate chaos and an unfair oracle.
- **Event-driven dynamics are not automatically fair or hard.** Closed-form inter-event motion improves canonicality, but dispersing or long-tumble systems can remain chaotic. Prefer convergent, dissipative outcomes with well-separated final states.
- **Named textbook algorithms often collapse novel-looking tasks.** Canonical multi-regime geometry or scientific computation is still easy when recalling the named object determines the complete solution. Domain interpretation and interacting evidence must remain after algorithm recall.
- **Run Docker-first determinism checks.** Concurrency, RNG, scheduling, futures, and background work must pass the full Oracle matrix in the exact isolated/noexec environment before semantic manifests or probes.

## 6. Historical saturation evidence — reusable screening rules

> Apply these only to matching shapes. Current Terminus 3 accepts honest Base, Core, Advanced, and Frontier tasks.

- **Fully stated decision engines usually collapse.** More rules, recursion depth, optimization states, or cascades do not reliably create difficulty when the entire contract can be transcribed and self-tested.
- **Well-known standards and published adjudicators are usually reconstructable.** The residual tail often becomes either a contested convention or one narrow quirk. Reject only the matching conformance shape, not the broader domain.
- **Contested authorities are unsuitable hidden ground truth.** If serious implementations disagree on hard cases, either specify the chosen convention or redesign around an uncontested observable.
- **Canonical operational repair is discoverable by iteration.** Multi-service restoration and standard database migration can remain easy despite causal unmasking because logs and established recipes lead solvers through the fix.
- **Pure interaction breadth does not guarantee difficulty.** Long context, several services, or multiple disclosed rule families can still reduce to mechanical joins or a canonical procedure.
- **Continuous chaotic simulation has no fair-and-hard window when discrete outcomes depend on integrator choices.** Tame cases are easy; chaotic cases are oracle-sensitive. Require method-independent outcomes and perturbation robustness.
- **Optimization is not a reliable wall by itself.** Strong solvers derive dynamic programs or brute-force small domains and self-check the optimum. Difficulty must come from domain reconstruction or interacting constraints, not merely objective complexity.
- **Measure before declaring a family dead.** Platform returns or pooled probes support strong priors; a local sample of one instance supports only a suspect prior. A materially stronger, structurally different control may retest a suspect seam, but never a reskin.
- **Preserve lower-tier and rejected evidence honestly.** Do not prune easy cases, hide facts, or add hints to manufacture a target tier. Generalize the lesson here; keep task-specific logs, hashes, scores, and artifacts outside this shared file.

## 7. Probing & grading methodology

- **Probe hygiene.** Name the single task image as the only execution environment; forbid host tools, other images, listing the shared scratchpad and running `git` (sibling file names and a `git diff --stat` leaked in batch 6).
- **⭐ Profiled gate pipeline (updated 2026-09-15):** choose and record one profile before Stage A. `campaign_ready` mines a bounded scope, builds only retained obligations, passes strict Oracle=1/NOP=0/noexec/isolation plus V3 and mutation evidence, completes its fairness/auditor roles while scope stays coherent, then obtains exactly two valid fresh blind-solver results; `0/2` or `1/2` enters the CORE+ shortlist and `2/2` gets one fair strengthening/re-probe before rejection. `panel_ready` instead runs bounded design, design-only connectedness precheck, deterministic structure/isolation, Oracle/NOP/noexec, full snapshot-bound precheck, one eight-reviewer discovery panel, at most one consolidated repair and one fresh clearance; it omits campaign roles/probes/full mutation receipts while retaining minimal precheck wrong-path evidence, and outputs only `local_panel_cleared`. Fixture count adds no causal depth, and any semantic post-probe change invalidates campaign difficulty evidence.

Record the run as unverified, preserve the logs, and retry only when the infrastructure is healthy. Local fresh probes and current `stb` model runs must use real provenance; neither may be replaced by a handwritten surrogate.
- Keep local compute light: validate in Docker (harbor), not on the host; no 2^n brute force for n>18 locally.

## 8. Verifier & test design

- **State the OUTCOME, not the mechanism.** Detailed rules live in `/app/SPEC.md` (or an RFC-style file under `environment/app/`), instruction.md keeps goal + high-level names of every tested violation kind.
- **Binary reward 0/1, never proportional.** Clients flag the CTRF proportional-reward pattern as a verifier defect. Fix coverage honestly (per-case parametrize / prune / disclose) and use the standard pytest-exit-code block; oracle must then pass 100%.
- **Corpus curation (V3 correction, 2026-08-13):** soft size cap ~≤100 curated cases for a normal conformance corpus (300+ only for a genuinely broad wall with per-case evidence). A predicted low-pass case is a 0/N risk, not an automatic disclose/drop instruction: audit oracle/verifier, explicit interface, evidence inferability, and CTRF resolution first. Keep hidden instances/combinations that exercise the same inferable model; remove only invalid, redundant, flaky, over-strict, or oracle-only assertions. Never trim easy cases to manufacture a higher tier.
- **Build the candidate from `/app` source at verifier import time** — never `shutil.which()` or a pre-installed binary path (makes nop ungradeable, fragile to nonstandard build paths).
- **Use the project's own build system, never hardcode compiler invocations in the verifier.** A `build_binary` fixture that calls `g++ src/main.cpp src/engine.cpp` instead of `make` (or `cargo build`, `go build ./...`, etc.) ignores agent-added source files and Makefile updates, failing the agent unfairly. Always invoke the project's build tool so agents can modularize freely.
- **A build helper must check the build's EXIT STATUS, not just that the artifact exists.** `make clean` → assert the binary is gone → build → assert `returncode == 0` (stdout+stderr in the message) → assert the binary exists. Otherwise a warm Docker build can leave a stale binary and grade non-compiling source as green. Drop warm artifact builds and inject a compile error to confirm reward 0 with the build failure surfaced.
- **Checker-owned compile and hidden answer corpora:** if `tests/` ships expected-value corpora, never run submitted build logic while the corpus remains readable. Load the corpus into memory, unlink it before compiling or running candidate code, and use a verifier-owned build command when the public interface permits it so submitted build logic cannot generate a fixture lookup.
  - **Hide `/solution`, reject escaping source, and isolate pytest.** Remove `/solution` before grading; reject source symlinks or includes that escape `/app` or name the solution. Run pytest from a verifier-owned directory with `PYTHONSAFEPATH=1 python3 -P -m pytest` or `python3 -I -m pytest` so agent-planted startup files or `pytest.py` cannot bypass collection. Put executable build outputs on an exec-capable filesystem, not a noexec `/tmp`.
  - **Rubrics score final behavior, not work steps.** Do not award points for reading files, running a build, or following a particular process. Score the implemented model and required observable command surface. Keep the platform rubric synchronized with the canonical submission packet.
- **⭐ A staged rebuild pins its invocation surface (2026-09-25, `tbrain-variable-font-diacritic-interpolation`):** after a panel return for artifact-only grading, the verifier rebuilt the font from staged copies of the editable sources (plus perturbed source variants) by calling `python -m <pkg>.build --output PATH` from a staging directory. That silently required three things the agent-visible contract never stated: the `--output` flag survives a rewrite, sources resolve relative to the package rather than a fixed `/app` path, and the output directory holds only the deliverable. Document every flag, cwd/path assumption, and output-directory exclusivity the rebuild relies on in the README or instruction. Select perturbed source records by stable id, never list index, because a schema-legal reorder moves the perturbation. The second panel return on the same task added two more rules. First, every invocation form the docs promise must itself be graded: the task documented a no-argument default and an `--output` override, but every graded build passed `--output`, so a CLI that made the flag required survived. Run at least one staged build exactly as documented, with no arguments, and read its default output path. Second, builder-causality perturbations must cover every consumed source field, and covering each family once is not enough. The second return caught an unperturbed `gravecomb`. The third return (2026-09-26) caught the `light_wide` `n` anchor and the `light_wide` `o` advance: every family had one perturbed record, but a builder that copied any other single visible value still passed. Sampling fields one at a time loses to a panel that looks for the next unsampled one. The durable fix is one staged whole-source variant. It moves every consumed field of every source record by a small nonzero offset keyed by record, field and original value, so rotation or reordering cannot shift the offset. The test then asserts the compiled artifact at every source, plus one interior mixture, against that offset model. Offsets that differ per record also catch copied constants shared across records. Third, fixed metadata such as the name table must be checked as a **closed inventory**. The set of record IDs and platforms must equal the supplied set, together with any IDs that fvar/STAT legitimately reference. Checking selected keys let an added nameID 7 trademark record pass. Fourth, a stated container flavor is itself a graded promise. The README said "TrueType-flavored", and the tests required `glyf` but never the `0x00010000` sfnt signature, so an `OTTO`-labelled font with TrueType tables passed (return 4, Minor). Assert the declared format signature directly on the artifact bytes. A graded build that fails must still reach pytest (a missing-font fixture failure), not exit early, so the wrong-path runner sees a CTRF witness.
- **Hermetic fixtures:** build/compile into a fresh `tempfile.mkdtemp()` (own GOCACHE/GOPATH/classpath), never write into read-only `/app`. **Keep a compiled candidate's yard off `/tmp` (2026-09-23, `tbrain-chromatographic-peak-suitability`):** the binary built there cannot run when `/tmp` is mounted noexec, so preflight's noexec Oracle run scores 0. Build into a root-made directory such as `/var/lib/<pkg>-yard` with `GOTMPDIR` inside it; plain scratch working directories may stay on `/tmp`.
- **Randomized differentials must not re-test pinned corners:** if >40% of generated cases hit a corner the curated suite already enforces, strip it from the generator (zero-param 66%→0%, count 8000→4000; injected bug still caught 53%).
- **Free-form explanation strings:** match structured fields exactly + assert key FACTS as order-independent substrings — exact string match creates a no-middle-band unfairness; count-only asserts (`len(findings)>0`) create false EASY.
- **Neutralize test/fixture labels and docstrings** ("latent defect", "second bug") — behavior_in_task_description FAILs on them; fix the labels, never describe the wall in the instruction.
- **⭐ Entry points can mask oracle/reference bugs.** A formatter may drop, truncate, or reindex a malformed internal result while keeping black-box CLI output correct. Test public intermediate methods and structural invariants directly, including empty inputs and output length, while preserving NOP failure on the actual missing behavior. Neutralize scaffold comments that reveal the algorithm, but keep the authoritative task-visible evidence required for fairness.
- **Editing `environment/repo` source (even comments) breaks `fix.patch`:** regenerate the patch against the edited base, confirm it carries none of the removed text, re-run oracle+nop.
- **Starter comments are agent-visible difficulty surface:** do not leave `NOTE`/TODO blocks that enumerate the exact incomplete components or missing mechanism families. Keep behavioral requirements in the public contract; let the agent locate work from neutral code and failing behavior. After scrubbing comments, regenerate `solution/fix.patch` from the clean base and confirm the patch does not reintroduce them.
- **Editing `environment/repo` source (even comments) breaks `fix.patch`:** regenerate the patch against the edited base, confirm it carries none of the removed text, re-run oracle+nop. **Editing environment files consumed at Docker-build time (SQL seed data, config files, static fixtures) does NOT break `fix.patch`** — only changes to files under the git-tracked source directory that the patch targets require patch regeneration. Always re-run oracle+nop after any environment change regardless.
- **⭐ A seeded departure must be wrong on its own (2026-09-23, `tbrain-chromatographic-peak-suitability`):** the rectangle-for-trapezoid area departure was accepted (reward 1) when reverted alone, because once the repaired baseline passes through a peak's ends both end heights are nought and rectangles equal trapezoids. It was only wrong in combination with the shipped flat baseline. Revert every departure alone through `wrong_path_runner.py` before trusting a departure count, and re-seed any departure whose revert survives so that it survives the other repairs (here, heights measured over the start value inline).
- **⭐ Go floating point is not the same on arm64 and amd64 (2026-09-23, `tbrain-chromatographic-peak-suitability`):** the Go compiler fuses `x*y + z` into one FMA rounding on arm64 but not on amd64 (GOAMD64=v1), so a Go build on an Apple machine and on the platform can differ in the last bit of a time or an interpolation. A Python model matched the amd64 build byte for byte over 1,199 fuzz jobs, while arm64 differed in 1–3 jobs per 150. `int()` of an infinity also differs by architecture. Compare computed numbers at the written precision (one unit in the last written place), use dyadic values at every edge that decides a discrete outcome, grade no int conversion of a non-finite value, and check the Oracle under `DOCKER_DEFAULT_PLATFORM=linux/amd64` before trusting a local arm64 result. The note should say a fused product-plus-term may land either way.
- Two legit hardness-reduction patterns when the SPEC itself causes a 0%: location-string normalization in the comparison fn; honest coverage fixes. Never apply to dodge an intentional hidden convention.
- **⭐ RTL tasks: "it synthesizes" enforces nothing about RTL hygiene (2026-09-23, `tbrain-link-replay-transmitter`):** Yosys 0.23 (Debian bookworm) `read_verilog -sv; synth -top <top>` exits 0 on a module that reads a testbench signal by hierarchical name (it only warns that the name is implicitly declared), carries `#` delays, or calls `$display`/`$fopen`. A candidate module runs inside the same simulator process as the hidden testbench, so a hierarchical read of bench state, or a `$fopen` onto the bench's log, is a reward-hacking path. Back every build rule with a source lint (strip comments and strings, then reject `$name` other than the allowed functions and any dotted `a.b` name) in addition to the Yosys run, and demote the compile and simulation with `/tests` sealed so an `` `include `` cannot reach verifier files. A second lesson from the same build: a go-back-N resend defect whose bad copy the far end drops (a start chosen one edge late, a released resend whose beats were overwritten) passes every delivery-only check. Grade the spec's per-cycle rules at the ports, not only what the far end keeps.
- Guard every promised preservation clause with a test; give concrete observable acceptance bars, not algorithm names. Naming exact OUTPUT constants (reason codes, enum values) is fair and satisfies behavior_in_task — output constants aren't mechanism; never lump a should-be-ALLOW outcome in with suppression outcomes (spec coin-flip = unfair).

- **⚙️ Canonical scaffolding and fail-closed handover (Terminus 3):** new tasks live at `workspace/tasks/<slug>/`; returned tasks live at `workspace/revision/<task_id>/<slug>/`; upload artifacts live at `workspace/submissions/`. `scripts/new-task.sh <slug> <lang> <category> <subcategory>` owns the initial `task.toml`, `.dockerignore`, `tests/Dockerfile`, and `tests/test.sh`; `scripts/preflight.sh <task-dir> --strict --report-json workspace/reports/<slug>/preflight.json --evidence-dir workspace/reports/<slug>/preflight-logs --emit-zip workspace/submissions/<slug>.zip` must build both containers, validate declared-artifact transfer, and retain hash-bound build/solve/verifier/CTRF/reward evidence. `scripts/batch-handover.py` is the sole `candidate_ready` authority: it rejects a stale task/ZIP/submission, missing or altered raw evidence, incomplete source-bound sufficiency reviews, unaudited client/style reviews, stale probe snapshots, and handwritten probe claims. Any content change invalidates dependent receipts; rerun the originating stage instead of editing hashes.

- **Canonical digest-pinned bases** from `public.ecr.aws/docker/library/*`: Rust = `rust:1.85-slim` (the only accepted Rust image; full digests live in `task-clone/SKILL.md`, never retype them from here), single-stage; gcc:13-bookworm (C/C++ — already ships gcc/make, do NOT re-apt-install build tools; like temurin it MUST carry the full `public.ecr.aws/docker/library/` registry prefix with the digest from `task-clone/SKILL.md` — a bare `gcc:13-bookworm@sha256:…` with the identical digest is flagged non-canonical by the CodeBuild base-image check); golang:1.24-bookworm (+ `ENV GOTOOLCHAIN=auto` for newer go.mod; also `ln -sf /usr/local/go/bin/go /usr/local/bin/go` because platform login shells reset PATH and otherwise oracle/verifier `go build` can fail with `go: command not found`); node:22-bookworm-slim (lacks `patch` — apt-install it); eclipse-temurin:21-jdk-jammy (must include the `public.ecr.aws/docker/library/` registry; a bare `eclipse-temurin:21-jdk-jammy@sha256:…` with the identical digest is still rejected as non-canonical); python:3.13-slim-bookworm (use the CI-reported manifest-list digest, not `docker inspect`'s platform digest). PHP: do not use `php:*-cli-bookworm` even when the checker says it is sanctioned; CodeBuild canonical-base check rejects it. Use the canonical Debian bookworm-slim base and apt-install `php-cli` plus needed extensions such as `php-mbstring`.
- **NO `# syntax=docker/dockerfile:1` line** — platform build nodes can't pull it → "Oracle failed"; convert `--mount=type=bind` to plain `COPY` + `rm -rf` in the same layer. Merge ALL dep installs (apt+pip) into ONE contiguous `RUN`; drop warm `RUN go build` (for deps use `go mod download` before source COPY, or `go test -run '^$'`). Strip explanatory `#` comments from Dockerfiles/code before zipping.
- **`.dockerignore`:** use the full canonical set verbatim (including `.gitignore`, `.pytest_cache`, `.mypy_cache`, `.ruff_cache`, and `node_modules`) plus `solution/`, `tests/`, `.env`, and `**/.git`. Missing exclusions can pass local Harbor yet fail review. `node_modules/` is required even for non-Node tasks. Add missing entries without overwriting valid custom exclusions, then reconfirm Oracle=1.0 and NOP=0.0.
- **Binary name consistency:** the compiled binary's name must be IDENTICAL across every file that references it: `test_outputs.py` (BIN variable + `go build -o <name>` command), `test.sh` (if present), `main.go` top-level comment, `.dockerignore` binary exclusion, `README.md` build instruction, `instruction.md` build command, and `solve.sh` — a mismatch (e.g. `over-limit` vs `latmon`) causes build failures or confusion. Grep the task root for the old name before zipping.
- **ZIP path separators:** CodeBuild/Linux requires archive entries like `environment/Dockerfile`, not `environment\Dockerfile`, and no wrapper directory above `environment/`. On Windows, create final zips with a script that writes `Path.relative_to(root).as_posix()` entry names and verify with Python `zipfile.namelist()` that no entry contains `\`; `Compress-Archive`/Explorer-created zips can produce static-check failures where `environment/` and `tests/test.sh` appear missing.
- **Separate verifier:** `tests/Dockerfile` is required, every `FROM` is digest-pinned, all verifier dependencies are installed there with exact pins, `COPY . /tests/` is present, and parent directories for every declared artifact are created before upload. The agent image must not copy `tests/` or `solution/`.
- **test.sh:** use `set -uo pipefail` (never `set -e`), run pytest with `--ctrf /logs/verifier/ctrf.json`, capture its status, write reward 1/0, and end on the reward block's `fi`. Do not add a trailing `exit`: pytest's status is captured rather than propagated, while a failed reward write must surface as infrastructure error. The current verifier image may use `python`; if the published Terminus 3 skeleton differs, the skeleton wins.
- **CI `ruff F841` on a differential generator's leftover RNG draws:** do not delete calls that consume shared RNG state, because doing so shifts the entire validated seed-to-scenario space. Keep the random calls as bare statements and drop only unused bindings, leaving RNG state identical. Reconfirm Ruff on the whole tree and rerun the relevant differential matrix.
- **task.toml resources:** Terminus 3 tasks must not require a GPU; `gpus`, `gpu_types`, and `docker_flags` remain optional Harbor fields. Use roughly 2 CPU, 8 GB memory, and 10 GB storage. Keep `[environment].network_mode = "public"` and explicitly set `[agent]`/`[verifier]` to `"public"` or `"no-network"` for their actual needs — except on Compose tasks, see below.
- **Compose networking (portal 2026-09-17/18, `check_compose_networks`, blocking in `stb harbor check` and platform preflight):** an `environment/docker-compose*.yml` / `.yaml` must not declare a top-level `networks:` block, a per-service `networks:` list, or a per-service `network_mode:` — the runner puts every service in one shared namespace, so those keys make the project invalid before the image builds (`mutually exclusive network_mode and networks`). Keep `depends_on` and service-name DNS. When any Compose file is present, `[environment]`, `[agent]`, and `[verifier]` must all be `network_mode = "public"`; the runner cannot apply separate phase policies to Compose. A task that must run offline has to ship as a single container — do not restore Compose isolation via `internal: true` or `network_mode: none`. Enforce peer isolation inside the service instead (bind `127.0.0.1`, drop the route, require a token).
- **`COPY --chown=` named users are valid again (portal 2026-09-17):** the cloud image builder resolves names through `/etc/passwd`, so `root:root`, `appuser:appuser`, and numeric IDs all pass `check_modal_dockerfile_compat`, on `ADD --chown=` too. The digest-only rule for external-image `COPY --from=` refs is unchanged, and `ADD` with a local source is still unsupported (use `COPY`). Do not flag a named `--chown` in review.
- **ZIP:** `workspace/submissions/`; zip the 5 allowlist roots' contents (no parent folder) with Python `zipfile` and forward-slash arcnames (PowerShell backslash zips break CI); scripts `chmod +x` / exec bits preserved; strip macOS forks, stray `.git`/`jobs`, rust-analyzer `environment/target/`, CRLF (Windows edits break `git apply`); verify `.dockerignore` contains `solution/`, `tests/`, `.env` (harbor-green ≠ reviewer-green); final grep sweep for `.whl`, an unexpected task-level `environment/pyproject.toml`, `CANARY-`, and leaked CLAUDE.md. Do not flag an upstream-required nested `environment/app/pyproject.toml`. Verify `unzip -p <zip> task.toml | grep author`. **Revise-extension archive convention (2026-08-13):** preserve the platform download as immutable `workspace/revision/<task_id>/revisions/<slug>-source.zip`; each completed remediation writes the next unused `<slug>-revN.zip` (`rev1`, `rev2`, ...), never overwriting history; copy the newest revision byte-for-byte to stable upload name `workspace/submissions/<slug>.zip`. Do not use ambiguous `vN` names or put `revN` in the platform upload filename.
- **Removed manifest fields:** never emit `codebase_size`, `number_of_milestones`, `subcategories`, `allow_internet`, `expert_time_estimate_min`, or `junior_time_estimate_min`; these were Terminus 2 fields.
- **Deps:** pin `pytest==9.1.1` and `pytest-json-ctrf==0.5.2` (the versions in the portal docs and `scripts/new-task.sh`; `0.4.2` does not exist on PyPI) with a plain `RUN pip install` **in `tests/Dockerfile`**. ## 11. Harbor / platform troubleshooting

- **CLI / invocation (portal update 2026-07-21):** install and use `snorkelai-stb`; authenticate with `stb login` then `stb keys refresh` when needed — never manually export `OPENAI_API_KEY`/`OPENAI_BASE_URL` for agent runs. Use `stb harbor run -a oracle|nop -p <task-dir> -o <jobs-dir> --job-name <n> -q`; reward at `stats.evals.<key>.metrics[0].mean`; gate = oracle 1.0 AND nop 0.0. Build context IS `environment/` — no `environment/` prefix in COPY paths. Run stb from the jobs parent dir, models sequentially. The bare local `harbor run` (without the `stb` wrapper) runs `test.sh` in the agent image and ignores a separate `tests/Dockerfile`, so separate-verifier tasks score a false 0 with `No module named pytest` in the verifier log (2026-09-25). When `stb` keys are expired, validate by hand: run `solve.sh` in the environment image, `docker cp` its `/app` into the `tests/Dockerfile` image, and run `bash /tests/test.sh` there.
- **macOS local Harbor network compatibility (updated 2026-08-28):** Harbor's Docker provider has rejected explicit no-network agent/verifier phases before the trial on the current macOS runtime; switching providers to Islo can instead fail with `UnauthorizedError`, which is infrastructure rather than task evidence. Keep `[environment]` public as required and choose agent/verifier policy by task need; when offline isolation is load-bearing, run Oracle/NOP with retained raw result trees and use the trusted direct-Docker fallback for the closed phase if Harbor refuses it. A provider/setup failure never counts as Oracle, NOP, Harbor, or difficulty evidence, and any metadata change made to regain a supported provider invalidates snapshot-bound receipts.
- **Platform difficulty measurement (Terminus 3):** after quality-panel clearance and before human review, GPT-5.6 and Claude Opus 5 run four trials each, once (eight total). A new submission needs at least 3 of those 8 runs to fail, so no more than 5 may pass (62.5% ceiling); grandfathered tasks keep the prior one-failure rule. The mean pass rate sets the final Frontier/Advanced/Core/Base tier. No separate iteration measurement or post-acceptance run remains. Declared-vs-measured tier mismatch alone is not a revision reason; retired tier names remain invalid.
- **Docker validation without harbor:** `docker build -t task-test ./environment` then `docker run --rm -v $(pwd)/solution:/solution:ro -v $(pwd)/tests:/tests:ro task-test bash -c 'cd /app && patch -p1 < /solution/fix.patch && go build -o latmon ./cmd/latmon && mkdir -p /logs/verifier && cd /tests && bash test.sh && cat /logs/verifier/reward.txt'`. **⚠️ Must mount `solution/` and `tests/` as volumes — `.dockerignore` excludes them from the image.** For nop, omit the patch step. ⚠️ A verifier that UNLINKS files under `/tests` (corpus-hiding anti-cheat) errors every test under a `:ro` tests mount — false red; platform `/tests` is writable. Mount at `/tests-src:ro`, `cp -r` to a writable path inside the container, and run pytest on the copy (the hide-guard that checks the dir is exactly `/tests` simply skips, which is fine for grading).
- **"Oracle solution failed" root causes by language** (check ALL; multiple can coexist):
  - **Go (4):** ① git buildvcs on root-owned `/app/.git` → `git config --system safe.directory /app` + `-buildvcs=false`; ② no writable HOME breaks GOCACHE → private temp GOCACHE/GOPATH; ③ `go build -o` into read-only `/app` → build into the temp dir; ④ the `# syntax` line (above). Repro trap: use `chmod -R a+rwx`, never `chown` (false PASS), and test the source-only/read-only path (Go's identical-binary skip masks ③).
  - **C (3):** empty requirements.lock; fix.patch logic gaps; `subprocess.run(input=str)` needs bytes on Python 3.11.
  - **Java:** `javac -d classes` writing into `/app` → hermetic temp classpath; plus safe.directory, `-Xint`, `languages=["java"]`.
  - **Node/TS:** ts-node unavailable offline → pin ts-node/typescript, real package-lock.json, flatten the Node project to `environment/` top level.
  - **C graphviz precedent:** wrong include path, fixture violating its own policy, orphaned asserts — build+run the oracle against EVERY fixture.
- **"Oracle failed" on a byte-identical locally-green artifact** = stale platform image → fresh repackage + force-build; repeated staleness means content-hash caching — make a real difficulty-neutral content change (e.g. trim a verifier loop) to bust it.
- **Platform Oracle failure with locally green tests plus staged executables ⇒ suspect noexec `/tmp` first.** Reproduce with `docker run --tmpfs /tmp:noexec,nosuid,size=256m …`. Stage executable outputs on a probed exec-capable base such as `/app`, `/var/tmp`, or `/dev/shm`; interpreters may read code from `/tmp`, so prefer an argv prefix over staging executable wrapper scripts. Validate Oracle=1 and NOP=0 under the noexec repro.
- **Unsanctioned language images create vendored-toolchain size fragility.** Prefer a canonical base and ecosystem when a language requires shipping a large compiler/runtime. If a port is explicitly authorized, preserve the behavioral corpus but re-audit language-specific key, encoding, numeric, and runtime semantics rather than assuming APIs are equivalent.
- **Reviewer-supplied example values can be wrong.** Re-run the authoritative oracle before adding any disclosed example from feedback or memory. Correct factual mistakes first; never harden a task by preserving a false example or by adding arbitrary counter-intuitive pairs solely to chase a tier.
