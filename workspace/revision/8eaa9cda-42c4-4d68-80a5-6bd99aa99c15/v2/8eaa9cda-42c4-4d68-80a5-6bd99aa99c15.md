1. [Sound Verifier] MAJOR -- overstrict comparator / execution policy
   The launcher prohibits subprocesses even though the contract permits a standard-library
   Python implementation that delegates to a Python worker in the same submitted file.
   Confirmed by running the grader: a valid submission was rejected after this change --
   "Changes the direct CLI entry point to launch the unchanged statement implementation in a
   standard-library Python worker process" (reference reward 1.0, changed 0.0).
   Why this fails:
     Reach: On every graded input, use the demonstrated entry-point mutation: if argv[1] is
     '--worker', call the unchanged main with that flag removed; otherwise call
     subprocess.run([sys.executable, __file__, '--worker', *sys.argv[1:]], check=True). Under
     the documented direct invocation, the parent starts the same Python file, the worker
     removes '--worker', and the original implementation receives exactly the readings, payments
     and output arguments. This uses only Python and its standard library, and needs no
     additional artifact. Flip: The verifier instead installs _audit before runpy.run_path.
     subprocess.run reaches the 'subprocess.Popen' audit event, which raises PermissionError
     before the worker starts. The uncaught exception makes the candidate exit nonzero, failing
     test_outputs.py:78. The trusted execution result confirms reward changes from 1 to 0. The
     contract contains no in-process restriction, so this is a demonstrated false rejection of
     an ordinary worker-process refactor.
   Where to look: instruction.md:1, tests/port_runner.py:13-36, tests/test_outputs.py:60-78

2. [Sound Verifier] MAJOR -- missing behavioral coverage
   The payment corpus permits a port to silently truncate posting runs at 100 records despite
   the contract covering runs of a few hundred records.
   Why this fails:
     Reach: Use one valid billed account 91000001 and a payments file containing 101 lines of
     '91000001;PAY;1.00;x'. This fits the input format and amount limits and requires only
     $101.00 of postings. Flip: A port collecting payment lines with
     [line.rstrip('\n').ljust(80)[:80] for line in fh][:100] prints only 100 postings and a
     $100.00 paid total, instead of 101 postings and $101.00. All visible payment fixtures fit
     within that buffer: generated_11.pay has 40 lines and even long_run.pay has only four. The
     runner supplies fixed pairs and adds no larger payment run. More decisively, the trusted
     harness reports that precisely this truncation mutation retained reward 1.0, confirming
     that unseen fixtures did not defeat it. A fixed 100-record buffer is a plausible
     corner-cutting implementation, not a verifier-specific parsing exploit.
   Where to look: instruction.md:3, environment/app/legacy/RUNBOOK.md:27-33,
     tests/test_outputs.py:93-112, tests/test_outputs.py:121-152,
     tests/cases/generated_11.pay:35-40, tests/cases/long_run.pay:1-4

3. [Sound Verifier] MINOR -- dependency enforcement mismatch
   Python import isolation does not enforce the standard-library-only requirement because the
   submitted program can restore access to installed third-party packages.
   Why this fails:
     Reach: Prepend 'import sys; sys.path.append("/usr/local/lib/python3.13/site-packages");
     import packaging' to an otherwise passing port. The final image installs pytest and its
     dependencies in the Python 3.13 environment; packaging is a pytest dependency. Flip: -I -S

     sys.path. The audit hook blocks only the listed process and ctypes events, not importing

     clears every byte comparison, despite importing a non-standard-library dependency. The
     supplied execution attempt was inconclusive, so it is not cited as empirical proof; the
     path and event trace establish the mechanism. This construction intentionally reverses the
     verifier's import isolation and therefore falls on the adversarial Minor side, rather than
     being an ordinary accidental dependency.
   Where to look: instruction.md:1, tests/Dockerfile:18-23, tests/test_outputs.py:60-61,
     tests/port_runner.py:13-36
