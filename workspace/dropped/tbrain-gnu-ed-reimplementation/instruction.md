Our minimal images have no ed, and the maintenance scripts that still pipe edit commands into it are being pointed at `/app/pyed/ed.py` instead. Implement it so that `python3 /app/pyed/ed.py [OPTIONS] [FILE]` behaves exactly like GNU ed 1.19 run as `ed [OPTIONS] [FILE]` with `LC_ALL=C` and the same standard input. It must produce the same standard output, byte for byte, and leave the same files with the same contents in the current directory. Its exit status must be zero exactly when GNU ed's is. What goes to standard error is not compared. The GNU ed manual is in `/app/docs/ed.txt`.

The scripts use the part of the manual that these maintenance scripts rely on:

- the options `-E`, `-l` and `-s`, and no others, each written as a single letter after one hyphen: they may come before or after the optional FILE, and several may be combined in one argument;
- every form of line address and address range;
- basic and extended regular expressions, except that the GNU escapes `\b`, `\B`, `\w`, `\W`, `\s`, `\S`, `\<`, `\>`, `` \` `` and `\'` never appear. In basic ones `\|` is alternation, as in GNU, and in extended ones `\|` matches a literal `|`. Matching is POSIX leftmost-longest: of the matches that start at the leftmost possible position, the longest one wins, whichever alternative of a `|` produces it;
- the commands `a`, `c`, `d`, `e`, `E`, `f`, `g`, `i`, `j`, `k`, `m`, `n`, `p`, `q`, `Q`, `r`, `s`, `t`, `u`, `v`, `w`, `wq`, `W`, `=`, `#` and the null command, with the `n` and `p` suffixes and every `s` flag and form, including the global commands, undo and marks. The commands `l`, `z`, `x`, `y`, `G`, `V`, `P`, `h`, `H` and `!`, and the `l` suffix, never appear in a script, and no file name, on the command line or after a command, starts with `!`.

After every command that fails, ed writes `?` and a newline to standard output, and when its standard input is a regular file it then stops. Standard input is sometimes a regular file and sometimes a pipe, and none of the standard streams is a terminal. Reaching the end of standard input acts like a `q` command, repeated as often as needed. Scripts are ASCII text, and every line of a script ends with a newline. The files the scripts start from hold at most a few dozen lines of ASCII text without NUL bytes, and every line ends with a newline. No line of a script or of a starting file holds more than 200 bytes before its newline. Files named in commands may not exist. A FILE named on the command line may not exist only when standard input is a pipe. In that case ed starts with an empty buffer and that default filename, and the missing file does not by itself make the exit status non-zero. Import only the Python standard library (its own compiled modules included) and Python source files under `/app`, load no other native code (through `ctypes`, for example), and do not start other programs; all three rules are checked while it runs.

Every check relies only on behaviour that the manual describes, together with the rules above and the places where GNU ed 1.19 departs from its manual, which are listed in `/app/docs/ed-errata.txt`. Every expected result comes from running GNU ed 1.19 itself on the same script, so where the manual and the program disagree the program is what counts. It will be checked that way with many command scripts.
