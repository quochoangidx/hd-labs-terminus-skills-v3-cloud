We are retiring the Fortran 77 snowpack routine in `/app/legacy/snowpk.f` and moving the band model to Python. Finish `/app/src/snowband/band.py` so that `SnowBand` reproduces the routine bit for bit: `SnowBand(we0)` is a call of `SNOWIN(WE0)` at the start of a band's run, `day(px, ta)` is one call of `SNOWPK` with `PX` = `px`, `TA` = `ta` and `NHR` = `len(ta)`, returning `(OUTFLW, IWE, NHR, ITAVG, DMTOT, FRTOT)` as the routine leaves them, and the attributes `we`, `liqw`, `heat`, `kdays` and `bal` hold `COMMON /PACK/` after each call. Several bands may be run side by side, each from its own start.

The reference is the routine as compiled by `gfortran -std=legacy -O0 -ffp-contract=off` on x86-64 and run from a fresh program for each band: INTEGER and REAL are 32 bits, DOUBLE PRECISION is 64 bits, every REAL operation is one IEEE-754 single-precision operation rounded to nearest with ties to even, every expression is evaluated as written (parentheses first, then left to right within a precedence level) with any conversion between types made at the operation where they meet, and the intrinsics follow the Fortran 77 standard. Return every REAL or DOUBLE PRECISION result as a Python float holding exactly that value, and every INTEGER as an int. The inputs `we0`, `px` and `ta` are Python floats that are exactly representable in single precision, with 1 to 24 hours a day. Use only the Python standard library.

Your port will be run against the compiled routine on many band runs of up to a few hundred days, mixing snow and rain, warm and cold spells, days that stop early at a missing hour (a temperature below -90), and temperatures that fall exactly on rounding and freezing boundaries. Every returned value and every attribute is compared exactly after every call.
