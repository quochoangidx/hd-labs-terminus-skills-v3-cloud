`/app/src/gaugeflow` turns our river gauges' stage records into published discharge, and it no longer does so the way its design note, `/app/docs/record-processing.md`, says it should. The note is the authority. Change the package so that it does what the note says, keeping its public surface as it is: `shift_at`, `Segment`, `RatingCurve` with `discharge`, `Reading`, `discharge_series`, `joined_pieces`, `span_totals`, `daily_mean`, `daily_values`, `volume` and `peaks`, with the arguments and return shapes they have now. Tables, curves, records and series passed to it always keep the order the note gives them.

Every rule in the note holds for all the arguments it is written for. Where the note says nothing, what the package does today stands, including what it returns or raises: a function keeps the result it gives today for arguments the note does not describe, and that result is used wherever the note places the function. Add no exception, clamp or guard to what a function accepts now. That covers empty tables, curves and series, spans, gap limits and separations of zero or less, points that share a time, and settings outside the ranges a rule is written for.

The package will be driven through each public function directly and through `daily_values`, with records from a handful of readings to several thousand across many days: irregular sampling, gaps longer than the limit, pieces that cross midnight, readings on shift-entry times and on segment boundaries, shifts before, between and after their entries, stages at and below an offset, runs that touch a threshold, and events that nearly merge. Numbers are compared with `math.isclose(rel_tol=1e-9, abs_tol=1e-9)`, `None` and raised exceptions by kind, and lists element by element.
