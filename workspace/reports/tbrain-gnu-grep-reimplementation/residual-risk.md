# Residual risk — tbrain-gnu-grep-reimplementation (2026-09-24)

- **Filtered, not stated.** Nine variant readings (the -T width, detection of binary data after output, counting without NUL splitting, separator edge cases, -w with empty matches, -w retry versus existence for -o, `\-`) are enforced by dropping cases, not by a sentence. A solver that picks the other reading on a point no retained case touches loses nothing. The corpus simply does not grade those points.
- **The -w retry path for -o is ungraded.** The `wordexisto` variant removed every case where GNU's shorter-match retry differs from a plain existence check, so the `word-no-retry` mutant survives. The wrong path `word-first-match-only` covers -w line selection instead.
- **Construction rules are enforced by a launcher.** Every graded run goes through tests/guard.py, which ends the run on a process start, on native code (a counted solver really did call glibc's regcomp through ctypes) or on an import from outside the standard library. Five probe programs test it. Vendored pure-Python source typed into the package is still out of reach of any check.
- **The probe ran on a copy.** The agent network was public and pip was removed. Harbor could not run the no-network verifier locally, so both artifacts were graded offline with the task's own verifier image. The trajectories show no install or network use.
- **Solvability.** 15 all-or-nothing tests with about 235 cases per mixed family. Both counted GPT-5.6 runs (7/17 each on the final snapshot) failed on two points the manual states outright (binary-match message on stderr; the -L exit status). A careful solver can pass, but one misread rule fails eight families at once.
